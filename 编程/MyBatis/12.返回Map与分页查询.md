# 返回Map与分页查询

本篇含两个互不相关的主题：MyBatis 查询结果返回 `Map`；以及分页查询。

## MyBatis 返回 Map

当查询结果**没有对应的实体类**时（典型场景是聚合函数的结果），可以让 MyBatis 直接把一行结果装配成 `Map`：键是列名（或列别名），值是该列的值。

### 场景

源文的 Mapper 接口中，最后一行就是这种用法：

```java
public interface StuInfoMapper {
    List<StuInfo> getStuInfosAndSubjects();// 获得所有学生，并且获得每一个学生所有考试科目
    List<StuInfo> getStuInfosAndSubjectsAndScore();// 获得所有学生，并且获得每一个学生所有考试科目以及对应的成绩

    List<StuInfo> getStuInfosAndSubjectsMoreParameter(Tempter tempter);// 给两个学生Id，获得成绩(关联查询的多参数处理)

    // 传入一些字母，然后通过姓名字母查询，查询是否包含这些字母
    List<StuInfo> getStuInfosByNameLike(String name);

    List<StuInfo> getStuInfosByNameLike2(String name);
    List<StuInfo> getStuInfosByNameLike3(String name);
    List<StuInfo> getStuInfosByNameLike4(Map<String,String> map);
    List<Map<String, BigDecimal>> getAvg();// 获得聚合函数的键值对
}
```

> [!tip] 为什么这里必须用 Map
> `avg(s.score_cent)` 是一个**运行时才产生的聚合值**，它不属于任何一张表的实体结构。前 7 个方法的返回值都有实体类（`StuInfo`）可对应，唯独 `getAvg()` 没有——于是用 `Map<String, BigDecimal>` 承接"列名 → 数值"。

### 映射配置

关键在于 `resultType` 写的不是实体类别名，而是 `java.util.HashMap`：

```xml
<select id="getAvg" resultType="java.util.HashMap">
    select stu.stu_name,avg(s.score_cent) as score from t_stu_info stu INNER JOIN t_score s on s.score_stu_id= stu.stu_id group by stu.stu_name;
</select>
```

这条 SQL 每行返回两个值：`stu_name` 与聚合出的 `score`。因为没有实体类，MyBatis 把这行塞进一个 `HashMap`，**SQL 中的列名/别名就成为 Map 的键**。

### 测试与取值

```java
@Test
public void test029(){

    // 返回聚合函数
    // select stu.stu_name,avg(s.score_cent) as score from t_stu_info stu INNER JOIN t_score s on s.score_stu_id= stu.stu_id group by stu.stu_name;
    StuInfoMapper mapper = session.getMapper(StuInfoMapper.class);
    List<Map<String, BigDecimal>> avgs = mapper.getAvg();// 获得对应的Map类型
    for (Map<String, BigDecimal> avg : avgs) {
        String key=avg.keySet().iterator().next();
        BigDecimal value = avg.get(key);
        System.out.println("key:"+key);
        System.out.println("value:"+value.doubleValue());
        System.out.println("====================================");
    }
}
```

> [!warning] 用 Map 接收的代价
> 取值的写法暴露了 Map 路线的弱点：`avg.keySet().iterator().next()` 只能"取第一个键"，**代码并不知道键叫什么**。一旦 SQL 改了列别名，Java 侧不会编译报错，只会在运行时取错或取空。
>
> - 单列聚合结果：可以用 `resultType` 指定单个类型（如 `BigDecimal`），比 `Map` 更安全；
> - 多列且无实体：`Map` 是可行退路，但应在文档或注释里固定列别名，或改用专门的 DTO 类。
>
> 源文此处只演示了 `Map` 的写法，未讨论上述替代方案。
