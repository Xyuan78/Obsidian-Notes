# 结果映射与 Mapper 接口

上一章用 `namespace + id` 字符串调用 SQL，能跑通，但两处不舒服：**查出来的对象字段可能是 null**，以及**写错参数类型时编译器不管**。这一章解决这两个问题：`resultMap` 负责"查出来的列怎么塞进对象属性"，Mapper 接口负责"像调用普通方法一样调用 SQL"。

## resultMap 解决什么问题

### 问题复现：属性名与列名对不上

源文给出一个刻意的"坏例子"——实体类的属性名没有遵循驼峰命名法：

```java
//实体类
public class Stu implements Serializable {
    private int stuId;
    private String stuNo;
    private String name;//属性名与数据库中的列名，没有遵循驼峰命名法的映射
```

对应的数据库表：

```sql
CREATE TABLE `t_stu_info` (
  `stu_id` int(11) NOT NULL AUTO_INCREMENT COMMENT '序号，自动增长列，没有任何意义',
  `stu_no` char(9) NOT NULL COMMENT '学号，唯一',
  `stu_name` varchar(50) NOT NULL DEFAULT '无名氏' COMMENT '姓名',
  PRIMARY KEY (`stu_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8;
```

列名是 `stu_id` / `stu_no` / `stu_name`，属性是 `stuId` / `stuNo` / `name`。前两个还能靠下划线转驼峰对上（该全局配置见 [[1.MyBatis 环境搭建与快速入门]]），但 `stu_name` → `name` 无论如何都对不上。

查询代码照旧三步走：

```java
//（1）新建接口
public interface StuMapper {
    List<Stu> selectAll();//获得全部
}
```

```xml
<!--（2）新建 xml 文件 -->
<?xml version="1.0" encoding="UTF-8" ?>
<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN"
        "http://mybatis.org/dtd/mybatis-3-mapper.dtd">
<mapper namespace="com.neuedu.mapper.StuMapper">

    <select id="selectAll" resultType="Stu">
        select * from t_stu_info
    </select>

</mapper>
```

```java
//（3）查询代码
public class Test008 {
    public static void main(String[] args) throws IOException {
        //查找根目录
        InputStream is = Resources.getResourceAsStream("mybatis-config.xml");
        SqlSessionFactory factory = new SqlSessionFactoryBuilder().build(is);
        SqlSession session =factory.openSession();//打开session
        StuMapper mapper  = session.getMapper(StuMapper.class);
        List<Stu>  stus = mapper.selectAll();
        //通过foreach 循环打印
        for (Stu stu: stus ) {
            System.out.println(stu);
        }
        //因为是查询，不会修改数据库中的数据，所有不需要commit
        //session.commit();//提交数据
        session.close();//用完关闭session
    }
}
```

结果是 `name` 一片 null：

```text
//结果，name没有值？？？ 原因是字段与属性不是一一对应的
Stu{stuId=1, stuNo='stu001', name='null'}
Stu{stuId=2, stuNo='stu002', name='null'}
Stu{stuId=3, stuNo='stu003', name='null'}
```

> [!warning] `resultType` 只能"自动猜"
> `resultType="Stu"` 走的是自动映射：MyBatis 拿列名去猜属性名。列名与属性名对不上时，它**不报错**，只是把该属性留空（null）。字段静默为 null，是 MyBatis 最常见的"没报错但结果不对"。

### 用 resultMap 手动映射

源文的解法是自己写一份映射关系，再用 `resultMap` 属性引用它：

```xml
<?xml version="1.0" encoding="UTF-8" ?>
<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN"
        "http://mybatis.org/dtd/mybatis-3-mapper.dtd">
<mapper namespace="com.neuedu.mapper.StuMapper">
    <!-- 实现属性与数据库中字段的手动映射
    <resultMap>
    id="名字的唯一" type="对应的实体类的类型"
    <id> 用于主键列的处理
    <result>用于普通列的处理
    property="java类的属性" column="数据库中的字段"
     -->
    <resultMap id="stuBase" type="Stu">
        <id property="stuId" column="stu_id"/>
        <result property="stuNo" column="stu_no" />
        <result property="name" column="stu_name" />
    </resultMap>

    <select id="selectAll" resultType="Stu">
        select * from t_stu_info
    </select>
    <!-- resultMap 使用自己编写的映射标签，引用自己编写的resultMap标签的 id  -->
    <select id="selectAll2" resultMap="stuBase">
        select * from t_stu_info
    </select>
</mapper>
```

接口同步加一个方法：

```java
public interface StuMapper {
    List<Stu> selectAll();//获得全部
    List<Stu> selectAll2();//获得全部
}
```

测试时改用 `selectAll2()`：

```java
public class Test008 {
    public static void main(String[] args) throws IOException {
        //查找根目录
        InputStream is = Resources.getResourceAsStream("mybatis-config.xml");
        SqlSessionFactory factory = new SqlSessionFactoryBuilder().build(is);
        SqlSession session =factory.openSession();//打开session
        StuMapper mapper  = session.getMapper(StuMapper.class);
        //List<Stu>  stus = mapper.selectAll();//name属性没有被填充
        List<Stu>  stus = mapper.selectAll2();
        //通过foreach 循环打印
        for (Stu stu: stus ) {
            System.out.println(stu);
        }
        //因为是查询，不会修改数据库中的数据，所有不需要commit
        //session.commit();//提交数据
        session.close();//用完关闭session
    }
}
```

结果三个字段都填上了：

```text
Stu{stuId=1, stuNo='stu001', name='zhangsanTX'}
Stu{stuId=2, stuNo='stu002', name='lisiTX'}
Stu{stuId=3, stuNo='stu003', name='wangwuTX'}
```

### resultMap 的子标签与属性

源文注释里给出的说明：

| 写法 | 含义 |
|---|---|
| `<resultMap id="名字的唯一" type="对应的实体类的类型">` | `id` 是这份映射的名字，供 `resultMap="…"` 引用；`type` 是要映射成的实体类 |
| `<id property="java类的属性" column="数据库中的字段"/>` | 主键列的处理 |
| `<result property="java类的属性" column="数据库中的字段"/>` | 普通列的处理 |

`property` 永远写 **Java 属性名**，`column` 永远写 **数据库列名**，二者顺序不要凭感觉猜。

> [!tip] 什么时候必须写 resultMap
> 列名与属性名能自动对上（含下划线转驼峰）时，`resultType` 足够省事；一旦出现"属性名与列名完全不像"的情况，就必须显式写 `resultMap`。本章示例中源文**两个 select 都保留**——`selectAll` 用 `resultType`、`selectAll2` 用 `resultMap`——目的是对比效果。

> [!info] 本笔记的范围
> 本区间只涉及**列名与属性名不一致**这一类映射。`resultMap` 的关联映射子标签（`<association>`、`<collection>`）在源文更靠后的位置才出现（源文 1088 行起），属后续章节，见 [[5.关联查询、一对一与一对多]]。

## Mapper 接口的使用

### 字符串定位的缺陷

源文先摆出"字符串调用"的病根：

```text
select函数中如果使用字符串与Object查询时，Object的类型没有办法进行约束，
//错误的，如何在编码的时候就进行类型检测？？？，第二个参数需要传入一个字符串
TeacherInfo info =  session.selectOne("com.neuedu.entity.TeacherInfoMapper.selectOneByName",new Stu());//查询一个
System.out.println(info);
```

问题在于 `selectOne(String, Object)` 的第二个参数是 `Object`：传 `new Stu()` 进去，编译期完全合法，类型错误要等到运行时才暴露。源文用问号标出了这个困惑，答案就是下面的代理方式。

### 通过代理处理

源文给出的三步：

```java
//（1）新建接口
public interface StuMapper {
    List<Stu> selectAll();//获得全部
    List<Stu> selectAll2();//获得全部
    Stu selectStuById(int id);//通过主键查询**
}
```

```xml
<!-- （2）修改 xml 文件，创建查询标签，保证查询标签的id与方法名一致，参数也一致 -->
<select id="selectStuById" parameterType="int" resultMap="stuBase">
    select * from t_stu_info where stu_id=#{id}
</select>
```

```java
//（3）通过 session.getMapper 代理，获得接口的实现类
public static void main(String[] args) throws IOException {
        //查找根目录
        InputStream is = Resources.getResourceAsStream("mybatis-config.xml");
        SqlSessionFactory factory = new SqlSessionFactoryBuilder().build(is);
        SqlSession session =factory.openSession();//打开session
        //代理对象
        StuMapper mapper = session.getMapper(StuMapper.class);//通过代理，获得自定义的接口对象
        Stu stu = mapper.selectStuById(1);//对参数的类型进行的判断
        System.out.println(stu);
        session.close();//用完关闭session
}
```

`session.getMapper(StuMapper.class)` 返回的是 MyBatis 为接口生成的**代理对象**：接口本身没有实现类，调用 `mapper.selectStuById(1)` 时，MyBatis 按"接口全限定名 + 方法名"找到对应的 SQL 标签并执行。参数类型因此由接口方法签名约束住了——传错类型编译期就报错。

### 接口代理的前提条件

| 前提 | 源文依据 |
|---|---|
| XML 的 `namespace` 等于**接口的全限定名** | 源文 xml 写 `com.neuedu.mapper.StuMapper`（源文 404、445 行），接口声明在 `com.neuedu.mapper` 包下、名为 `StuMapper`（源文 396、470 行），二者字符串一致 |
| SQL 标签的 `id` 等于**接口方法名** | 源文原话："保证查询标签的id与方法名一致，参数也一致"（源文 520 行） |
| 参数类型与方法签名一致 | 同上；标签侧写 `parameterType="int"`，SQL 里用 `#{id}` 取值 |
| 标签产出的结果类型与方法返回值一致 | `selectStuById` 返回 `Stu`，标签用 `resultMap="stuBase"`，其 `type="Stu"`（源文 453、518、521 行） |

> [!warning] 三条对应关系缺一不可
> `namespace` / `id` / 方法签名只要有**一处对不上**，运行时就会报找不到语句或方法未绑定之类的错误（源文未逐一演示这些报错信息）。注意 `namespace` 的作用在源文更早处被说明为"使该 xml 的标签 id 唯一"（源文 187 行），而接口代理又要求它恰好等于接口全限定名——写 xml 时直接按"包名.接口名"命名最省事。

> [!info] 背景
> 源文对代理的**实现原理**只给出了一条外部博客链接（源文 531 行），没有展开说明。

## 易错点

> [!warning] `resultType` 猜不中，字段静默为 null
> 列名与属性名对不上时不会抛异常，只是属性为空。排查"某个字段查出来是 null"时，先核对 `property` / `column` 是否写反。

> [!warning] `resultMap` 与 `resultType` 不能同时用在一个标签上
> 标签要么写 `resultType`（自动映射），要么写 `resultMap="…"`（手动映射）。源文示例中两个属性分别出现在两个不同的 `<select>` 标签里。

> [!warning] `#{id}` 里的名字要与方法参数对得上
> 源文示例的 `selectStuById(int id)` 对应 `#{id}`。参数名对不上时同样取不到值。

> [!warning] 查询不需要 commit，session 仍要 close
> 与上一章一致：查询不修改数据，可以不 commit；但 `SqlSession` 用完必须关闭。
