# 动态 SQL

静态 SQL 的条件是写死的：一个 `<select>` 标签只能对应一条固定的 SQL。动态 SQL 解决的是另一类需求——**实现多条件下的 SQL 语句拼接**（源文对动态 SQL 的概括）：条件给几个就拼几个，不给就不拼。

本章覆盖三块内容：动态 SQL 的六个标签、模糊查询的正确与错误写法、以及负责拼接 `%` 的 `bind` 绑定标签。示例跑在 `tb_user`、`t_stu_info`、`tb_admin`、`t_employee` 等表上，Mapper 统一通过接口代理调用，写法见 [[2.结果映射与 Mapper 接口]]。

## SQL 的高级使用

### 动态 SQL 标签

六个标签各管一类拼接需求，速查如下（"解决什么问题"一列按源文说明归纳）：

| 标签 | 解决什么问题 | 关键属性 |
|---|---|---|
| `<if>` | 按条件决定是否拼接某一段 SQL | `test` |
| `<choose>` / `<when>` / `<otherwise>` | 相当于 switch 结构，多个条件符合时只走第一个符合的 | `test` |
| `<where>` | 条件拼接不必写 `where 1=1`，并去掉 SQL 开始或结束处的连接符（`and`、`or`） | —— |
| `<set>` | 用在更新语句上（动态 Update），自动去掉后面多余的逗号 | —— |
| `<foreach>` | 用在 where 中、SQL 里有 `in` 的场景：批量修改、删除、审批、添加 | `collection`、`item`、`index`、`open`、`separator`、`close` |
| `<trim>` | 在包含内容的前后加前缀/后缀，并忽略首部或尾部的指定内容，可替换 `where` 标签与 `set` 标签 | `prefix`、`suffix`、`prefixOverrides`、`suffixOverrides` |

#### if（判断）

**解决什么问题**：条件是可选的，用户给了 `userId` 才加 `user_id >= ?`，给了 `userLoginName` 才加模糊条件；没给的字段完全不出现在 SQL 里。

**源文示例**——注意源文用 `where 1=1` 为后面的 `<if>` 提供一个可拼接的起点（`where` 标签的动机正来自这里，见下一节）：

```java
@Test
public void test017() throws IOException {
    //if的处理
    UserMapper mapper = session.getMapper(UserMapper.class);
    User user1 = new User();
    user1.setUserId(3);
    user1.setUserLoginName("z");

    List<User> users = mapper.getUserIfMethod(user1);
    for (User user : users) {
        System.out.println(user);
    }

}
```

```xml
<!-- if 标签的使用 -->
<select id="getUserIfMethod" parameterType="User" resultType="User">
    select * from tb_user
    where 1=1
    <if test="userId != null">
        and user_id >= #{userId}
    </if>
    <if test="userLoginName != null">
        and user_login_name like  concat('%', #{userLoginName},'%')
    </if>
    <if test="userPhone != null">
        and user_phone like concat('%', #{userPhone},'%')
    </if>
    <if test="userState != null">
        and user_state = #{userState}
    </if>
</select>
```

> [!warning] `if` 是"各自独立"的判断
> 每一个 `<if>` 只看自己的 `test`，互不排斥。四个条件都满足时，四段 SQL 会全部拼进同一条语句——这正是它与 `choose` 的分水岭。

#### choose（when,otherwise）相当于 switch 结构

**解决什么问题**：条件之间是"多选一"关系时，用 `choose` 保证只拼一段。源文说明：`when` 符合条件时执行，`otherwise`（所有的条件都不满足时执行）；走其中符合的一项 SQL 语句的拼接，**如果有多个条件符合，只走第一个符合的**。

**源文示例一**（`otherwise` 里用的是 `user_error` 字段，照抄源文）：

```text
@Test
    public void test018() throws IOException {
        //choose的处理
        UserMapper mapper = session.getMapper(UserMapper.class);
        User user1 = new User();
        user1.setUserId(3);
        user1.setUserLoginName("z");

        List<User> users = mapper.getUserChooseMethod(user1);
        for (User user : users) {
            System.out.println(user);
        }

    }
<!-- choose 标签的使用 -->
    <select id="getUserChooseMethod" parameterType="User" resultType="User">
        select * from tb_user
        where 1=1
        <choose>
            <when test="userId != null">
                and user_id >= #{userId}
            </when>
            <when test="userLoginName != null">
                and user_login_name like  concat('%', #{userLoginName},'%')
            </when>
            <when test="userPhone != null">
                and user_phone like concat('%', #{userPhone},'%')
            </when>
            <when test="userState != null">
                and user_state = #{userState}
            </when>
            <otherwise>
                and user_error = #{userError}
            </otherwise>

        </choose>
    </select>    
```

**补充多条件的判断 使用 and 或 or 链接对属性的判断**（源文原文表述），即一个 `when` 的 `test` 里可以用 `and` 连接多个属性：

```xml
<!-- choose 标签的使用2 -->
<select id="getUserChooseMethod2" parameterType="User" resultType="User">
    select * from tb_user
    where 1=1
    <choose>
        <when test="userId != null">
            and user_id >= #{userId}
        </when>
        <when test="userLoginName != null and userPhone != null">
            and user_login_name like  concat('%', #{userLoginName},'%')  and user_phone like concat('%', #{userPhone},'%')
        </when>
        <when test="userState != null">
            and user_state = #{userState}
        </when>
        <otherwise>
            and user_error = #{userError}
        </otherwise>

    </choose>
</select>
```

源文用两次运行对比了这个"合并条件"的行为（测试方法名在源文里两次都写作 `test026`，照抄）：

注意：只传 `userLoginName` 一个参数时，`userLoginName != null and userPhone != null` 不成立，四个 `when` 全落空，于是落到 `otherwise`，最终 SQL 变成 `where 1=1 and user_error = ?`，参数为 `null`，命中 0 行——这是 `otherwise` 兜底的实际后果。

> [!warning] if 与 choose 的区别（源文原话）
> - `if` 如果有多个条件满足，**多个字段都会拼接成一个 SQL 语句**；
> - `choose` 如果有多个条件满足，它**只拼接第一个符合条件的 SQL**，其他字段自动忽略。

#### where

**解决什么问题**：源文指出，做条件拼接时必须写一个 `where 1=1` 为后面的 SQL 语句提供一个拼接条件，**但是拼接后的 SQL 语句执行速度慢**。`where` 标签就是替掉 `where 1=1` 的：它还会去掉 SQL 语句中开始或结束处的连接符（`and`、`or`）。

```text
@Test
    public void test019() throws IOException {
        //where+if的处理
        UserMapper mapper = session.getMapper(UserMapper.class);
        User user1 = new User();
        user1.setUserId(3);
        user1.setUserLoginName("z");

        List<User> users = mapper.getUserWhereIfMethod(user1);
        for (User user : users) {
            System.out.println(user);
        }

    }
    
    <!-- where 标签的使用 -->
    <select id="getUserWhereIfMethod" parameterType="User" resultType="User">
        select * from tb_user
        <where>
            <if test="userId != null">
                and user_id >= #{userId}
            </if>
            <if test="userLoginName != null">
                and user_login_name like  concat('%', #{userLoginName},'%')
            </if>
            <if test="userPhone != null">
                and user_phone like concat('%', #{userPhone},'%')
            </if>
            <if test="userState != null">
                and user_state = #{userState}
            </if>
        </where>
    </select>
```

对比上一节可以看出：`<where>` 里每个 `<if>` 依旧以 `and` 开头、`select` 后面也不再需要 `where 1=1`，是标签把开头那个多余的 `and` 去掉了。

> [!tip] 写法上的差别
> `where 1=1` 版本把"第一个条件前面必须有个 `where`"这件事交给了一个恒真条件；`<where>` 版本把这件事交给标签本身。源文的理由是前者"执行速度慢"。

#### set（用在更新语句上，动态 Update）

**解决什么问题**：更新语句里每拼一个字段就带一个逗号，可最后一个字段的逗号必须没掉。源文一句话概括：**`set` 会自动去掉后面多于的逗号**。

源文把它与 `where` 组合成一个动态 Update：

```text
 @Test
    public void test020() throws IOException {
        //where+if的处理
        UserMapper mapper = session.getMapper(UserMapper.class);
        User user1 = new User();
        user1.setUserId(3);
        user1.setUserLoginName("zdfasdfasdfdasf");
        user1.setUserState(2);

       int count = mapper.updateUserWhereIfSetMethod(user1);
       System.out.println(count);
       //session.commit();//不修改数据库数据库，只看打印出的sql

    }
    
    <!-- where+if+set 标签的使用 -->
    <update id="updateUserWhereIfSetMethod" parameterType="User">
        update tb_user
        <set>
            <if test="userLoginName != null">
                user_login_name=#{userLoginName},
            </if>
            <if test="userPhone != null">
                user_phone=#{userPhone},
            </if>
            <if test="userState != null">
                user_state = #{userState},
            </if>
        </set>
        <where>
            <if test="userId != null">
                and user_id >= #{userId}
            </if>
            <if test="userLoginName != null">
                and user_login_name like  concat('%', #{userLoginName},'%')
            </if>
            <if test="userPhone != null">
                and user_phone like concat('%', #{userPhone},'%')
            </if>
            <if test="userState != null">
                and user_state = #{userState}
            </if>
        </where>
    </update>
```

注意 `<set>` 内部每段都照常以 `,` 结尾，多余的那个逗号由 `<set>` 处理。

> [!tip] 只看 SQL、不动数据
> 源文在批量修改、批量删除、`set` 更新、`trim` 更新的测试里都把 `session.commit();` 注释掉，并注明"不修改数据库数据库，只看打印出的 SQL"。调试动态 SQL 拼接结果时这是常用手段。

#### foreach

**解决什么问题**：`foreach` 也是用在 `where` 中，SQL 里有 `in`，代表在某某之中。源文举例：工作中，批量的修改，删除，审批。

源文先给出了语法结构说明（照抄自源文注释）：

```xml
 <!-- 
		foreach的主要用在构建in条件中，它可以在SQL语句中进行迭代一个集合。foreach元素的属性主要有item，index，collection，open，separator，close。
		item表示集合中每一个元素进行迭代时的别名，
		index指定一个名字，用于表示在迭代过程中，每次迭代到的位置，
		open表示该语句以什么开始，
		separator表示在每次进行迭代之间以什么符号作为分隔符，
		close表示以什么结束，
		在使用foreach的时候最关键的也是最容易出错的就是collection属性，该属性是必须指定的，但是在不同情况下，该属性的值是不一样的，
		主要有一下3种情况：
		1.如果传入的是单参数且参数类型是一个List的时候，collection属性值为list
		2.如果传入的是单参数且参数类型是一个array数组的时候，collection的属性值为array
		3.如果传入的参数是多个的时候，我们就需要把它们封装成一个Map了，当然单参数也可以封装成map，实际上如果你在传入参数的时候，
		在MyBatis里面也是会把它封装成一个Map的，map的key就是参数名，所以这个时候collection属性值就是传入的List或array对象在自己封装的map里面的key
  -->
```

四段源文示例——查询（List 入参）、查询（数组入参）、批量修改、批量删除：

```xml
<!-- foreach 传入的是list -->
    <select id="getUsersByIds" parameterType="list" resultType="User">
        select * from tb_user
        <where>
            user_id in
            <foreach collection="list" item="id" close=")" open="(" separator=",">
                #{id}
            </foreach>
        </where>
    </select>
    <!-- foreach 传入的是数组 -->
    <select id="getUsersByIds2" parameterType="list" resultType="User">
        select * from tb_user
        <where>
            user_id in
            <foreach collection="array" item="id" close=")" open="(" separator=",">
                #{id}
            </foreach>
        </where>
    </select>
<!-- foreach 传入的是数组 批量修改 -->
    <update id="updateUsersByIds" parameterType="list">
        update tb_user set user_state = 0
        <where>
            user_id in
            <foreach collection="array" item="id" close=")" open="(" separator=",">
                #{id}
            </foreach>
        </where>
    </update>

    <!-- foreach 传入的是数组 批量删除 -->
    <delete id="deleteUsersByIds" parameterType="list">
        delete from tb_user
        <where>
            user_id in
            <foreach collection="array" item="id" close=")" open="(" separator=",">
                #{id}
            </foreach>
        </where>
    </delete>
```

> [!warning] 最容易出错的是 `collection`
> 源文强调 `collection` 属性**必须指定**，且取值随入参形态变化：List → `list`，数组 → `array`，多个参数封装成 Map → Map 里对应的 key。写错取值的表现就是运行时报找不到集合。

##### 批量添加

`in` 之外的另一个典型用途是批量插入：此时 `foreach` 迭代的是 `values` 后面的每一行，用 `#{item.属性}` 取元素字段。

> [!warning] 源文缺口
> 源文此小节正文只写了一句"文件导入，"便直接给出代码，导入的具体做法没有展开。

```xml
  <!--  List集合，元素类型是Employee,#{item.属性}  -->
    <insert id="inserall" parameterType="list">
        insert into  t_employee
        values
        <foreach collection="list" item="emp" separator=",">
            (null,#{emp.empNo},#{emp.empName},2,'男','本科', 'zhagnsanfeng@163.com', '13711111111', '2022-05-14 15:35:55', '2022-05-14 15:35:55')
        </foreach>
    </insert>
```

```java
@Test
    public void foreachDemo06(){
        EmployeeMapper mapper = session.getMapper(EmployeeMapper.class);
        List<Employee> employeeList = new ArrayList<>();
        employeeList.add(new Employee("0001","张三"));
        employeeList.add(new Employee("0002","张三123"));
        employeeList.add(new Employee("0003","张三24"));
        employeeList.add(new Employee("0004","张三34"));
        int i = mapper.inserall(employeeList);

        System.out.println("==============================");
    }
```

与 `in` 的用法相比，这里没有 `open`/`close`，只用 `separator=","` 把多组 `values` 隔开；`item` 命名成 `emp`，取值就写成 `#{emp.empNo}`。

#### trim

**解决什么问题**：`trim` 是在"加前缀/后缀"与"忽略首尾内容"这两个动作上做通用化。源文注释：

```xml
  <!-- 
	trim元素的主要功能是可以在自己包含的内容前加上某些前缀，也可以在其后加上某些后缀，与之对应的属性是
	加入：prefix（前缀）和suffix（后缀）；
	可以把包含内容的首部某些内容覆盖，即忽略，也可以把尾部的某些内容覆盖，对应的属性是
	忽略：prefixOverrides（忽略前面的）和suffixOverrides（忽略后面的）。
	可以非常方便的替换where标签与set标签
	prefixOverrides="and|or" 忽略前面的and或者or
   	 -->
```

源文示例把上面 `set` + `where` 的那个动态 Update 用 `trim` 重写了一遍——`prefix="set" suffixOverrides=","` 对应 `<set>`，`prefix="where" prefixOverrides="and|or"` 对应 `<where>`：

```xml
<!-- trim 标签的使用 -->
    <update id="updateUserTrimMethod" parameterType="User">
        update tb_user
        <trim prefix="set" suffixOverrides=",">
            <if test="userLoginName != null">
                user_login_name=#{userLoginName},
            </if>
            <if test="userPhone != null">
                user_phone=#{userPhone},
            </if>
            <if test="userState != null">
                user_state = #{userState},
            </if>
        </trim>
        <trim prefix="where" prefixOverrides="and|or">
            <if test="userId != null">
                and user_id >= #{userId}
            </if>
            <if test="userLoginName != null">
                and user_login_name like  concat('%', #{userLoginName},'%')
            </if>
            <if test="userPhone != null">
                and user_phone like concat('%', #{userPhone},'%')
            </if>
            <if test="userState != null">
                and user_state = #{userState}
            </if>
        </trim>
    </update>
```

接口在这一节新增一个方法，测试如下：


> [!info] 三者的关系（据源文注释归纳）
> 源文明确写了 trim"可以非常方便的替换 where 标签与 set 标签"，并给出 `prefixOverrides="and|or"` 的作用是忽略前面的 `and` 或者 `or`；`set` 的行为是"自动去掉后面多于的逗号"，`where` 的行为是"去掉 SQL 语句中开始或结束的连接符（`and`、`or`）"。也就是说：`where`、`set` 能做的事，`trim` 都能用 `prefix` / `suffixOverrides` / `prefixOverrides` 显式表达出来。

### 模糊查询

## 易错点

> [!warning] `${}` 是字符串替换，不是占位符
> 源文对 `#{}` 与 `${}` 的区别说得很直接：`${}` 是字符串的替换（替换符），不是占位符的处理（预格式化 SQL 语句）。模糊查询的"错误的写法"就出自这一族用法，不要与 `#{}`、`concat`、`bind` 三条正确路线混同。

> [!warning] `if` 与 `choose` 别用错
> `if` 是各个条件各自判断、满足就拼；`choose` 是 switch 语义，多个 `when` 满足也只拼第一个，全不满足才轮到 `otherwise`。想让"多条件同时生效"就用 `if`，想"多选一"就用 `choose`。

> [!warning] `foreach` 的 `collection` 必须指定且取值随入参变化
> 单参数 List → `list`；单参数数组 → `array`；多参数需封装成 Map → 取 Map 里的 key。源文称这是"最关键的也是最容易出错"的一点。

> [!warning] `bind` 取值依赖 `_parameter` 的形态
> 单参数用 `_parameter`；对象用 `_parameter.getXxx()`（**实体类一定要有对应的 get 方法**）；List 用 `_parameter.list.get(下标)`；数组用 `_parameter.array[下标]`；Map 用 `_parameter.key`。

> [!tip] 用 `where 1=1` 的代价
> 源文指出，条件拼接时必须写 `where 1=1`，但拼接后的 SQL 语句执行速度慢；`<where>` 标签既省掉这个恒真条件，又会去掉 SQL 开始或结束处的 `and`、`or`。

其他需要留意的写法事实：

| 现象 | 源文对应说明 |
|---|---|
| `<set>` 里的每段字段都以 `,` 结尾 | `set` 会自动去掉后面多于的逗号 |
| `<trim>` 能替掉 `<where>`、`<set>` | `prefix="where" prefixOverrides="and\|or"`、`prefix="set" suffixOverrides=","` |
| 单参数绑定必须叫 `_parameter` | 源文注释："参数名一定是 `_parameter`" |
| 批量添加没有 `open`/`close` | 只用 `separator=","` 分隔多组 `values`，用 `#{item.属性}` 取字段 |
| 改数据的测试看不到落库变化 | 源文把 `session.commit();` 注释掉，只看打印出的 SQL |
