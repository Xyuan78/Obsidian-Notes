# 注解编程、基础CRUD

前面的路线是把 SQL 写在 Mapper XML 里，用 `namespace + id` 找到它。注解路线换了个位置：**SQL 直接写在 Mapper 接口的方法上**，一个 XML 文件都不需要。源文对这一选择的态度很直接：

> 注解编程的好处就是减少配置文件的使用，方便修改与查找，注解还有自己的问题，我们后面可以结合注解与xml一起使用。

三个要点：好处是少文件、好查找；问题是注解自身有局限；最终路线是 **注解与 XML 混用**，而不是二选一。

> [!info] 两条路线的关系
> 注解与 XML 不是两套框架，而是同一条 Mapper 接口代理机制下的两种 SQL 载体：
> - 注解：`@Select` / `@Insert` / `@Update` / `@Delete` 写在接口方法上，接口即映射，无需额外文件；
> - XML：SQL 写在 `<mapper namespace="包.Mapper">` 的标签里，用 `id` 与接口方法名对齐。
>
> XML 那一侧的写法与 `namespace` 规则见 [[4.Mapper XML 与 sql 标签]]，接口代理的调用方式见 [[2.结果映射与 Mapper 接口]]。本篇只讲注解写法。

## 基本写法

源文先把这一族注解列了出来（原文照录）：

```text
@Insert，@Update，@Delete，@Select，@Param,@Result,@Results,@One,@Many,@Options，@ResultMap
```

其中本区间用到的是 `@Insert`、`@Update`、`@Delete`、`@Select`、`@Param`、`@Options`、`@Result`、`@Results`、`@ResultMap`；`@One`、`@Many` 属于关系映射，见 [[10.注解编程、关系映射]]，动态 SQL 注解见 [[11.注解编程、动态SQL与script]]。

### 增删改

#### @Insert

源文用一个接口 `UserMapperAnnotation` 演示了三种插入写法：

```java
//接口代码
public interface UserMapperAnnotation {
    //固定值
    @Insert("INSERT INTO tb_user VALUES ('8', 'admin1', 'DEC2BFC0F2EA631CCE2D72CB6FBD5602', 'bc@fg!', '管理员1', '12713713713', '1', '1', '5')")//写上要执行的sql语句
    //参数值
    int insertUser(User user);
    @Insert("INSERT INTO tb_user VALUES (#{userId}, #{userLoginName}, #{userPwd}, #{userSalt}, #{userName}, #{userPhone}, #{userIsAdmin}, #{userState}, #{userError})")//数据换成属性参数
    int insertUser2(User user);
    //加入某些处理方式，例如，返回自动增长列的值
    @Insert("INSERT INTO tb_user VALUES (null, #{userLoginName}, #{userPwd}, #{userSalt}, #{userName}, #{userPhone}, #{userIsAdmin}, #{userState}, #{userError})")//数据换成属性参数
    @Options(useGeneratedKeys = true,keyProperty = "userId",keyColumn = "user_id")
    int insertUser3(User user);
    //useGeneratedKeys = true确定返回自动增长列,keyProperty = "userId" 返回自动增长列后，填充哪一个属性,keyColumn = "user_id" 从哪一个列中获得自动增长列的值

    int updateUser(User user);
    int deleteUser(User user);
    int updateUser2(User user);
    int deleteUser2(User user);
}
```

三种写法的差别：

| 方法 | 写法 | 特征 |
|---|---|---|
| `insertUser` | SQL 里全是固定值 | `@Insert` 里**写死**了每一列的值，传进来的 `User` 参数实际未被使用 |
| `insertUser2` | SQL 里全是 `#{属性名}` | 数据换成属性参数，由对象取值 |
| `insertUser3` | 主键位写 `null` + `@Options` | 主键交给数据库自增，并把生成值回填到对象 |

`@Options` 的三个属性，源文的注释写得很清楚（原文照录）：

```text
useGeneratedKeys = true确定返回自动增长列,keyProperty = "userId" 返回自动增长列后，填充哪一个属性,keyColumn = "user_id" 从哪一个列中获得自动增长列的值
```

> [!tip] 自增主键回填的完整条件
> 三件事必须同时对上：SQL 中主键位**不传值**（源文用 `null` 占位）、`useGeneratedKeys = true` 打开回填、`keyProperty`（Java 属性）与 `keyColumn`（数据库列）分别指明两端。测试里 `System.out.println(user)` 之所以能看到主键，就是因为回填写进了对象。

#### 测试代码：JUnit + 事务提交/回滚

源文的测试不再手写 `main`，改用 JUnit，并把 session 的开关放进 `@Before` / `@After`：

```java
//测试的代码
public class JunitAnnotationTest {

    SqlSession session;
    //测试代码执行前先执行这个函数
    @Before
    public void myBegin() throws IOException {
        //查找根目录
        InputStream is = Resources.getResourceAsStream("mybatis-config.xml");
        SqlSessionFactory factory = new SqlSessionFactoryBuilder().build(is);
        session =factory.openSession();//打开session
    }
    //当测试代码执行完毕后，执行after注解的函数
    @After
    public void myClose(){
        session.close();//用完关闭session
    }
    @Test
    public void test001(){
        UserMapperAnnotation mapper = session.getMapper(UserMapperAnnotation.class);
        User user = new User();
        int count = mapper.insertUser(user);
        if(count==1){
            session.commit();//提交永久保存
        }else{
            session.rollback();//回滚事务，取消以前的所有操作
        }
        System.out.println(count);
    }
    @Test
    public void test002(){
        UserMapperAnnotation mapper = session.getMapper(UserMapperAnnotation.class);
        //添加数据
        User user = new User();
        user.setUserPhone("1234");
        user.setUserState(1);
        user.setUserLoginName("aaaaaa");
        user.setUserId(9);
        user.setUserError(0);
        user.setUserIsAdmin(1);
        user.setUserName("aaaaaaa");
        user.setUserPwd("DEC2BFC0F2EA631CCE2D72CB6FBD5602");
        user.setUserSalt("bc@fg!");

        int count = mapper.insertUser2(user);
        if(count==1){
            session.commit();//提交永久保存
        }else{
            session.rollback();//回滚事务，取消以前的所有操作
        }
        System.out.println(count);
    }
    @Test
    public void test003(){
        UserMapperAnnotation mapper = session.getMapper(UserMapperAnnotation.class);
        //添加数据
        User user = new User();
        user.setUserPhone("123433");
        user.setUserState(1);
        user.setUserLoginName("aaabbb");
        //user.setUserId(9);//没有给自动增长列赋值
        user.setUserError(0);
        user.setUserIsAdmin(1);
        user.setUserName("aaaabbb");
        user.setUserPwd("DEC2BFC0F2EA631CCE2D72CB6FBD5602");
        user.setUserSalt("bc@fg!");
        //返回自动增长列的值
        int count = mapper.insertUser3(user);
        if(count==1){
            session.commit();//提交永久保存
        }else{
            session.rollback();//回滚事务，取消以前的所有操作
        }
        System.out.println(count);
        System.out.println(user);
    }
}
```

对照 `test002` 与 `test003` 可以看出 `@Options` 的效果：`test002` 的 `insertUser2` 需要**手动** `user.setUserId(9)`，`test003` 走 `insertUser3`，源文把这一行注释掉了（`//user.setUserId(9);//没有给自动增长列赋值`），主键由数据库给出、再回填。

> [!warning] 注解路线同样必须 `commit`
> `openSession()` 默认不自动提交，这一点不因换成注解而改变。源文的模板是 `if(count==1){ session.commit(); } else { session.rollback(); }`——按受影响行数决定提交还是回滚。写操作不提交，数据库不会有任何变化。

> [!warning] `session` 与 `mapper` 的获取时机
> `session` 在 `@Before` 里创建、在 `@After` 里关闭，所以每个测试方法拿到的是同一个 session 字段；而 `mapper` 必须**在每个测试方法内部**用 `session.getMapper(UserMapperAnnotation.class)` 现取。注解只是 SQL 的存放位置，调用入口仍然是 `getMapper` 拿到的接口代理。

#### Mapper 接口的注册

接口写完还需要在 `mybatis-config.xml` 里登记。源文在接口代码之后给出了这段片段：

```xml
<!-- 注册接口 -->
		<mapper class="com.neuedu.mapper.UserMapperAnnotation"/>
	</mappers>
</configuration>
```

> [!info] 这段片段的作用与位置
> 源文给它的标题是"接口的注册（mybatis-config.xml）"，即：注解路线的接口同样要在 `mybatis-config.xml` 的 `<mappers>` 节中登记，`class` 属性写**接口的全限定名**。源文片段是节选，只保留了 `<mapper class="..."/>` 以及收尾的 `</mappers>`、`</configuration>`，`<mappers>`、`<configuration>` 的开标签并未在同一片段中给出。
>
> 源文这里用的是 `<mapper class="..."/>`（逐个列出接口）。同一个 `<mappers>` 节也可以按包批量注册，配置文件两端的细节见 [[3.全局配置与日志]]。

> [!warning] 少了一层"字符串 id"依赖，但不是零配置
> 注解把 SQL 挪到了方法上，省掉的是 Mapper XML 文件与 `namespace + id` 的字符串定位；`mybatis-config.xml` 这个全局配置文件**依然存在**，Mapper 接口的注册也依然要在里面完成。

#### @Update

```java
//接口
//参数是一个对象
    //同学们经常错的地方，就是在换行时，有的sql语句的空格被省略掉了
    @Update("update tb_user " +
            "set user_login_name=#{userLoginName} " +
            "where user_id=#{userId}")
    int updateUser(User user);
    //多个不相干的参数，
    //@Param("userLoginName")给对应参数值，提供一个key，在sql中，通过key方式调用到对应的值
    @Update("update tb_user " +
            "set user_login_name=#{userLoginName}, " +
            "user_state=#{state} " +
            "where user_id=#{userId}")
    int updateUser2(@Param("userLoginName") String loginName, @Param("userId") Integer id, @Param("state") Integer state);
//测试代码
@Test
    public void test004() {
        UserMapperAnnotation mapper = session.getMapper(UserMapperAnnotation.class);
        //修改数据，参数是一个对象
        User user = new User();
        user.setUserLoginName("aaaaccc");
        user.setUserId(10);
        int count = mapper.updateUser(user);
        if (count == 1) {
            session.commit();//提交永久保存
        } else {
            session.rollback();//回滚事务，取消以前的所有操作
        }
        System.out.println(count);
    }

    @Test
    public void test005() {
        UserMapperAnnotation mapper = session.getMapper(UserMapperAnnotation.class);
        //修改数据，参数是一组
        int count = mapper.updateUser2("helloworld",10,5);
        if (count == 1) {
            session.commit();//提交永久保存
        } else {
            session.rollback();//回滚事务，取消以前的所有操作
        }
        System.out.println(count);
    }
```

`updateUser` 传对象，`#{userLoginName}`、`#{userId}` 直接取属性；`updateUser2` 传三个不相干的参数，就必须用 `@Param` 为每个参数"提供一个 key"，SQL 里通过 key 取值——注意 `updateUser2` 的 `@Param("userLoginName")` 修饰的形参名其实叫 `loginName`，SQL 里用的是 **`@Param` 里的值**。

> [!warning] 字符串拼接时最容易丢掉空格
> `@Update` 的 SQL 是用 `+` 拼多个字符串字面量写成的，源文专门标了"同学们经常错的地方，就是在换行时，有的sql语句的空格被省略掉了"。`"update tb_user "` 末尾的空格、`"set user_login_name=#{userLoginName} "` 末尾的空格都是 SQL 的一部分，删掉就会拼出 `update tb_userset ...` 这样的非法语句。实际报错时优先检查每个字符串字面量的**尾部空格**。

#### @Select

```java
//接口
 //查询
@Select("select * from tb_user")
List<User>  getUsers();
//查询
@Select("select * from tb_user where user_id=#{id}")
User  getUserById(@Param("id") Integer id);
//查询
@Select("select * from tb_user where user_id=#{no}")
User  getUserById2(@Param("no") Integer id);
//测试
@Test
    public void test008() {
        UserMapperAnnotation mapper = session.getMapper(UserMapperAnnotation.class);
        //查询数据(默认都遵循了驼峰命名法的映射关系)
        List<User> users = mapper.getUsers();
        for (User user : users) {
            System.out.println(user);
        }

    }
    @Test
    public void test009() {
        UserMapperAnnotation mapper = session.getMapper(UserMapperAnnotation.class);
        //查询数据(默认都遵循了驼峰命名法的映射关系)
        User user = mapper.getUserById(9);
        System.out.println(user);
    }
    @Test
    public void test0010() {
        UserMapperAnnotation mapper = session.getMapper(UserMapperAnnotation.class);
        //查询数据(默认都遵循了驼峰命名法的映射关系)
        User user = mapper.getUserById2(8);
        System.out.println(user);

    }
```

返回类型直接决定用哪个方法：`List<User>` 对应查集合，`User` 对应查单个。`getUserById` 与 `getUserById2` 的唯一差别是 `@Param` 的 key（`id` / `no`）与 SQL 中 `#{}` 的写法——**两边必须一致**。

> [!tip] `@Param` 的 key 才是 `#{}` 里的名字
> `getUserById2(@Param("no") Integer id)`：形参叫 `id`，但 SQL 写的是 `#{no}`，取值成功。所以 `#{}` 里填的是 `@Param` 指定的 **key**，不是形参名。key 与 `#{}` 对不上时，取到的是 `null` 或直接报错。

#### 驼峰映射不匹配时：@Results 与 @Result

源文紧接着抛出一个问题：

> **问题，如果编写代码时，没有遵循驼峰命名法的映射关系如何处理？**

它换用"原来的 Stu"来演示——`t_stu_info` 表里姓名列是 `stu_name`，而实体属性叫 `name`：

```java
// 接口
  @Select("select * from t_stu_info")
  List<Stu> getStus();
//测试
@Test
    public void test011() {
        StuMapperAnnotation mapper = session.getMapper(StuMapperAnnotation.class);
        //查询数据(没有遵循了驼峰命名法的映射关系，某些字段是null)
        List<Stu> stus = mapper.getStus();
        for (Stu stu : stus) {
            System.out.println(stu);
        }

    }
//运行结果，学生的姓名，没有填充成功
Stu{stuId=1, stuNo='stu001', name='null'}
Stu{stuId=2, stuNo='stu002', name='null'}
Stu{stuId=3, stuNo='stu003', name='null'}
Stu{stuId=4, stuNo='stu001', name='null'}
```

> [!warning] 源文缺口
> 源文在此只写了一句"使用原来的Stu，"就把 `Stu` 实体与 `StuMapperAnnotation` 接口拿来用了，它们的定义、`t_stu_info` 的建表语句都不在本区间内。

改成 `@Results` + `@Result` 手工指定映射关系：

```java
//接口
@Select("select * from t_stu_info")
    @Results({
            @Result(id = true, property = "stuId", column = "stu_id"),
            @Result(property = "stuNo", column = "stu_no"),
            @Result(property = "name", column = "stu_name")
    })//编写映射关系
    List<Stu> getStus2();
    //@Results是一个集合@Result对应的是某一个映射的处理
    // id = true 是否是主键，不写默认是false, property = "stuId" 属性, column = "stu_id" 数据中的列
//测试
 @Test
    public void test012() {
        StuMapperAnnotation mapper = session.getMapper(StuMapperAnnotation.class);
        //查询数据(自己编写了映射关系)
        List<Stu> stus = mapper.getStus2();
        for (Stu stu : stus) {
            System.out.println(stu);
        }

    }
//结果（修改代码后，所有的字段都填充成功）
Stu{stuId=1, stuNo='stu001', name='zhangsanTX'}
Stu{stuId=2, stuNo='stu002', name='lisiTX'}
Stu{stuId=3, stuNo='stu003', name='wangwuTX'}
Stu{stuId=4, stuNo='stu001', name='wangliuTX'}
```

源文对 `@Results` / `@Result` 的说明（原文照录）：

```text
//@Results是一个集合@Result对应的是某一个映射的处理
// id = true 是否是主键，不写默认是false, property = "stuId" 属性, column = "stu_id" 数据中的列
```

> [!info] 什么时候才需要写 `@Result`
> 源文测试代码的注释反复强调"默认都遵循了驼峰命名法的映射关系"——也就是说 `tb_user` 那组查询之所以什么都不用写，是因为列名与属性名本来就能对上（依赖全局的驼峰映射）。只有当列名和属性名**对不上**（如 `stu_name` ↔ `name`）时，才需要 `@Results` 手工补映射，否则该字段就是 `null`。

#### 复用映射：@ResultMap

同一个映射关系写多遍显然不划算，源文的原话是：

> **如果每次查询都要写相同的映射关系，效率低，不方便后期的修改与维护**

先看重复的写法：

```java
//原来的
@Select("select * from t_stu_info")
    @Results({
            @Result(id = true, property = "stuId", column = "stu_id"),
            @Result(property = "stuNo", column = "stu_no"),
            @Result(property = "name", column = "stu_name")
    })//编写映射关系
    List<Stu> getStus2();
    //@Results是一个集合@Result对应的是某一个映射的处理
    // id = true 是否是主键，不写默认是false, property = "stuId" 属性, column = "stu_id" 数据中的列


    //通过条件，再查一次集合(映射条件我们写了多次，能不能只写一次呢？完全可以)
    @Select("select * from t_stu_info where stu_id >=#{no}")
    @Results({
            @Result(id = true, property = "stuId", column = "stu_id"),
            @Result(property = "stuNo", column = "stu_no"),
            @Result(property = "name", column = "stu_name")
    })
    List<Stu> getStus3(@Param("no") Integer no);
```

给 `@Results` 起一个 `id`，其他地方用 `@ResultMap` 引用：

```java
//修改为
 @Select("select * from t_stu_info")
    @Results(id="stuBase1",value= {
            @Result(id = true, property = "stuId", column = "stu_id"),
            @Result(property = "stuNo", column = "stu_no"),
            @Result(property = "name", column = "stu_name")
    })//编写映射关系
    List<Stu> getStus2();
    //@Results是一个集合@Result对应的是某一个映射的处理
    // id = true 是否是主键，不写默认是false, property = "stuId" 属性, column = "stu_id" 数据中的列


    //通过条件，再查一次集合(映射条件我们写了多次，能不能只写一次呢？完全可以)
    @Select("select * from t_stu_info where stu_id >=#{no}")
    @ResultMap("stuBase1")//调用已经存在的@Results的id
    List<Stu> getStus3(@Param("no") Integer no);
//测试
 @Test
public void test013() {
    StuMapperAnnotation mapper = session.getMapper(StuMapperAnnotation.class);
    //查询数据(自己编写了映射关系)
    List<Stu> stus = mapper.getStus3(3);
    for (Stu stu : stus) {
        System.out.println(stu);
    }

}
//结果
[com.neuedu.mapper.StuMapperAnnotation.getStus3]-==> Parameters: 3(Integer)
[com.neuedu.mapper.StuMapperAnnotation.getStus3]-<==      Total: 2
Stu{stuId=3, stuNo='stu003', name='wangwuTX'}
Stu{stuId=4, stuNo='stu001', name='wangliuTX'}
```

注意改法：加 `id="stuBase1"` 的同时把原来直接写的那组 `@Result` 放进了 `value = { ... }`，因为 `@Results` 的 `id` 与 `value` 是两个属性，映射集合这时是显式赋给 `value` 的。

#### 直接调用 XML 中的 resultMap

`@ResultMap` 引用的不限于注解里定义的映射，也可以指向 XML 文件中 `resultMap` 标签的 `id`：

```java
//也可以直接调用xml文件中的resultMap标签的id，调用的方式是，命名空间+id
//接口
@Select("select * from t_stu_info where stu_id <=#{no}")
    @ResultMap("com.neuedu.mapper.StuMapper.stuBase")//调用已经存在的xml文件中resultMap标签的id，命名空间+id
```

调用的方式是 **命名空间 + id**：`com.neuedu.mapper.StuMapper.stuBase`——前一段是 XML 的 `namespace`，后一段是 `resultMap` 标签的 `id`。这正是源文开头所说"结合注解与xml一起使用"的第一个落点：SQL 用注解写，映射仍复用 XML 里已有的定义。

## 易错点

> [!warning] 拼接 SQL 丢掉空格
> `@Update` / `@Delete` 的 SQL 用 `+` 串联多个字符串字面量时，每个字面量**末尾的空格**是语句的一部分。源文明确点出这是"同学们经常错的地方"，报语法错误时先查尾部空格。

> [!warning] 增删改忘了 `commit`
> `openSession()` 默认不自动提交。`insertUser*` / `updateUser*` / `deleteUser*` 之后必须 `session.commit()`，源文用 `if(count==1)` 判断、否则 `session.rollback()`。

> [!warning] `#{}` 里的名字要和 `@Param` 的 key 对齐
> 多个不相干的参数必须用 `@Param("key")` 给 key，SQL 中通过 key 取值（`updateUser2`）。要留意源文 `getUserById2(@Param("no") Integer id)` 这种形参名与 key 不同的情况——认的是 **key**，不是形参名。

> [!warning] 列名与属性名对不上，字段就是 `null`
> 驼峰映射能对上的（`tb_user` 那组）不用写任何映射；对不上的（`stu_name` ↔ `name`）必须用 `@Results` / `@Result` 指定，否则源文的 `test011` 结果里 `name` 全是 `null`。

其他对照：

| 现象 | 原因 |
|---|---|
| 拼接出的 SQL 语法错误 | 字符串字面量尾部空格被删掉 |
| 数据没进库 | 增删改后未 `commit` |
| 某字段查出为 `null` | 列名与属性名不符合驼峰映射，且未写 `@Results` |
| `#{}` 取不到值 | `@Param` 的 key 与 `#{}` 中的名字不一致 |
| 回填不到自增主键 | 缺 `@Options(useGeneratedKeys = true, keyProperty = ..., keyColumn = ...)`，或 SQL 里给主键传了值 |
| `getMapper` 拿不到接口 | 接口未在 `mybatis-config.xml` 的 `<mappers>` 中注册 |
