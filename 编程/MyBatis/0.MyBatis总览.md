## 学习主线

1. **先建立"半自动 ORM"的定位**：MyBatis 基于 JDBC，封装连接与结果集处理，但把 SQL 与映射交给开发者。不理解这一点，就会误以为它是 Hibernate 那样的全自动 ORM。
2. **跑通最小闭环**：依赖 → 目录 → 数据源配置 → 实体类 → 全局配置 → Mapper 映射 → SqlSession 调用。这条链路走通一次，后面所有特性都是在这条链上做加法。
3. **掌握两种映射能力**：`resultMap` 解决列名与属性不一致；`association`/`collection` 解决多表装配。前者是后者的基础。
4. **理解关联查询的两条路线**：嵌套查询（多发 SQL）与嵌套结果（一次 join 取回）。N+1 问题就产生于前者，见第 7 篇。
5. **掌握动态 SQL**：让一条 SQL 标签应对多种条件组合，这是 MyBatis 最实用的部分。
6. **再走一遍注解路线**：注解把 SQL 搬回接口，适合简单场景；复杂 SQL 仍以 XML 为主。两条路线要能互相翻译。

## 必须区分的核心概念

| 概念 | 结论 |
|---|---|
| `#{}` 与 `${}` | `#{}` 是预编译占位符（走 `PreparedStatement` 参数）；`${}` 是**字符串替换**，直接拼进 SQL，有注入风险。模糊查询的错误写法就出自这一族 |
| `resultType` 与 `resultMap` | `resultType` 用于列名与属性天然对应的简单情况；列名不一致、或需要装配关联对象时用 `resultMap` |
| `association` 与 `collection` | `association` 装配**单个**关联对象（一对一）；`collection` 装配**集合**（一对多/多对多） |
| `ofType` 与 `javaType` | `collection` 的 `ofType` 指集合**元素**的类型；`javaType` 指属性本身的类型。源文第 5 篇只出现 `ofType` |
| `select *` 与显式列名 | `select *` 写法省事，但解析时需遍历整表结构取全部列；显式列名更快，代价是表结构变更后维护量大。`<sql>` 片段正是为降低这个维护量 |
| 增删改与查询的提交 | `openSession()` 默认不自动提交，**增删改后必须 `commit()`**；查询不修改数据，无需提交 |
| XML 路线与注解路线 | XML 适合复杂 SQL 与动态 SQL 复用；注解适合简单 SQL，写在接口方法上。两者可混用 |
| 嵌套查询与嵌套结果 | 嵌套查询每条主记录再发一次子查询（易触发 N+1）；嵌套结果用一条 join SQL 一次取回 |
