## MySQL 递归查询

### 要解决的问题

源文的出发点：对于数据库中的树形结构数据，如部门表，有时候，我们需要知道**某部门的所有下属部门**，或者**某部分的所有上级部门**，这时候就需要用到 MySQL 的递归查询。

本节的示例表是一张地区表 `t_areainfo`：每行记录自己的 `id` 与父节点 `parentId`，根节点（`id=1`「中国」）的 `parentId` 为 `0`。

### 建表与示例数据

```sql
-- 创建表
DROP TABLE IF EXISTS `t_areainfo`;
CREATE TABLE `t_areainfo` (
 `id` int(11) NOT '0' AUTO_INCREMENT,
 `level` int(11) DEFAULT '0',
 `name` varchar(255) DEFAULT '0',
 `parentId` int(11) DEFAULT '0',
 `status` int(11) DEFAULT '0',
 PRIMARY KEY (`id`)
) ENGINE=InnoDB AUTO_INCREMENT=65 DEFAULT CHARSET=utf8;
```

> [!warning] 源文疑似笔误
> 上面 `id` 列的 `int(11) NOT '0' AUTO_INCREMENT` 中的 `NOT '0'` 不是合法 DDL。按上下文（其它列用 `DEFAULT '0'`，主键自增）判断，这里**很可能是 `NOT NULL` 的笔误**。此处照抄源文原样以便与讲义对照；实际建表时需写成合法形式。

示例数据源文共列出 **63 行** `INSERT`，构成「中国 → 华北区/华南区 → 北京 → 海淀区…」等多层结构。节选如下：

```sql
-- 添加数据

INSERT INTO `t_areainfo` VALUES ('2', '0', '华北区', '1', '0');
INSERT INTO `t_areainfo` VALUES ('3', '0', '华南区', '1', '0');
INSERT INTO `t_areainfo` VALUES ('4', '0', '北京', '2', '0');

INSERT INTO `t_areainfo` VALUES ('6', '0', '丰台区', '4', '0');
INSERT INTO `t_areainfo` VALUES ('7', '0', '朝阳区', '4', '0');
-- ……（源文此处续有 '8'~'64' 共 57 行示例数据，结构与上面相同，此处不再逐行罗列）
INSERT INTO `t_areainfo` VALUES ('64', '0', 'xx省19', '1', '0');
```

各列依次为 `id, level, name, parentId, status`。层级关系由 `parentId` 指向父行的 `id` 表达：`华北区(2)`、`华南区(3)` 的父节点是 `中国(1)`；`北京(4)` 的父节点是 `华北区(2)`；`海淀区(5)` 的父节点是 `北京(4)`。

### 向下递归：查所有下级

源文用 `find_in_set()` 与 `group_concat()` 配合 `WHILE` 循环实现：

```sql
-- 向下递归：利用find_in_set()函数和group_concat()函数实现递归查询：
DROP FUNCTION IF EXISTS queryChildrenAreaInfo;DELIMITER ;;
CREATE FUNCTION queryChildrenAreaInfo(areaId INT)
RETURNS VARCHAR(4000)
BEGIN
DECLARE sTemp VARCHAR(4000);
DECLARE sTempChd VARCHAR(4000);

SET sTemp='$';
SET sTempChd = CAST(areaId AS CHAR);

WHILE sTempChd IS NOT NULL DO
SET sTemp= CONCAT(sTemp,',',sTempChd);
SELECT GROUP_CONCAT(id) INTO sTempChd FROM t_areainfo WHERE FIND_IN_SET(parentId,sTempChd)>0;
END WHILE;
RETURN sTemp;
END;;DELIMITER ;
-- 调用
SELECT queryChildrenAreaInfo(1);
```

调用后，函数返回的是一串以 `$` 开头、用逗号分隔的 `id` 集合。

调用方式与用途：

```sql
查询id为"4"下面的所有节点

SELECT * FROM t_areainfo WHERE FIND_IN_SET(id,queryChildrenAreaInfo(4));
```

**逐层推进的过程**（依据上面的函数体）：

1. 起始：`sTemp='$'`，`sTempChd` = 传入的 `areaId`（转成字符串）。
2. 循环：把当前层的 `sTempChd` 追加到 `sTemp` 之后；再用 `GROUP_CONCAT(id)` 查出**所有 `parentId` 属于当前层**的子节点 `id`，结果覆盖回 `sTempChd`，作为下一层的输入。
3. 终止：当再也查不到子节点时，`GROUP_CONCAT` 返回 `NULL`，`WHILE sTempChd IS NOT NULL` 判定为假，循环结束。
4. 外层用 `FIND_IN_SET(id, 函数的返回串)`，即可一次性把集合内的所有行筛出来。

> [!tip] 两个关键点
> - `SET sTemp='$'` 是一个**初始哨兵值**，作用是让拼接出的字符串以 `$` 开头，从而能与其他值区分开；
> - `FIND_IN_SET(x, 'a,b,c')` 用来判断 `x` 是否在这个逗号串里——正是它把"字符串"当成了集合来用。

### 向上递归：查所有上级

向上递归要逐级取单个父节点，因此循环条件与写法都不同：

```sql
5、向上递归
DROP FUNCTION IF EXISTS queryChildrenAreaInfo1;DELIMITER;;
CREATE FUNCTION queryChildrenAreaInfo1(areaId INT)
RETURNS VARCHAR(4000)
BEGIN
DECLARE sTemp VARCHAR(4000);
DECLARE sTempChd VARCHAR(4000);

SET sTemp='$';
SET sTempChd = CAST(areaId AS CHAR);
SET sTemp = CONCAT(sTemp,',',sTempChd);

SELECT parentId INTO sTempChd FROM t_areainfo WHERE id = sTempChd;
WHILE sTempChd <> 0 DO
SET sTemp = CONCAT(sTemp,',',sTempChd);
SELECT parentId INTO sTempChd FROM t_areainfo WHERE id = sTempChd;
END WHILE;
RETURN sTemp;
END;;DELIMITER ;

调用方式
查询id为"7"的节点的所有上级节点：
SELECT * from t_areainfo where FIND_IN_SET(id,queryChildrenAreaInfo1(7));
```

### 两个方向的差别

| 对比项 | 向下递归 `queryChildrenAreaInfo` | 向上递归 `queryChildrenAreaInfo1` |
|---|---|---|
| 目标 | 某节点的所有**下级** | 某节点的所有**上级** |
| 每轮取几个节点 | 一批（`GROUP_CONCAT(id)`，靠 `parentId` 反查子节点） | 一个（`SELECT parentId INTO ...`，逐级向上） |
| 循环条件 | `WHILE sTempChd IS NOT NULL` | `WHILE sTempChd <> 0` |
| 终止原因 | `GROUP_CONCAT` 查无结果时返回 `NULL` | 到达根节点，其 `parentId` 为约定的 `0` |
| 使用的函数 | `FIND_IN_SET` + `GROUP_CONCAT` | 仅 `FIND_IN_SET`（用于最终筛选） |

> [!warning] 源文未说明的限制
> 两个函数的返回值与局部变量都声明为 `VARCHAR(4000)`。当层级很深、返回的 `id` 串超过该长度时的行为，**源文没有说明**，此处不做推测。实际使用前建议确认这一点。
>
> 另外，向上递归的终止条件依赖于"根节点的 `parentId` 约定为 `0`"这一前提；如果数据中根节点的 `parentId` 不是 `0`，循环将无法按预期结束——这是从函数体可以看出的前提，源文未展开讨论。
