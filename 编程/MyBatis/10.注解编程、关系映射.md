# 注解编程、关系映射

注解路线的关联查询，说到底是把 XML 里的两个嵌套标签换成两个注解属性：

- XML 的 `<association>` → 注解的 `one = @One(...)`（装**一个**对象）；
- XML 的 `<collection>` → 注解的 `many = @Many(...)`（装**一个集合**）。

基础的单表 CRUD 注解（`@Select` / `@Insert` / `@Results` / `@Result`）见 [[9.注解编程、基础CRUD]]；XML 路线的 `association` / `collection` 与嵌套查询配置见 [[5.关联查询、一对一与一对多]]、[[6.关联查询、多对多与三表案例]]。那两篇讲过的建表、实体、映射配置，本篇不重复搬运，只聚焦同一件事在注解里怎么写。

## 注解与 XML 的对应关系

下表每一项都取自本篇源文代码里实际出现过的写法：

| XML 路线 | 注解路线 | 作用 |
|---|---|---|
| `<resultMap id="xxx">` | `@Results(id="xxx")` | 给这一组列映射起名字 |
| `<id>` / `<result>` | `@Result(property = ..., column = ...)` | 一列 → 一个属性 |
| `<association>` | `@Result(..., one = @One(...))` | 装配一个对象 |
| `<collection>` | `@Result(..., many = @Many(...))` | 装配一个集合 |
| 嵌套节点的 `select="命名空间.id"` | `@One` / `@Many` 的 `select = "..."` | 再发一条查询取关联数据 |
| 嵌套节点的 `resultMap="命名空间.resultMapId"` | `@One` / `@Many` 的 `resultMap = "..."` | 不再发查询，从当前结果集装配 |
| `fetchType="lazy"` / `"eager"` | `fetchType = FetchType.LAZY` / `EAGER` | 延迟或立即加载 |
| `<select resultMap="xxx">` | 方法上的 `@ResultMap("xxx")` | 复用别处定义好的映射 |

> [!info] 注解里的 `select` 写完全限定名
> 源文注释原话：「注意注解中的写法 select = "包名.接口名.方法名" 完全限定名」。注解版的 `select` 指向的是 **Mapper 接口的方法**。源文紧接着又示范了另一条路：同一个位置「也可以调用 xml 文件中的对应的方法（命名空间.id）」。即注解里既能指向注解方法，也能指向 XML 里的标签 id。
>
> `FetchType` 需要 import：`org.apache.ibatis.mapping.FetchType`。

## 一对一映射 @One

源文用的还是「身份证与员工」的老案例。

> [!warning] 源文缺口
> 源文的实体部分只写了一句：「在任何一方，创建对方的一个对象属性（略）」。也就是说这一节里 `Card` 与 `Worker` 两个实体的完整字段定义、以及 `t_card` / `t_worker` 的建表 SQL，源文都没有给出，需要参考 [[5.关联查询、一对一与一对多]]。此外整节开头写的是「使用原来的身份证与员工的案例」，同样是在指向前面的篇章。

### 接口

```java
//接口
public interface CardMapperAnnotation {
    //获得所有的身份证号，同时获得对应的员工信息
    @Select("select * from t_card")
    @Results(id="cardWorkerAdv2",value={
            @Result(property = "cardId",column = "card_id"),
            @Result(property = "cardNo",column = "card_no"),
            @Result(property = "cardAddress",column = "card_address"),
            @Result(property = "worker",column = "card_id",one = @One( fetchType = FetchType.EAGER,
                    select = "com.neuedu.mapper.WorkerMapperAnnotation.getWorkerByCardId")),//注意注解中的写法select = "包名.接口名.方法名" 完全限定名
    })
    List<Card> getCardsAndWorker();

    //通过xml方式去调用
    @Select("select * from t_card")
    @Results(id="cardWorkerAdv3",value={
            @Result(property = "cardId",column = "card_id"),
            @Result(property = "cardNo",column = "card_no"),
            @Result(property = "cardAddress",column = "card_address"),
            @Result(property = "worker",column = "card_id",one = @One( fetchType = FetchType.EAGER,
                    select = "com.neuedu.mapper.WorkerMapper.getWorkerByCardId")),//也可以调用xml文件中的对应的方法（命名空间.id）
    })
    List<Card> getCardsAndWorker2();

}

public interface WorkerMapperAnnotation {
    @Select("select * from t_worker where worker_card_id=#{id}")
    Worker getWorkerByCardId(@Param("id") Integer id);
}
```

两个方法的主体结构完全一样，只有 `one = @One(...)` 里的 `select` 不同：

- `getCardsAndWorker()` → 指向**注解方法** `com.neuedu.mapper.WorkerMapperAnnotation.getWorkerByCardId`；
- `getCardsAndWorker2()` → 指向 **XML 里的标签**（命名空间.id）`com.neuedu.mapper.WorkerMapper.getWorkerByCardId`。

> [!tip] `@One` 就是嵌套 select
> `column = "card_id"` 说明拿当前结果集的 `card_id` 这一列的值当参数，喂给 `select` 指定的那条查询（对到方法参数上的 `#{id}`）。这是「一次主查询 + N 次子查询」的形态，源文在这两个方法上都标 `fetchType = FetchType.EAGER`，即立即加载。

```java

```

这段里有两处源文**自己**给出的判断，必须原样保留：

| 方法 | 源文注释 | 源文的说明 |
|---|---|---|
| `getAllCards2()` | 「存在N+1的问题」 | 复用的 XML `resultMap`「是使用select属性」 |
| `getAllCards3()` | 「解决了n+1的问题」 | 复用的 XML `resultMap`「是使用resultMap属性」，且 `@Select` 写成了一条 `inner join` |

> [!warning] `getAllCards2()` 是反例
> 它是源文标注为「存在 N+1 的问题」的写法，不能当作可行方案照抄。原因就在源文自己写的注释里：它引用的 `com.zsp.mapper.CardMapper.cardAndEmp` 这个 XML resultMap 用的是 `select` 属性（嵌套 select，会再发子查询）；而 `getAllCards3()` 引用的 `cardAndEmp2` 用的是 `resultMap` 属性，同时 `@Select` 里已经把两张表 join 好，一次取回。判定口径的完整说明见 [[7.关联查询的N+1问题]]。

> [!warning] 「补充」这段与前面不是同一个工程
> 包名是 `com.zsp.mapper`（前面是 `com.neuedu.mapper`），表名是 `t_cardinfo` / `t_emp`（前面是 `t_card` / `t_worker`），属性名是 `emp`（前面是 `worker`），列名大小写是 `card_Id`（前面是 `card_id`）。不要把两段拼进同一个 mapper 目录。

> [!warning] 源文缺口
> `com.zsp.mapper.CardMapper.cardAndEmp`、`cardAndEmp2` 这两个 XML resultMap 的定义、`CardMapper` / `EmpMapper` 的 XML 内容、以及 `t_cardinfo` / `t_emp` 的建表 SQL，本节均未给出，需参考 [[5.关联查询、一对一与一对多]] 与 [[7.关联查询的N+1问题]]。

## 一对多映射 @Many

源文用的还是「身份证号与银行卡」的一对多关系，并给了两句口诀：

> （1）在“多”的一方的类中，创建“一”的一方的对象，参考上面的一对一的写法
> （2）在“一”的一方创建“多”的一方的**集合**

第（2）步是注解版一对多真正新增的东西——在一的一方的实体里放一个集合属性。

```java
public class Card2 {
    private int cardId;
    private String cardNo;
    private String cardAddress;
    //（1）建立一个集合，保存某一张身份证对饮的所有的银行卡信息
    private List<BankCard> bankCards;
    public List<BankCard> getBankCards() {
        return bankCards;
    }
    public void setBankCards(List<BankCard> bankCards) {
        this.bankCards = bankCards;
    }
    //....
}
```

> [!note] 源文原样保留
> 上面注释里的「对饮」是源文的错别字（应为「对应」），此处照抄不改。

### 接口

```java
//接口
public interface Card2MapperAnnotation {
    //调用其他接口的注解编程的代码
    @Select("select * from t_card2")
    @Results(id="getCard2AndBankCards",value = {
            @Result(property ="cardId",column = "card_id"),
            @Result(property ="cardNo",column = "card_no"),
            @Result(property ="cardAddress",column = "card_address"),
            @Result(property ="bankCards",column = "card_id",many = @Many( fetchType = FetchType.LAZY,
                    select = "com.neuedu.mapper.BankCardMapperAnnotation.getBankCardsByCard2Id"
            )),
    })
    List<Card2> getCard2AndBankCards();//获得身份证号对应的所有的银行卡

    //调用xml文件中的,直接使用创建好的ResultMap
    @Select("select * from t_card2")
    @ResultMap("com.neuedu.mapper.Card2Mapper.card2AndBankCardsAdv")
    List<Card2> getCard2AndBankCards2();//获得身份证号对应的所有的银行卡


}
public interface BankCardMapperAnnotation {
    @Select("select * from t_bank_card where bank_card_id=#{id}")
    List<BankCard> getBankCardsByCard2Id(@Param("id") Integer id);//通过身份证号，获得对应的银行卡的集合
}
```

和一对一对照着看，差别只有两处：

- `one = @One(...)` 换成了 `many = @Many(...)`；
- 子查询方法 `getBankCardsByCard2Id` 的返回类型是 `List<BankCard>`（集合），而一对一的 `getWorkerByCardId` 返回的是单个 `Worker`。

`fetchType` 这里写的是 `FetchType.LAZY`（延迟加载），与一对一的 `EAGER` 相反。

> [!warning] 源文缺口
> `com.neuedu.mapper.Card2Mapper.card2AndBankCardsAdv` 这个 XML resultMap 的定义、`Card2` / `BankCard` 的完整实体字段、以及 `t_card2` / `t_bank_card` 的建表 SQL，本节均未给出。

## 多对多映射 @Many

这一节底下源文分了三个小节，用的注解仍然是 `@Many`。

### 两表的处理

源文的两句前提：

> （1）使用原来的学生与科目的关系
> （2）多对多是双向的一对多关系，从任何一方看过都是一对多关系

a，在“一”的一方创建“多”的一方的**集合**：

```java
public class Subject implements Serializable {
    private int subjectId;
    private String subjectName;
    private int subjectCent;

    private List<StuInfo> stuInfos; //科目中的学生信息的集合
    public List<StuInfo> getStuInfos() {
        return stuInfos;
    }
    public void setStuInfos(List<StuInfo> stuInfos) {
        this.stuInfos = stuInfos;
    }
    //....
}
```

```java
//接口
public interface SubjectMapperAnnotation {
    //调用其他注解的方式，实现多对多的处理
    @Select("select * from t_subject")
    @Results(id="getSubjectsAndStuInfos",value = {
            @Result(property = "subjectId",column = "subject_id"),
            @Result(property = "subjectName",column = "subject_name"),
            @Result(property = "subjectCent",column = "subject_cent"),
            @Result(property = "stuInfos",column = "subject_id",many = @Many(fetchType = FetchType.LAZY,
            select = "com.neuedu.mapper.StuInfoMapperAnnotation.getStuInfosBySubjectId")),
    })
    List<Subject> getSubjectsAndStuInfos();//获得所有的科目与对应的学生信息
    //调用xml文件的方式，实现多对多的处理
    @Select("select * from t_subject")
    @ResultMap("com.neuedu.mapper.SubjectMapper.subjectsAndStuInfosAdv")
    List<Subject> getSubjectsAndStuInfos2();//获得所有的科目与对应的学生信息

}
public interface StuInfoMapperAnnotation {
    @Select("select stu.stu_id,stu.stu_name,stu.stu_no \n" +
            "from t_stu_info stu INNER JOIN t_score s on s.score_stu_id=stu.stu_id \n" +
            "where s.score_subject_id=#{id} \n")
    List<StuInfo> getStuInfosBySubjectId(@Param("id") Integer id);
}
```

关键在子查询的那条 SQL：它**不是**只查一张 `t_stu_info`，而是 `INNER JOIN t_score`（成绩表）之后才走到学生。`t_score` 就是连接学生与科目的中间表。

> 仍然使用大括号的方式处理｛key=value,key1=value1, ...｝

> [!tip] `{key=value}` 的三个要点（源文注释原文）
> - `key` 随便写，`value` 一定是**查询结果集中的列**；
> - **多参数传入数据时，key 要与要调用的函数的 `@Param("key")` 要一致**；
> - 上面这段里 `column = "{id=card_id,cardNo=card_no}"` 的两个 key `id` / `cardNo`，正好对上 `getBankCardsByCard2Id2(@Param("id") Integer id, @Param("cardNo") String no)` 的两个 `@Param` 名字（注意 Java 形参名叫 `no`，但 `@Param` 里写的是 `cardNo`，起作用的是一致的那一端——`@Param` 的值）。

### 为什么一对多和多对多用的是同一个 @Many

这是注解路线里最容易犯迷糊的地方：源文「一对多映射」和「多对多映射」两节，用的都是 `many = @Many(...)`，**没有为多对多引入任何新注解**。

源文对此唯一写明的依据，是「多对多映射」开头的第二句：

> 多对多是双向的一对多关系，从任何一方看过都是一对多关系

也就是说，在 MyBatis 的注解这一层，多对多本来就不需要单独的注解——它拆开看就是一条一对多。至于两个小节在代码上到底差在哪，源文没有专门写「判据」一节，但从它给出的代码里能读出三处客观差异：

| 观察点 | 一对多（身份证 ↔ 银行卡） | 多对多（学生 ↔ 科目） |
|---|---|---|
| `@Many` 里 `select` 指向的子查询 SQL | 只查对方一张表：`select * from t_bank_card where bank_card_id=#{id}` | 必须经中间表才能走到对方：`from t_stu_info stu INNER JOIN t_score s on s.score_stu_id=stu.stu_id where s.score_subject_id=#{id}` |
| 集合属性的元素类型与字段名 | `private List<BankCard> bankCards;` | `private List<StuInfo> stuInfos;` |
| 业务语义 | 一张身份证对应多张银行卡，另一侧不建集合 | 科目与学生互为「多」，中间靠 `t_score` 连接 |

结论：**区分的依据不在注解名上**——`@Many` 对两者是同一个注解。区别体现在它指向的那条子查询：一对多的子查询直接落到对方表上；多对多的子查询要先 `INNER JOIN` 一张中间表（这里是 `t_score`）才能拿到对方记录，且源文把它描述为「双向的一对多」。集合元素类型（`List<BankCard>` / `List<StuInfo>`）只是这一差别在实体上的投影，本身并不能说明关系的重数。

> [!warning] 别把「多对多」当成第三条路
> 源文没有给出任何形如 `@ManyToMany` 的注解，`@One` / `@Many` 就是全部。遇到多对多的表结构时，按源文的做法写 `@Many` + 一条走中间表的子查询即可；需要双向都能查时，源文的说法是「从任何一方看过都是一对多关系」，也就是在**两边各写一套** `@Many`（本节只给出了一侧到另一侧的映射，反向的 `StuInfo.subjects` 见前一小节的源文缺口说明）。

### 这一段里能读出的结构差别

源文没有给这一节的运行日志，也没有逐行分析，因此下面只列代码本身能读出的东西：

1. **XML 那三组 resultMap 里，只有 `bookAdv03` 不再是嵌套 select。** `bookAdv01` 的 `<collection>` 写的是 `select="com.cs.mapper.ReaderMapper.getReadersByBookId"`、`bookAdv02` 写的是 `select="com.cs.mapper.HistoryMapper.getHistoriesByBookId"`——这两处都会**再发一条查询**；`bookAdv03` 写的是 `resultMap="com.cs.mapper.HistoryMapper.historyAdv02"`，没有 `select`。
2. **`njiayi()` 配的是一条表连接 SQL。** `@Select` 里是 `book b left JOIN read_his h ... left JOIN reader r ...`，一条语句把书、借阅历史、读者都取回来，再用 `@ResultMap("com.cs.mapper.BookMapper.bookAdv03")` 复用上面的映射。
3. **全注解版的嵌套节点同样没有 `select`。** `@Many(fetchType = FetchType.LAZY, resultMap = "com.cs.mapper.HistoryMapperAnnotation.historyAdv01")` 与 `@One(fetchType = FetchType.EAGER, resultMap = "com.cs.mapper.ReaderMapperAnnotation.readerBase")` 写的都是 `resultMap`，即从当前结果集装配，而不是另发查询；外层配的也是同一条 left join SQL。

> [!warning] 源文在这里只写了「n+1问题」这个注释
> 两个 `njiayi()` 方法上方的注释都是 `//n+1问题`，测试方法上的注释是 `//n+1查询`。但源文**没有**像 XML 篇章那样在标题里标注「有问题的」，也没有指出问题出在哪一行、更没有任何一处写着「解决了 n+1」。因此本篇不替源文下结论，只把它实际写出的结构差别摆出来。
>
> 「`select` 会再发查询 → N+1；`resultMap` 从当前结果集装配 → 不再发查询」这个判定口径，出自 [[7.关联查询的N+1问题]] 中源文自己的注释与两种写法的对比，可以拿它回来读本节这两段代码。反过来，本节也印证了那个口径：同一件「书 → 借阅历史 → 读者」的装配，XML 路线与注解路线都各自提供了「嵌套 select」与「嵌套 resultMap」两种写法，差别只在嵌套节点上写 `select` 还是写 `resultMap`。

> [!info] 没有用到的 `@Select` 也必须写
> 源文在 `ReaderMapperAnnotation.getReaderById` 上方给的注释是：「虽然没有使用该语句进行查询，这里也不能不写」。原因是 `readerBase` 这组列映射必须挂在某个方法上才存在——注解版没有独立的 `<resultMap>` 标签，被 `@One` / `@Many` 的 `resultMap` 引用的映射，只能寄居在一个普通方法上。所以哪怕这条 `@Select` 永远不会被调用，它也不能省。

> [!tip] `fetchType` 在这里不是判据
> 看一眼就知道：本节 `@Many` 写的是 `LAZY`，`@One` 写的是 `EAGER`，而 [[7.关联查询的N+1问题]] 里「可以使用的」那种写法两份都是 `eager`。真正区分两种做法的是嵌套节点上写的是 **`select`** 还是 **`resultMap`**。

> [!warning] 源文缺口
> `com.cs.mapper.HistoryMapper.historyAdv02` 这个被 `bookAdv03` 引用的 resultMap、`com.cs.mapper.ReaderMapper` 与 `com.cs.mapper.HistoryMapper` 两个 XML 文件的内容、`Book` / `History` / `Reader` 的完整实体字段、以及 `book` / `read_his` / `reader` 三张表的建表 SQL，本节均未给出。`reader` 表的建表语句同时也不在 [[7.关联查询的N+1问题]] 这一节里，两处都缺。

## 易错点小结

> [!warning] 注解里的 `select` 必须写完全限定名
> 两种合法写法：`包名.接口名.方法名`（指向注解方法），或 `命名空间.id`（指向 XML 标签）。只写方法名是找不到的。

> [!warning] `@One` / `@Many` 引用的 `resultMap` 要带命名空间
> 源文里的写法是 `resultMap = "com.cs.mapper.ReaderMapperAnnotation.readerBase"`、`@ResultMap("com.neuedu.mapper.SubjectMapper.subjectsAndStuInfosAdv")`，全都带全路径。被引用的那个 `@Results(id=...)` 必须真的存在于该接口中。

> [!warning] 多参数 `column` 的 key 必须与 `@Param` 一致
> 源文原话：「** 多参数传入数据时，key要与要调用的函数的@Param("key") 要一致 **」。key 名随意，但必须两边对得上；value 一定是**结果集里的列名**，写属性名无效。

> [!warning] 子查询方法的参数要加 `@Param`
> 每一个例子里的子查询方法都写了 `@Param("id")` / `@Param("stuId")` / `@Param("bookId")`，SQL 里才能用 `#{id}` 取到值。一一对应关系见下表。

| 主查询 | 嵌套注解 | 子查询 | 传参方式 |
|---|---|---|---|
| `CardMapperAnnotation.getCardsAndWorker` | `one = @One` | `WorkerMapperAnnotation.getWorkerByCardId(@Param("id") ...)` | 单列 `column = "card_id"` |
| `Card2MapperAnnotation.getCard2AndBankCards` | `many = @Many` | `BankCardMapperAnnotation.getBankCardsByCard2Id(@Param("id") ...)` | 单列 `column = "card_id"` |
| `Card2MapperAnnotation.getCard2AndBankCards3` | `many = @Many` | `BankCardMapperAnnotation.getBankCardsByCard2Id2(@Param("id"), @Param("cardNo"))` | `column = "{id=card_id,cardNo=card_no}"` |
| `SubjectMapperAnnotation.getSubjectsAndStuInfos` | `many = @Many` | `StuInfoMapperAnnotation.getStuInfosBySubjectId(@Param("id") ...)` | 单列 `column = "subject_id"` |
| `SubjectMapperAnnotation.getSubjectsAndStuInfos3` | `many = @Many` | `StuInfoMapperAnnotation.getStuInfosBySubjectId2(@Param("id"), @Param("no"))` | `column = "{id=subject_id,no=subject_cent}"` |
| `StuInfoMapperAnnotation.getStudents` | `many = @Many` | `ScoreMapperAnnotation.getScoresByStuId(@Param("stuId") ...)` | 单列 `column = "stu_id"` |
| `ScoreMapperAnnotation.getScoresByStuId` | `one = @One` | `SubjectMapperAnnotation.getSubjectById(@Param("id") ...)` | 单列 `column = "score_subject_id"` |
| `BookMapperAnnotation.njiayi` | `many = @Many` + `resultMap` | 无（不发查询） | — |
| `HistoryMapperAnnotation.getHistoriesByBookId` | `one = @One` + `resultMap` | 无（不发查询） | — |

> [!tip] 返回集合还是单个对象，与 `one` / `many` 配套
> `many` 指向的方法返回 `List<...>`（`List<BankCard>`、`List<StuInfo>`、`List<Score>`、`List<History>`），`one` 指向的方法返回单个对象（`Worker`、`Subject`、`Reader`）。照抄时别把这两者写反。

> [!warning] 本节涉及的所有实体与建表 SQL 都不在本区间
> 源文全程用「使用原来的……案例」来指代，`Card` / `Worker` / `Card2` / `BankCard` / `Subject` / `StuInfo` / `Score` / `Book` / `History` / `Reader` 的完整字段定义与 `t_card`、`t_worker`、`t_card2`、`t_bank_card`、`t_subject`、`t_stu_info`、`t_score`、`book`、`read_his`、`reader` 的建表语句都没有给出，需要回到 [[5.关联查询、一对一与一对多]]、[[6.关联查询、多对多与三表案例]]、[[7.关联查询的N+1问题]] 补齐。
