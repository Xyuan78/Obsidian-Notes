# 组件通信

## 父传子：Props

```vue
<!-- Parent.vue -->
<script setup>
import SearchInput from "./SearchInput.vue";
</script>

<template>
  <SearchInput placeholder="搜索课程" />
</template>
```

```vue
<!-- SearchInput.vue -->
<script setup>
defineProps({
  placeholder: {
    type: String,
    default: "请输入",
  },
});
</script>

<template>
  <input :placeholder="placeholder" />
</template>
```

## 子传父：自定义事件

子组件：

```vue
<script setup>
const emit = defineEmits(["submit-user"]);

function submit() {
  emit("submit-user", {
    name: "张三",
    age: 18,
  });
}
</script>

<template>
  <button @click="submit">提交</button>
</template>
```

父组件：

```vue
<script setup>
import UserForm from "./UserForm.vue";

function handleUser(user) {
  console.log(user);
}
</script>

<template>
  <UserForm @submit-user="handleUser" />
</template>
```

- 子组件不直接修改父组件状态。
- 事件名称建议使用 kebab-case。
- 事件可以携带数据。
- Props 向下传，事件向上报，形成单向数据流。

## 双向绑定组件

使用 `defineModel()` 可以让组件支持 `v-model`：

```vue
<!-- CustomInput.vue -->
<script setup>
const model = defineModel({
  type: String,
  required: true,
});
</script>

<template>
  <input v-model="model" />
</template>
```

父组件：

```vue
<script setup>
import { ref } from "vue";
import CustomInput from "./CustomInput.vue";

const username = ref("");
</script>

<template>
  <CustomInput v-model="username" />
</template>
```

`defineModel()` 需要较新的 Vue 3 版本。旧项目可以继续使用 `modelValue` Prop 和 `update:modelValue` 事件。

## 跨层级通信：provide / inject

祖先组件提供数据：

```vue
<script setup>
import { provide, ref } from "vue";

const theme = ref("dark");

provide("theme", theme);
</script>
```

后代组件注入数据：

```vue
<script setup>
import { inject } from "vue";

const theme = inject("theme", "light");
</script>

<template>
  <p>当前主题：{{ theme }}</p>
</template>
```

`provide` / `inject` 适合主题、配置、语言等跨层级依赖，不适合滥用成全局变量。

## 状态提升

当两个兄弟组件需要共享数据时，可以把状态提升到共同父组件：

```text
Parent
├── ChildA（修改数据）
└── ChildB（显示数据）
```

父组件管理状态，ChildA 触发事件，父组件更新后通过 Props 传给 ChildB。如果状态涉及多个页面，再考虑 Pinia。

## 通信方式如何选择

- 父子组件：Props + Emits。
- 支持双向绑定：`v-model` / `defineModel()`。
- 祖孙组件：`provide` / `inject`。
- 兄弟组件：状态提升。
- 跨页面共享：Pinia。
- 复杂组件需要灵活扩展：插槽和作用域插槽。

## 常见错误

- 子组件直接用 Props 做本地修改。
- 事件命名过于泛化，如统一的 `change`。
- 所有状态都放进全局 Store。
- 组件层级过深却继续使用 Props 层层传递。
- Props 类型和默认值不明确。
