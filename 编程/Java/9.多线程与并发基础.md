# 多线程与并发基础

> [!info] 资料来源
> 基于语雀《JavaSE核心技术》的 [12.多线程](https://www.yuque.com/neuedu/campus/gc6p09wp3q23lc2o) 整理，并对线程安全与生命周期表述做了现代化补充。

## 1. 进程与线程

- **进程**：操作系统分配资源的基本单位。一个进程拥有独立的地址空间和系统资源。
- **线程**：进程内部的执行单元，同一进程中的线程共享内存、文件句柄等资源。
- **并发**：多个任务在重叠的时间段内推进，单核 CPU 也能通过快速切换实现。
- **并行**：多个任务在同一时刻真正同时执行，通常需要多核 CPU。

线程比进程更轻量，但共享资源会带来线程安全问题。

## 2. 创建线程的方式

### 2.1 继承 Thread

```java
public class NumberThread extends Thread {
    @Override
    public void run() {
        for (int i = 1; i <= 5; i++) {
            System.out.println(getName() + ": " + i);
        }
    }

    public static void main(String[] args) {
        NumberThread thread = new NumberThread();
        thread.start();
    }
}
```

`Thread` 类本身已经实现 `Runnable`，但继承 `Thread` 后无法再继承其他类，扩展性较差。

### 2.2 实现 Runnable

```java
public class PrintTask implements Runnable {
    @Override
    public void run() {
        for (int i = 1; i <= 5; i++) {
            System.out.println(Thread.currentThread().getName() + ": " + i);
        }
    }

    public static void main(String[] args) {
        PrintTask task = new PrintTask();
        new Thread(task, "线程-A").start();
        new Thread(task, "线程-B").start();
    }
}
```

推荐优先使用 `Runnable`：任务与线程分离，便于共享任务对象、组合线程池和继续继承其他类型。

### 2.3 实现 Callable

`Runnable.run()` 没有返回值，也不能直接抛出受检异常。`Callable.call()` 可以返回结果：

```java
import java.util.concurrent.Callable;
import java.util.concurrent.ExecutionException;
import java.util.concurrent.FutureTask;

public class CallableDemo {
    public static void main(String[] args)
            throws ExecutionException, InterruptedException {
        Callable<Integer> task = new Callable<Integer>() {
            @Override
            public Integer call() {
                int sum = 0;
                for (int i = 1; i <= 100; i++) {
                    sum += i;
                }
                return sum;
            }
        };

        FutureTask<Integer> futureTask = new FutureTask<Integer>(task);
        new Thread(futureTask).start();

        Integer result = futureTask.get();
        System.out.println(result);
    }
}
```

`futureTask.get()` 会阻塞，直到任务完成并返回结果。

## 3. start 与 run

```java
Thread thread = new Thread(task);
thread.start(); // 启动新线程，由 JVM 调度 run()
thread.run();   // 在当前线程中直接调用普通方法
```

> [!warning] 不要直接调用 `run()` 代替 `start()`
> 直接调用 `run()` 不会创建新线程，只是当前线程按顺序执行方法体。

同一个 `Thread` 对象不能重复调用 `start()`；线程结束后需要创建新线程或使用线程池。

## 4. 线程生命周期

Java 线程状态由 `Thread.State` 表示：

| 状态 | 含义 |
|---|---|
| `NEW` | 已创建但尚未调用 `start()` |
| `RUNNABLE` | 可运行；可能正在运行，也可能等待 CPU 调度 |
| `BLOCKED` | 等待获取监视器锁 |
| `WAITING` | 无限期等待 `notify()`、`join()` 等唤醒条件 |
| `TIMED_WAITING` | 带超时的等待，如 `sleep()`、`wait(timeout)` |
| `TERMINATED` | `run()` 已结束 |

## 5. 线程调度与常用方法

| 方法 | 作用 | 注意事项 |
|---|---|---|
| `setName()` / `getName()` | 设置、读取线程名 | 便于日志排查 |
| `isAlive()` | 是否处于存活状态 | 创建后未启动、结束后均为 `false` |
| `getPriority()` / `setPriority()` | 调度优先级 | 仅作提示，不能保证执行顺序 |
| `sleep(millis)` | 当前线程休眠指定毫秒 | 不会释放已持有的监视器锁 |
| `join()` | 调用方等待目标线程结束 | 常用于等待子线程结果 |
| `yield()` | 提示调度器让出 CPU | 不保证一定让出 |
| `interrupt()` | 设置中断标志或打断阻塞 | 不强制结束线程 |
| `isInterrupted()` | 查询中断状态 | 不清除标志 |
| `Thread.interrupted()` | 查询并清除中断状态 | 静态方法，作用于当前线程 |

### 5.1 sleep

```java
try {
    Thread.sleep(1000);
} catch (InterruptedException e) {
    Thread.currentThread().interrupt();
    return;
}
```

捕获 `InterruptedException` 后应恢复中断标志，让上层代码知道线程收到过中断，而不是简单忽略异常。

### 5.2 join

```java
Thread worker = new Thread(() -> {
    // 执行耗时任务
});
worker.start();
worker.join();
System.out.println("任务已完成");
```

`join()` 会让当前线程等待 `worker` 终止。

### 5.3 interrupt

```java
Thread worker = new Thread(() -> {
    while (!Thread.currentThread().isInterrupted()) {
        // 检查中断标志并执行任务
    }
});
worker.start();
worker.interrupt();
```

`interrupt()` 只是发出协作式中断信号；代码必须主动检查中断状态或在阻塞方法中处理 `InterruptedException`。

## 6. 线程运行的不确定性

线程何时获得 CPU、每条语句执行顺序如何交错，都由操作系统和 JVM 调度决定。即使代码按顺序编写，也不能假设线程执行顺序固定。

```java
for (int i = 0; i < 5; i++) {
    new Thread(() -> System.out.println(Thread.currentThread().getName())).start();
}
```

每次运行的输出顺序可能不同。需要顺序时，应使用同步、等待或并发工具，而不是依赖 `sleep()` 猜测时间。

## 7. 线程安全问题

多个线程同时读写共享可变状态，而操作之间缺少必要同步时，可能产生：

- 竞态条件：结果依赖线程执行交错顺序。
- 可见性问题：一个线程的修改未及时被其他线程观察到。
- 原子性问题：复合操作被其他线程打断。

典型错误：

```java
private int count;

public void increase() {
    count++; // 读取、加 1、写回，不是原子操作
}
```

多个线程同时调用时可能丢失更新。

## 8. synchronized

### 8.1 同步方法

```java
public class Counter {
    private int count;

    public synchronized void increase() {
        count++;
    }

    public synchronized int getCount() {
        return count;
    }
}
```

实例同步方法锁的是当前对象 `this`，不同实例之间不互相阻塞。

### 8.2 同步代码块

```java
private final Object lock = new Object();

public void increase() {
    synchronized (lock) {
        count++;
    }
}
```

- 同一时刻只有一个线程能持有同一把锁执行同步区域。
- 锁对象必须是多个线程共享的同一个对象。
- 同步代码范围应尽量小，但必须完整覆盖需要保持原子性的操作。
- 静态同步方法锁的是类的 `Class` 对象。

> [!warning] synchronized 不自动解决所有问题
> 它主要用于同一组锁下的互斥和可见性。错误地使用不同锁对象、过度加锁或锁内执行耗时操作，仍会造成并发问题或性能下降。

## 9. wait、notify 与生产者消费者

`wait()`、`notify()`、`notifyAll()` 是 `Object` 的方法，调用前线程必须持有对象锁：

```java
public synchronized void produce() throws InterruptedException {
    while (full) {
        wait();
    }
    // 生产数据
    full = true;
    notifyAll();
}

public synchronized void consume() throws InterruptedException {
    while (!full) {
        wait();
    }
    // 消费数据
    full = false;
    notifyAll();
}
```

关键点：

- 使用 `while` 而不是 `if` 判断条件，避免虚假唤醒。
- 唤醒后必须重新检查条件并再次竞争锁。
- `wait()` 会释放对象锁，`sleep()` 不会。
- 通常优先使用 `notifyAll()`；只有在能证明安全时才使用 `notify()`。
- 现代代码可用 `BlockingQueue` 替代手写 `wait/notify`，以降低错误风险。

## 10. 死锁

死锁是多个线程互相持有对方需要的锁并永久等待。

```java
Thread t1 = new Thread(() -> {
    synchronized (lockA) {
        synchronized (lockB) {
            // ...
        }
    }
});

Thread t2 = new Thread(() -> {
    synchronized (lockB) {
        synchronized (lockA) {
            // ...
        }
    }
});
```

形成死锁的四个条件：互斥、占有且等待、不可剥夺、循环等待。预防手段：

- 多个线程按固定顺序获取锁。
- 缩短锁持有时间。
- 尽量不嵌套获取多个锁。
- 使用带超时的锁或高级并发工具。

## 11. 守护线程

```java
Thread worker = new Thread(task);
worker.setDaemon(true);
worker.start();
```

守护线程用于提供后台服务。当所有非守护线程结束后，JVM 会退出，即使守护线程仍在运行。

`setDaemon()` 必须在 `start()` 之前调用。守护线程不保证执行完 `finally` 代码，因此不能用于必须完成的数据持久化任务。

## 12. volatile、原子类与线程池

> [!tip] 课件之外的常用补充

- `volatile` 保证变量读写的可见性和一定的有序性，但 `count++` 仍不是原子操作。
- `AtomicInteger` 等原子类适合简单计数场景，通过 CAS 提供原子更新。
- 实际项目优先使用 `ExecutorService` 线程池管理线程，避免频繁创建线程。
- 共享可变状态越少，线程安全设计越简单；优先考虑不可变对象、局部变量和任务隔离。

```java
import java.util.concurrent.atomic.AtomicInteger;

AtomicInteger count = new AtomicInteger();
count.incrementAndGet();
```

## 13. 易错清单

- [ ] 调用 `run()` 而不是 `start()`，导致没有创建新线程。
- [ ] 假设线程一定按创建顺序执行。
- [ ] 用 `sleep()` 解决线程同步问题。
- [ ] `count++` 没有加锁却假设它是原子操作。
- [ ] 捕获 `InterruptedException` 后静默忽略中断。
- [ ] 同步方法使用不同对象作为隐式锁，却期望互斥。
- [ ] `wait()` 使用 `if` 而没有在循环中重新检查条件。
- [ ] 嵌套获取多把锁且顺序不一致，导致死锁。
- [ ] 把必须完成的业务任务交给守护线程。
