# 集合、异常与常用 API

> [!info] 资料来源
> 基于语雀《JavaSE核心技术》的 [08.异常处理](https://www.yuque.com/neuedu/campus/pz8as58uq8wtvbz9)、[09.常见工具类-高级篇](https://www.yuque.com/neuedu/campus/naudgsyggqqm6mml)、[10.集合框架](https://www.yuque.com/neuedu/campus/nqkwklpu7a3iv3pg) 补充；泛型的完整解释见 [[6.反射与泛型]]。


## 1. 集合体系概览

```text
Iterable
└── Collection
    ├── List
    │   ├── ArrayList
    │   └── LinkedList
    ├── Set
    │   └── HashSet
    └── Queue
        └── Deque / LinkedList

Map
├── HashMap
└── Hashtable
```

区别：

- `Collection` 保存单个元素。
- `Map` 保存键值对。
- 集合只能保存引用类型；基本类型会通过自动装箱变成包装类。
- 泛型用于限制集合元素类型，减少强制转换和运行时错误。

## 2. ArrayList

`ArrayList` 底层基于可变数组，随机访问和遍历效率高，中间插入和删除效率较低。

```java
import java.util.ArrayList;
import java.util.List;

List<Integer> list = new ArrayList<>();
list.add(15);
list.add(10);
list.add(0, 20);
list.set(1, 100);
```

常用方法：

| 方法 | 作用 |
|---|---|
| `add(e)` | 添加到末尾 |
| `add(index, e)` | 插入到指定位置 |
| `get(index)` | 按索引获取元素 |
| `set(index, e)` | 替换指定位置元素 |
| `remove(index)` | 按下标删除 |
| `remove(Object)` | 按对象删除 |
| `size()` | 元素数量 |
| `isEmpty()` | 是否为空 |
| `contains(e)` | 是否包含某元素 |
| `indexOf(e)` | 第一次出现的索引 |
| `subList(from, to)` | 截取子列表，前闭后开 |
| `toArray()` | 转换为数组 |
| `clear()` | 清空 |

> [!warning] `remove(int)` 与 `remove(Object)` 容易混淆
> 对 `List<Integer>` 调用 `remove(1)` 是删除下标 1；要删除值为 1 的元素，使用 `remove(Integer.valueOf(1))`。

## 3. LinkedList

`LinkedList` 底层基于双向链表，头尾插入删除效率高，按索引随机访问较慢。

```java
LinkedList<String> list = new LinkedList<>();

list.addFirst("A");
list.addLast("B");
list.add("C");

String first = list.getFirst();
String last = list.getLast();

list.removeFirst();
list.removeLast();
```

常用特有方法：

| 方法 | 作用 |
|---|---|
| `addFirst(e)` / `addLast(e)` | 头尾添加 |
| `getFirst()` / `getLast()` | 获取头尾元素 |
| `peek()` / `peekFirst()` | 查看头部 |
| `poll()` | 删除并返回头部 |
| `removeFirst()` / `removeLast()` | 删除头尾 |
| `offerFirst(e)` / `offerLast(e)` | 头尾插入并返回是否成功 |
| `descendingIterator()` | 倒序迭代器 |

### ArrayList 与 LinkedList 对比

| 对比项 | ArrayList | LinkedList |
|---|---|---|
| 底层结构 | 动态数组 | 双向链表 |
| 随机访问 | 快 | 慢 |
| 尾部添加 | 通常快 | 快 |
| 中间插入删除 | 需要移动元素 | 需要先定位，再修改指针 |
| 内存开销 | 较低 | 每个节点额外保存指针 |

## 4. 集合排序

### 4.1 Comparable：对象自身定义默认排序

```java
public class Student implements Comparable<Student> {
    private int total;

    @Override
    public int compareTo(Student other) {
        return this.total - other.total;
    }
}
```

```java
Collections.sort(students);
```

`compareTo` 返回：

- 负数：当前对象排在前面。
- 0：两者排序位置相同。
- 正数：当前对象排在后面。

> [!warning] 不要用两个大整数直接相减
> `a - b` 可能发生整数溢出。实际项目中优先使用 `Integer.compare(a, b)`。

### 4.2 Comparator：外部传入排序规则

```java
students.sort((s1, s2) -> {
    if (s1.getTotal() != s2.getTotal()) {
        return Integer.compare(s2.getTotal(), s1.getTotal());
    }
    return Integer.compare(s2.getChinese(), s1.getChinese());
});
```

- `Comparable`：类自身的自然排序。
- `Comparator`：为某次排序临时指定规则，更灵活。

## 5. HashSet

```java
HashSet<String> set = new HashSet<>();

set.add("A");
set.add("B");
set.add("A");
set.add(null);

System.out.println(set);
```

特点：

- 不允许重复元素。
- 不保证插入顺序。
- 允许一个 `null` 元素。
- 底层基于 `HashMap`。
- 非线程安全。

判断重复依赖于元素的 `equals` 和 `hashCode`。自定义对象放入 `HashSet` 时，应同时正确重写这两个方法。

## 6. Map

`Map` 保存键值对：

```java
Map<String, String> map = new HashMap<>();

map.put("a", "张三");
map.put("b", "李四");
map.put("a", "王五");

System.out.println(map.get("a")); // 王五
```

相同键再次 `put` 会覆盖旧值。

常用方法：

| 方法 | 作用 |
|---|---|
| `put(k, v)` | 添加或覆盖 |
| `get(k)` | 按键取值 |
| `getOrDefault(k, default)` | 按键取值，不存在时返回默认值 |
| `containsKey(k)` | 是否包含键 |
| `containsValue(v)` | 是否包含值 |
| `remove(k)` | 按键删除 |
| `keySet()` | 所有键的集合 |
| `values()` | 所有值的集合 |
| `entrySet()` | 所有键值对 |
| `size()` | 键值对数量 |
| `clear()` | 清空 |

遍历：

```java
for (Map.Entry<String, String> entry : map.entrySet()) {
    System.out.println(entry.getKey() + "=" + entry.getValue());
}

map.forEach((key, value) -> System.out.println(key + "=" + value));
```

### 6.1 HashMap 与 Hashtable

| 对比项 | HashMap | Hashtable |
|---|---|---|
| 线程安全 | 否 | 是，方法同步 |
| `null` 键 | 允许一个 | 不允许 |
| `null` 值 | 允许多个 | 不允许 |
| 性能 | 通常更高 | 同步有开销 |
| 现代替代 | `ConcurrentHashMap` | `ConcurrentHashMap` |

### 6.2 HashMap 与 HashSet 的关系

`HashSet` 可以理解为只保存 `HashMap` 的键，值使用统一的占位对象。

## 7. Iterator 迭代器

```java
Iterator<String> iterator = set.iterator();

while (iterator.hasNext()) {
    String value = iterator.next();
    System.out.println(value);
}
```

- `hasNext()`：是否还有元素。
- `next()`：返回下一个元素并移动游标。
- `remove()`：删除刚返回的元素。

> [!warning] 遍历集合时不能随意直接调用集合的 `remove`
> 在迭代过程中修改集合可能抛出 `ConcurrentModificationException`。需要删除元素时使用 `iterator.remove()`。

## 8. Object 常用方法

所有类最终都继承 `Object`。

| 方法 | 作用 |
|---|---|
| `toString()` | 返回对象字符串表示 |
| `equals(Object)` | 判断对象是否相等 |
| `hashCode()` | 返回哈希值 |
| `getClass()` | 获取运行时类对象 |
| `clone()` | 复制对象 |
| `wait()` / `notify()` / `notifyAll()` | 线程等待与唤醒 |
| `finalize()` | 旧式终结方法，已不推荐使用 |

### 8.1 重写 equals 与 hashCode 的约定

如果两个对象通过 `equals` 判断相等，那么它们的 `hashCode` 必须相同。

```java
@Override
public boolean equals(Object o) {
    if (this == o) return true;
    if (o == null || getClass() != o.getClass()) return false;
    Student student = (Student) o;
    return id == student.id;
}

@Override
public int hashCode() {
    return Integer.hashCode(id);
}
```

## 9. 异常体系

```text
Throwable
├── Error
└── Exception
    ├── RuntimeException(可以不用处理)
    │   ├── NullPointerException
    │   ├── ArithmeticException
    │   ├── ArrayIndexOutOfBoundsException
    │   └── ClassCastException
    └── 其他受检异常
        ├── IOException
        ├── SQLException
        └── ClassNotFoundException
```

### 9.1 受检异常与运行时异常

| 类型 | 是否必须处理 | 典型例子 |
|---|---|---|
| 受检异常 | 必须捕获或声明抛出 | `IOException`、`SQLException` |
| 运行时异常 | 不强制，但应按逻辑避免 | `NullPointerException`、`ClassCastException` |
| Error | 通常不处理 | `OutOfMemoryError` |

## 10. 异常处理
处理异常时，先处理子类的异常，后处理父类的异常
比如IndexOutOfBoundsException和ArrayIndexOutOfBoundsException 处理时，先处理
ArrayIndexOutOfBoundsException
### 10.1 try-catch-finally

```java
try {
    int result = 10 / 0;
} catch (ArithmeticException e) {
    System.out.println("除数不能为 0：" + e.getMessage());
} finally {
    System.out.println("无论是否异常都会执行");
}
```

规则：

- 异常按顺序匹配 `catch`。如果前面有异常，后面异常不显示
- 父类异常必须放在子类异常后面，否则子类 catch 永远不可达。
- `finally` 通常用于释放资源。

### 10.2 throw 与 throws

```java
public static void validateAge(int age) {
    if (age < 0) {
        throw new IllegalArgumentException("年龄不能为负数");
    }
}

public static void readFile() throws IOException {
    // 方法内部可能抛出受检异常，交由调用方处理
}
```

- `throw`：在方法体内抛出一个异常对象。
- `throws`：在方法签名上声明可能抛出的异常类型。

### 10.3 自定义异常

```java
public class BalanceNotEnoughException extends RuntimeException {
    public BalanceNotEnoughException(String message) {
        super(message);
    }
}
```

- 业务逻辑错误通常继承 `RuntimeException`。
- 调用方必须处理的异常可以继承 `Exception`。

### 10.4 try-with-resources

```java
try (BufferedReader reader =
         new BufferedReader(new FileReader("data.txt"))) {
    String line;
    while ((line = reader.readLine()) != null) {
        System.out.println(line);
    }
} catch (IOException e) {
    e.printStackTrace();
}
```

只要资源实现了 `AutoCloseable`，离开 `try` 后就会自动关闭。多个资源用分号分隔，关闭顺序与创建顺序相反。

## 11. 异常处理原则

- 不要用异常控制正常业务流程。
- 不要捕获异常后什么都不做。
- 捕获后要么能恢复，要么补充上下文并继续抛出。
- 记录日志时不要重复打印同一个异常。
- 资源必须关闭，优先使用 try-with-resources。
- 在方法边界上统一处理异常，避免每个小方法都盲目捕获。

## 13. 集合层次与 ListIterator

![Java 集合框架体系](collection-hierarchy.png)

> 图源：语雀《JavaSE核心技术·10.集合框架》1.1.2。

`Collection` 的通用方法包括 `add()`、`remove()`、`contains()`、`size()`、`isEmpty()`、`clear()` 和 `iterator()`。

`ListIterator` 支持双向遍历和修改：

```java
List<String> list = new ArrayList<>(Arrays.asList("A", "B", "C"));
ListIterator<String> iterator = list.listIterator(list.size());

while (iterator.hasPrevious()) {
    System.out.println(iterator.previous());
}
```

迭代过程中不能直接调用集合的 `add()` 或 `remove()` 修改结构，否则可能抛出 `ConcurrentModificationException`；应使用迭代器自己的修改方法。

## 14. TreeSet

`TreeSet` 按元素的自然顺序排序，元素必须实现 `Comparable`，或创建时提供 `Comparator`。

```java
Set<Integer> numbers = new TreeSet<>();
numbers.add(5);
numbers.add(1);
numbers.add(3);
System.out.println(numbers); // [1, 3, 5]
```

常用操作：

```java
TreeSet<Integer> values = new TreeSet<>(Arrays.asList(10, 20, 30, 40));

values.first();
values.last();
values.floor(25);  // 小于等于 25 的最大元素：20
values.ceiling(25); // 大于等于 25 的最小元素：30
values.headSet(30); // [10, 20]
values.tailSet(30); // [30, 40]
```

`TreeSet` 判断重复依赖比较结果，不是单纯依赖 `equals()`；比较规则必须与业务含义一致。

## 15. TreeMap 与集合选择

`TreeMap` 按键排序，适合需要范围查询或按顺序遍历键的场景。

```java
TreeMap<String, Integer> scores = new TreeMap<>();
scores.put("Tom", 90);
scores.put("Alice", 95);
scores.put("Bob", 88);

System.out.println(scores.firstKey());
System.out.println(scores.headMap("Bob")); // Alice
```

| 需求 | 优先选择 |
|---|---|
| 按索引访问、遍历多 | `ArrayList` |
| 频繁头尾插入删除 | `LinkedList` |
| 不重复、不要求顺序 | `HashSet` |
| 不重复、需要排序 | `TreeSet` |
| 键值映射、不要求顺序 | `HashMap` |
| 键值映射、按键排序 | `TreeMap` |
| 需要线程安全 | 优先考虑 `ConcurrentHashMap`，而不是旧 `Hashtable` |

`Hashtable` 不允许 `null` 键或 `null` 值，方法大多同步，但性能和扩展性通常不如现代并发容器。`HashMap` 允许一个 `null` 键和多个 `null` 值。

## 16. 异常继承与调用栈

![异常继承树](exception-hierarchy.png)

> 图源：语雀《JavaSE核心技术·08.异常处理》8.2.1。

`Throwable` 分为：

- `Error`：JVM 或系统级严重问题，如 `OutOfMemoryError`、`StackOverflowError`，通常不应捕获后继续运行。
- `Exception`：程序可处理的异常。
- `RuntimeException`：非检查异常，如空指针、数组越界、类型转换错误。
- 其他 `Exception`：检查异常，如 `IOException`、`SQLException`，必须处理或声明抛出。

异常会沿方法调用栈向上传播，直到被某个 `catch` 捕获；如果没有捕获，当前线程终止并由 JVM 打印堆栈信息。

```java
public static void a() {
    b();
}

public static void b() {
    throw new IllegalArgumentException("参数错误");
}
```

异常栈信息中的每一行代表一个调用帧，应从最下方的触发位置向上分析。

## 17. 包装类与自动装箱

每个基本类型都有包装类：

| 基本类型 | 包装类 |
|---|---|
| `byte` | `Byte` |
| `short` | `Short` |
| `int` | `Integer` |
| `long` | `Long` |
| `float` | `Float` |
| `double` | `Double` |
| `char` | `Character` |
| `boolean` | `Boolean` |

```java
Integer number = 100; // 自动装箱
int value = number;  // 自动拆箱
```

> [!warning] 包装类比较与空值
> `==` 对包装类通常比较引用；值比较应使用 `equals()` 或先转换成基本类型。包装类还可能是 `null`，自动拆箱时可能抛出 `NullPointerException`。

现代代码应使用 `Integer.valueOf()`、`Double.valueOf()` 或自动装箱，不推荐 `new Integer(...)` 等构造器。

字符串与基本类型转换：

```java
int value = Integer.parseInt("123");
String text = String.valueOf(value);
Integer boxed = Integer.valueOf("123");
```

## 18. Date、Calendar 与格式化

旧日期 API 中：

```java
Date now = new Date();
long millis = now.getTime();

SimpleDateFormat formatter =
        new SimpleDateFormat("yyyy-MM-dd HH:mm:ss");
String text = formatter.format(now);
```

`Calendar` 可进行字段运算：

```java
Calendar calendar = Calendar.getInstance();
calendar.add(Calendar.DAY_OF_MONTH, 7);
Date nextWeek = calendar.getTime();
```

`SimpleDateFormat` 和 `Calendar` 不是线程安全的。多线程环境可每次创建局部对象，或直接使用 Java 8 的 `java.time`：

```java
LocalDateTime now = LocalDateTime.now();
DateTimeFormatter formatter =
        DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss");
String text = now.format(formatter);
```

完整的 `java.time` 用法见 [[10.Java 8 新特性]]。

## 19. 数字格式化与 Scanner

`DecimalFormat` 适合固定格式的数字输出：

```java
DecimalFormat format = new DecimalFormat("0.00");
System.out.println(format.format(12.345)); // 12.35，按默认舍入规则
```

`NumberFormat` 适合货币、百分数等本地化格式：

```java
NumberFormat currency = NumberFormat.getCurrencyInstance(Locale.CHINA);
System.out.println(currency.format(1234.5));
```

`Scanner` 可以读取键盘或字符串：

```java
Scanner scanner = new Scanner(System.in);
int age = scanner.nextInt();
String name = scanner.next();
```

混用 `nextInt()` 和 `nextLine()` 时要注意换行符：`nextInt()` 只读取整数，不会消费行尾换行，随后 `nextLine()` 可能读到空字符串。可以额外调用一次 `nextLine()` 清理输入。
## 12. 易错清单

- [ ] `ArrayList` 不能直接使用基本类型泛型，必须写包装类。
- [ ] `List.remove(int)` 与 `List.remove(Object)` 语义不同。
- [ ] `HashMap` 的键必须正确实现 `equals` 和 `hashCode`。
- [ ] `HashSet` 不保证顺序，不能把它当有序集合使用。
- [ ] 迭代过程中直接删除集合元素可能触发并发修改异常。
- [ ] `finally` 中提前 `return` 可能吞掉异常或覆盖返回值。
- [ ] 多 catch 时父类异常不能写在子类异常前面。
- [ ] 受检异常必须处理或继续声明抛出。
