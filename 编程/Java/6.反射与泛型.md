# 反射与泛型

> [!info] 资料来源
> 泛型部分基于语雀《JavaSE核心技术》的 [10.集合框架](https://www.yuque.com/neuedu/campus/nqkwklpu7a3iv3pg) 补充；反射部分保留原有整理并用于 ORM 示例。


## 1. 反射是什么

正常情况下，代码在编译阶段就知道要创建哪个类、调用哪个方法。

反射允许程序在**运行时**检查类、构造器、字段和方法，并动态创建对象、访问成员、调用方法。

典型用途：

- 框架解析配置并创建对象。
- 根据数据库结果动态映射到 Java 对象。
- 动态调用方法。
- 读取注解和泛型信息。
- 编写通用工具或简易 ORM。

反射的代价：

- 代码可读性下降。
- 编译期类型检查减少。
- 性能通常低于直接调用。
- 可访问性和安全性需要谨慎控制。

## 2. Class 对象

每个已加载的类，在 JVM 中都有一个对应的 `Class` 对象，描述该类的结构信息。

### 2.1 获取 Class 对象的三种方式

```java
Class<?> clazz1 = Class.forName("com.example.Student");

Student student = new Student();
Class<?> clazz2 = student.getClass();

Class<?> clazz3 = Student.class;
```

| 方式 | 特点 |
|---|---|
| `Class.forName(...)` | 根据全限定类名加载，配置化场景常用 |
| `对象.getClass()` | 已有一个对象时使用 |
| `类名.class` | 编译期明确知道类时使用，最安全直接 |

比较：

```java
System.out.println(clazz1 == clazz2); // 同一个类只有一个 Class 对象
```

## 3. 反射核心 API

| 类型 | 表示 |
|---|---|
| `Class<?>` | 类或接口 |
| `Constructor<?>` | 构造器 |
| `Field` | 成员变量 |
| `Method` | 方法 |
| `Parameter` | 方法参数 |
| `Modifier` | 修饰符 |

### 3.1 查看基本信息

```java
Class<?> clazz = Student.class;

System.out.println(clazz.getName());
System.out.println(clazz.getSimpleName());
System.out.println(clazz.getPackage().getName());

Class<?> superClass = clazz.getSuperclass();
Class<?>[] interfaces = clazz.getInterfaces();
```

## 4. 构造器

```java
Constructor<?>[] constructors = clazz.getConstructors();
Constructor<?> constructor = clazz.getDeclaredConstructor(String.class);

Object object = constructor.newInstance("张三");
```

- `getConstructors()` 只返回公开构造器。
- `getDeclaredConstructors()` 返回本类声明的全部构造器。
- `getConstructor(...)` 获取公开构造器。
- `getDeclaredConstructor(...)` 获取本类指定参数构造器。

> [!warning] 旧代码中的 `newInstance()`
> `Class.newInstance()` 已不推荐使用，无法正确传递构造器异常，也不能选择带参数的构造器。现代写法：
> ```java
> clazz.getDeclaredConstructor().newInstance();
> ```

## 5. 字段

```java
Field field = clazz.getDeclaredField("name");
field.setAccessible(true);

Object value = field.get(object);
field.set(object, "李四");
```

常用方法：

| 方法 | 作用 |
|---|---|
| `getFields()` | 获取公开字段，包括继承的 |
| `getDeclaredFields()` | 获取本类声明的全部字段 |
| `getField(name)` | 按名称获取公开字段 |
| `getDeclaredField(name)` | 按名称获取本类字段 |
| `get(object)` | 读取字段值 |
| `set(object, value)` | 设置字段值 |
| `getType()` | 获取字段类型 |

`setAccessible(true)` 可以绕过 Java 访问控制检查，但不能把它当作常规写法。模块系统可能限制访问，实际项目应优先提供合法 API。

## 6. 方法

```java
Method method = clazz.getDeclaredMethod("study", String.class);
method.setAccessible(true);

Object result = method.invoke(object, "Java");
```

常用方法：

| 方法 | 作用 |
|---|---|
| `getMethods()` | 获取公开方法，包括继承的 |
| `getDeclaredMethods()` | 获取本类声明的全部方法 |
| `getMethod(name, paramTypes...)` | 获取公开方法 |
| `getDeclaredMethod(name, paramTypes...)` | 获取本类方法 |
| `invoke(object, args...)` | 调用方法 |
| `getReturnType()` | 获取返回类型 |
| `getParameterTypes()` | 获取参数类型 |

`invoke` 包装了目标方法抛出的异常，通常会以 `InvocationTargetException` 对外体现，需要查看 `getCause()`。

## 7. 修饰符

```java
int modifiers = clazz.getModifiers();

System.out.println(Modifier.isPublic(modifiers));
System.out.println(Modifier.isFinal(modifiers));
System.out.println(Modifier.toString(modifiers));
```

## 8. 参数

```java
Method method = clazz.getMethod("setName", String.class);
Parameter[] parameters = method.getParameters();

for (Parameter parameter : parameters) {
    System.out.println(parameter.getName());
    System.out.println(parameter.getType());
}
```

参数名在编译时可能丢失，除非使用 `-parameters` 编译或保留调试信息。因此不能盲目依赖 `parameter.getName()` 返回源码中的名字。

## 9. 反射与简易 ORM

ORM 的基本目标：

```text
数据库表记录 -> Java 对象
Java 对象    -> 数据库表记录
```

简化流程：

1. 执行 SQL 得到 `ResultSet`。
2. 读取列名。
3. 将列名映射为 Java 属性名。
4. 找到 `setXxx` 方法。
5. 将数据库值转换为属性类型。
6. 通过反射调用 setter。
7. 将对象加入集合。

注意事项：

- 列名与属性名需要统一映射规则。
- 数据库 `null` 写入基本类型属性时会报错，需要默认值或使用包装类型。
- 类型转换必须准确。
- 反射调用要处理异常和性能开销。
- 实际框架会使用缓存、注解、TypeHandler 等机制增强 ORM。

## 10. 泛型基础

泛型的本质是“参数化类型”：

```java
List<String> names = new ArrayList<>();
names.add("Tom");
// names.add(100); // 编译错误
```

好处：

- 编译期检查元素类型。
- 从集合获取元素时不需要强制转换。
- 提高代码复用性。
- 使类型约束更明确。

常见类型参数名：

| 名称 | 常见含义 |
|---|---|
| `T` | Type |
| `E` | Element |
| `K` | Key |
| `V` | Value |
| `R` | Result |
| `U`、`S` | 第二、第三个类型参数 |

## 11. 泛型类

```java
public class Box<T> {
    private T value;

    public Box(T value) {
        this.value = value;
    }

    public T getValue() {
        return value;
    }

    public void setValue(T value) {
        this.value = value;
    }
}
```

使用：

```java
Box<String> stringBox = new Box<>("Hello");
Box<Integer> integerBox = new Box<>(100);

String text = stringBox.getValue();
Integer number = integerBox.getValue();
```

泛型类型参数只能是引用类型，不能直接写基本类型：

```java
// Box<int> box = new Box<>(1); // 错误
Box<Integer> box = new Box<>(1); // 正确
```

## 12. 泛型方法

```java
public static <T> T identity(T value) {
    return value;
}
```

类型参数声明 `<T>` 要放在修饰符和返回值类型之间。

```java
String result1 = identity("Java");
Integer result2 = identity(100);
```

泛型方法与泛型类的区别：

- 泛型类在创建对象时确定类型。
- 泛型方法在调用方法时确定类型。
- 泛型类中使用了 `T` 的成员方法，不一定是泛型方法。

## 13. 泛型接口

```java
public interface Generator<T> {
    T next();
}
```

实现时可以确定具体类型：

```java
public class StringGenerator implements Generator<String> {
    @Override
    public String next() {
        return "Java";
    }
}
```

也可以继续保留泛型：

```java
public class DefaultGenerator<T> implements Generator<T> {
    private T value;

    public DefaultGenerator(T value) {
        this.value = value;
    }

    @Override
    public T next() {
        return value;
    }
}
```

## 14. 泛型上界

```java
public <T extends Number> double half(T number) {
    return number.doubleValue() / 2;
}
```

`T extends Number` 表示类型参数必须是 `Number` 或其子类。调用后可以安全调用 `Number` 的方法。

多个上界：

```java
<T extends A & B & C>
```

如果有类，必须写在最前面。

## 15. 通配符

### 15.1 `? extends`

```java
public static double sum(List<? extends Number> list) {
    double total = 0;
    for (Number number : list) {
        total += number.doubleValue();
    }
    return total;
}
```

表示元素类型是 `Number` 或其子类，适合**读取**。

```java
List<Integer> integers = Arrays.asList(1, 2, 3);
sum(integers);
```

### 15.2 `? super`

```java
public static void addIntegers(List<? super Integer> list) {
    list.add(1);
    list.add(2);
}
```

表示列表元素类型是 `Integer` 或其父类，适合**写入**。

### 15.3 PECS 原则

```text
Producer Extends, Consumer Super
```

- 只从集合读取数据：使用 `? extends T`。
- 只向集合写入数据：使用 `? super T`。
- 既读又写：通常使用明确的 `List<T>`。

## 16. 泛型限制

- 不能使用基本类型作为类型参数，使用包装类。
- 不能创建参数化类型数组：

```java
// List<String>[] lists = new List<String>[10]; // 错误
```

- 不能对参数化类型直接使用 `instanceof`：

```java
// if (object instanceof Box<String>) { } // 错误
if (object instanceof Box<?>) { }          // 通常可写
```

- 不能创建类型参数对象：

```java
// T object = new T(); // 错误
```

- 静态成员不能直接使用类的类型参数：

```java
class Box<T> {
    // private static T value; // 错误
}
```

- 泛型信息会在编译后进行类型擦除，运行时通常看不到具体的 `String` 或 `Integer`。

## 17. 课件示例勘误

课件泛型下界示例中出现：

```java
List<Bird> birds = new ArrayList<>();
method07(birds);
```

如果方法签名是：

```java
void method07(List<? super Teacher> list)
```

`List<Bird>` 不能传入，因为 `Bird` 不是 `Teacher` 的父类型。`List<Teacher>`、`List<Person>`、`List<Object>` 才可以。

> [!important] 反射和泛型的关系
> 泛型主要提供编译期类型安全，反射主要处理运行时类型信息。需要绕过泛型擦除读取具体类型时，通常要借助字段、方法参数的 `Type`、`ParameterizedType` 等信息。

## 19. 泛型的不可变性与集合协变限制

即使 `Integer` 是 `Number` 的子类，`List<Integer>` 也不是 `List<Number>` 的子类型：

```java
List<Integer> integers = new ArrayList<Integer>();
// List<Number> numbers = integers; // 编译错误
```

原因是如果允许这样赋值，就可以通过 `List<Number>` 往列表中放入 `Double`，破坏原始 `List<Integer>` 的类型约束。

只读时可以使用上界通配符：

```java
public static double sum(List<? extends Number> numbers) {
    double total = 0;
    for (Number number : numbers) {
        total += number.doubleValue();
    }
    return total;
}
```

只写时可以使用下界通配符：

```java
public static void addNumbers(List<? super Integer> numbers) {
    numbers.add(1);
    numbers.add(2);
}
```

集合声明应尽量具体，避免滥用 `List<Object>`，否则会失去编译期类型检查。

## 20. 类型擦除与桥接方法

泛型主要在编译期提供类型检查，编译后类型参数通常会被擦除为上界。例如：

```java
List<String> strings = new ArrayList<String>();
List<Integer> integers = new ArrayList<Integer>();

System.out.println(strings.getClass() == integers.getClass()); // true
```

运行时通常无法直接判断一个对象是 `List<String>` 还是 `List<Integer>`。因此：

- 不能使用 `new T()`。
- 不能创建 `new T[10]`。
- 不能写 `obj instanceof List<String>`。
- 可以写 `obj instanceof List<?>`。
- 需要保留泛型信息时，应通过字段、方法参数、方法返回值的 `Type` 或 `ParameterizedType` 获取。

桥接方法是编译器为泛型继承生成的一种合成方法，用来保证泛型类型擦除后的多态调用仍然成立。日常编码中不需要手动声明桥接方法，但分析泛型重写和反射结果时可能遇到它。
## 18. 易错清单

- [ ] `Class.forName` 的参数必须是全限定类名。
- [ ] `getDeclaredXxx` 只包含本类声明成员，`getXxx` 通常包含继承的公开成员。
- [ ] 调用私有成员前要评估是否真的需要 `setAccessible(true)`。
- [ ] `invoke` 抛出 `InvocationTargetException` 时，要查看真实原因。
- [ ] 泛型不能替代运行时校验，集合仍可能混入非法数据。
- [ ] 使用反射解析泛型时，要注意类型擦除。
