# 模型可解释性与SHAP

金融、医疗场景里，“模型说不行”本身不够，必须说清楚为什么。SHAP 把一次预测精确拆成每个特征的贡献，是当前最常用的解释方法。

## 1. 为什么必须可解释

- **法律要求**：自动化决策对个人产生重大影响时，用户有权知道理由。《个人信息保护法》等法规把“解释”变成硬约束。
- **业务需要**：拒贷、拒保要给出具体原因和改善建议，否则引发投诉和诉讼。
- **算法审计**：只输出分数的黑盒无法通过合规审计。课上举的例子：某机构因信用卡额度存在性别差异又无法解释，被监管处罚并要求整改。
- **模型排查**：全局解释能发现某个渠道、某类人群整体风险异常。

### 1.1 两个层次

| 层次 | 回答的问题 | 典型图 |
|---|---|---|
| 全局解释 | 模型整体关注哪些特征 | 蜂群图、全局条形图 |
| 局部解释 | 这一个样本为什么得到这个结果 | 瀑布图、力图 |

两者互补：全局图不能回答“我为什么被拒”，局部图不能说明模型整体是否合理。

## 2. SHAP 之前的方法

| 方法 | 原理 | 缺陷 |
|---|---|---|
| 特征重要性（Gain） | 统计分裂带来的增益 | 不同模型不可比；模型升级后排序可能反直觉 |
| 排列重要性 | 打乱某特征，看性能下降多少 | 慢；特征强相关时会被替代，重要性被低估 |
| LIME | 在样本附近扰动，用线性模型局部拟合 | 结果不稳定，依赖随机种子和邻居参数 |

SHAP 的优势：有数学公理保证、可精确分解、跨模型可比。

## 3. Shapley 值：公平地分钱

1953 年 Shapley 研究“合作收益怎么分才公平”，提出四条标准：

1. **加和性**：分给每个人的份额加起来等于总收益；
2. **对称性**：贡献相同的人分得一样多；
3. **虚拟性**：没有贡献的人分 0；
4. **可加性**：两个项目合并，每人所得等于两项目分别所得之和。

满足这四条的分法**存在且唯一**，就是 Shapley 值。计算方法：枚举每个人加入团队的所有顺序，把他每次加入带来的边际贡献取平均。

三人例子（A、B、C 单干 20/30/40 万，合作总收益 100 万）：A 的 Shapley 值 = (20+20+30+20+30+20)/6 = 23.33 万，B = 33.33 万，C = 43.33 万，合计 100 万。

### 3.1 映射到机器学习

| 博弈论 | 模型解释 |
|---|---|
| 参与者 | 特征 |
| 总收益 | 该样本的预测值 |
| 分钱方案 | 每个特征的 SHAP 值 |

核心性质：

$$
\text{预测值} = \text{基线} + \sum_{j=1}^{M}\phi_j
$$

**精确相等，没有残差**。基线 `expected_value` 是训练集预测的平均值。

> [!note] 二分类的基线是 log-odds
> `expected_value` 不是概率。要换算：
> ```python
> p = 1 / (1 + np.exp(-expected_value))
> ```
> 给业务方看时必须换成概率或评分。

### 3.2 TreeSHAP

枚举所有特征顺序是 $M!$，30 个特征就是天文数字。对树模型，TreeSHAP 利用树结构把复杂度降到多项式级，几毫秒一个样本。

因此 **XGBoost + SHAP** 成为风控的常用组合：XGBoost 负责性能，TreeSHAP 负责可解释且算得动。神经网络只能用 DeepSHAP/KernelSHAP，慢得多。

## 4. 三步 API

```python
import shap

# 1. 创建解释器（树模型专用）
explainer = shap.TreeExplainer(model)

# 2. 算 SHAP 值（采样 1000~5000 足够稳定）
X_sample = X_test.sample(n=2000, random_state=42)
shap_values = explainer.shap_values(X_sample)

# 3. 画图
shap.summary_plot(shap_values, X_sample, max_display=10)
```

不同模型对应不同解释器：

| 模型 | Explainer |
|---|---|
| XGBoost / LightGBM / 随机森林 | `TreeExplainer` |
| 线性模型 | `LinearExplainer` |
| 神经网络 | `DeepExplainer` / `GradientExplainer` |
| 任意黑盒 | `KernelExplainer`（最慢） |

## 5. 五张图

### 5.1 蜂群图（最重要）

```python
shap.summary_plot(shap_values, X_sample, max_display=10)
```

| 视觉元素 | 含义 |
|---|---|
| Y 轴排序 | 特征重要性，最上面最重要 |
| 每个点 | 一个样本在该特征上的 SHAP 值 |
| X 轴位置 | 正=推高预测，负=压低 |
| 颜色 | 红=特征值高，蓝=特征值低 |

一张图同时回答“哪些特征重要、怎么影响、数据分布如何”。

信用卡欺诈课堂解读：

- **V14**：红点（值高）在左侧，说明 V14 越大越像正常交易；
- **V4**：红点（值高）在右侧，说明 V4 越大越像欺诈；
- **Hour**：红蓝混杂、紧贴零线，时间和欺诈关系不大。

### 5.2 全局条形图

```python
shap.summary_plot(shap_values, X_sample, plot_type="bar", max_display=10)
```

每条长度是该特征 $|\text{SHAP}|$ 的平均值，没有方向信息。适合汇报，比内置 `feature_importances_` 更可靠。

### 5.3 瀑布图（单样本解释）

```python
shap.plots.waterfall(shap_exp[0], max_display=10)
```

从基线出发，逐条加上各特征的正负贡献，最后落到该样本的预测值。最适合给客户/合规看：哪个因素推高、哪个压低、各占多少，一目了然。

### 5.4 力图

交互式版本，原理同瀑布图，适合网页展示。

### 5.5 依赖图

横轴是某特征的取值，纵轴是 SHAP 值，颜色是另一个特征。用来发现非线性、阈值效应和特征交互。

| 图 | 用途 |
|---|---|
| 蜂群图 | 全局总览，首选 |
| 条形图 | 汇报，简洁 |
| 瀑布图 | 单个客户解释 |
| 力图 | 交互演示 |
| 依赖图 | 排查特征交互 |

## 6. 进阶用法

### 6.1 检测模型偏见

按敏感群体（性别、地区）分组，比较同一特征上的 SHAP 分布。如果某群体在该特征上的 SHAP 系统性偏高，说明模型可能利用了敏感信息。修正手段：重采样/加权、后处理调整阈值。

### 6.2 找异常预测

两个样本预测概率相同，但一个由单一特征主导、另一个由多个特征均衡贡献——前者更可能是异常决策，值得人工复核。

## 7. 工程实践

- **采样**：全量算太慢。随机采样 1000–5000 条；线上监控可对高风险和边界概率（0.4–0.6）样本重点采样。
- **生成解释报告**：前几大特征的数值、参照值、可行动建议（反事实），用模板交给大模型生成自然语言。
- **审计报告**：模型版本、全局条形图、瀑布图、相似历史样本处理建议，缺图会被退回。

### 7.1 常见坑

| 坑 | 后果 | 处理 |
|---|---|---|
| 把 log-odds 当概率讲 | 解释错误、误导客户 | 用 sigmoid 转概率 |
| 列顺序与训练不一致 | SHAP 值错误且**不报错** | 保存 `feature_names`，推理前对齐 |
| 对神经网络用 TreeExplainer | 直接报错 | 换 DeepExplainer |
| 多分类形状搞错 | 图画错 | 二分类 `(N,M)`，多分类 `(N,M,K)`，选类别 |
| 给客户念“V14”“PCA” | 听不懂，等于没解释 | 用业务语言，给建议 |
