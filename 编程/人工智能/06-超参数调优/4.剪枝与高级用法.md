# 剪枝与Optuna高级用法

调参有两类浪费：没希望的 trial 跑完了才被淘汰；程序中断后从头再来。剪枝解决前者，持久化和并行解决后者。再往上是动态搜索空间和多目标优化。

## 1. 剪枝：让没希望的 trial 早点死

观察训练曲线会发现：前 50 棵树的 RMSE 已经能大致预测最终水平。一直在中位数以下的 trial，继续训大概率也追不上。

剪枝就是在训练中途定期报告分数，发现明显落后就终止。

### 1.1 MedianPruner

每个 trial 在某一步报告分数，和**历史 trial 在同一步的中位数**比较，比中位数差就砍掉。

```python
study = optuna.create_study(
    direction="minimize",
    pruner=optuna.pruners.MedianPruner(
        n_startup_trials=5,    # 前 5 个 trial 不剪，建立基线
        n_warmup_steps=30,     # 每个 trial 至少跑 30 步才考虑剪
    ),
)
```

两个参数必须设，否则会误杀：

| 参数 | 作用 | 推荐 |
|---|---|---|
| `n_startup_trials` | 前 N 次不剪，先积累参照 | 5–10 |
| `n_warmup_steps` | 开局抖动期不剪 | 20–50 |

### 1.2 接上 XGBoost 原生接口

`XGBClassifier` 的 sklearn 封装不方便逐步报告，剪枝要用原生 `xgb.train` 加回调：

```python
from optuna_integration import XGBoostPruningCallback
import xgboost as xgb

def objective(trial):
    params = {
        "max_depth":     trial.suggest_int("max_depth", 3, 10),
        "learning_rate": trial.suggest_float("learning_rate", 0.01, 0.3, log=True),
        "objective":     "reg:squarederror",
        "eval_metric":   "rmse",
    }

    cv = KFold(n_splits=5, shuffle=True, random_state=42)
    rmses = []

    for fold_idx, (tr, va) in enumerate(cv.split(X)):
        dtrain = xgb.DMatrix(X.iloc[tr], label=y.iloc[tr])
        dval = xgb.DMatrix(X.iloc[va], label=y.iloc[va])

        callbacks = []
        if fold_idx == 0:       # 只在第 0 折挂回调，避免多折信号互相干扰
            callbacks.append(XGBoostPruningCallback(trial, "validation-rmse"))

        booster = xgb.train(
            params, dtrain, num_boost_round=500,
            evals=[(dval, "validation")],
            callbacks=callbacks,
            verbose_eval=False,
        )
        preds = booster.predict(dval)
        rmses.append(float(np.sqrt(np.mean((preds - y.iloc[va].values) ** 2))))

    return float(np.mean(rmses))
```

课堂效果：

| 指标 | 数值 |
|---|---|
| 总 trial | 50 |
| 完成 | 18 |
| 被剪枝 | 32 |
| 最佳 MSE | 0.4495 |
| 耗时 | 比不剪枝省 30% 以上 |

### 1.3 其他剪枝器

| 剪枝器 | 机制 | 适用 |
|---|---|---|
| MedianPruner | 与同步骤中位数比较 | 默认，大多数场景 |
| SuccessiveHalving | 多轮淘汰赛，逐步加预算 | trial 数 500+ |
| Hyperband | 自动决定起步步数 | 神经网络架构搜索 |

入门和常规调参，MedianPruner 足够。

## 2. 断点续跑

长任务跑到一半断掉，之前的 trial 不能白跑。用 SQLite 持久化：

```python
study = optuna.create_study(
    study_name="california_housing",
    storage="sqlite:///optuna_study.db",
    direction="minimize",
    sampler=optuna.samplers.TPESampler(seed=42, multivariate=True),
    pruner=optuna.pruners.MedianPruner(n_startup_trials=5, n_warmup_steps=30),
    load_if_exists=True,      # 有同名 study 就继续
)
```

SQLite 是单机嵌入式数据库，不用装服务端，直接一个 `.db` 文件。重新执行脚本会从上次中断处继续。

## 3. 并行

```python
study.optimize(objective, n_trials=50, n_jobs=-1)
```

> [!warning] 避免双重并行
> `n_jobs=-1` 已经用满所有核，objective 内部的 XGBoost 必须设 `n_jobs=1`。否则外层和内层抢 CPU，反而更慢。

## 4. 动态搜索空间：一次搜索比多个算法

如果任务里 XGBoost、LightGBM、随机森林都想试，传统做法是写三套搜索再人工比较。Optuna 可以在一个 objective 里先选算法，再按算法定义各自的参数：

```python
def objective(trial):
    algo = trial.suggest_categorical("algo", ["xgb", "lgb", "rf"])

    if algo == "xgb":
        model = xgb.XGBRegressor(
            max_depth=trial.suggest_int("xgb_max_depth", 3, 10),
            learning_rate=trial.suggest_float("xgb_lr", 0.01, 0.3, log=True),
            n_jobs=1, random_state=42, verbosity=0,
        )
    elif algo == "lgb":
        model = lgb.LGBMRegressor(
            num_leaves=trial.suggest_int("lgb_leaves", 15, 127),
            learning_rate=trial.suggest_float("lgb_lr", 0.01, 0.3, log=True),
            n_jobs=1, random_state=42, verbose=-1,
        )
    else:
        model = RandomForestRegressor(
            n_estimators=trial.suggest_int("rf_n_est", 100, 500),
            max_depth=trial.suggest_int("rf_depth", 5, 30),
            n_jobs=1, random_state=42,
        )

    return -cross_val_score(
        model, X, y, cv=cv,
        scoring="neg_root_mean_squared_error", n_jobs=1,
    ).mean()
```

TPE 会自动把更多 trial 分配给表现好的算法。课堂输出里 LightGBM 拿到 36/80 次采样，随机森林只有 18/80——算力自动倾斜，不需要手写规则。

## 5. 多目标优化

精度和推理速度通常冲突。加权求和（`rmse + 0.001 * ms`）的问题是权重难定，换个项目就要重调。

多目标优化保留所有维度，返回一组 **Pareto 最优解**：

```python
def objective(trial):
    params = {
        "max_depth": trial.suggest_int("max_depth", 3, 12),
        "n_estimators": trial.suggest_int("n_estimators", 50, 2000),
        "learning_rate": trial.suggest_float("learning_rate", 0.01, 0.3, log=True),
    }
    model = xgb.XGBRegressor(**params, random_state=42, n_jobs=1, tree_method="hist")
    model.fit(X_tr, y_tr)

    rmse = float(np.sqrt(np.mean((model.predict(X_te) - y_te.values) ** 2)))

    t0 = time.perf_counter()
    for _ in range(20):
        model.predict(X_te.iloc[:100])
    inference_ms = (time.perf_counter() - t0) / 20 * 1000

    return rmse, inference_ms        # 返回元组

study = optuna.create_study(
    directions=["minimize", "minimize"],
    sampler=optuna.samplers.NSGAIISampler(seed=42),
)
study.optimize(objective, n_trials=100)

for t in sorted(study.best_trials, key=lambda t: t.values[0])[:5]:
    print(t.values, t.params)
```

| 业务场景 | 选 Pareto 前沿上的哪个点 |
|---|---|
| 离线批量评分 | RMSE 最低 |
| 在线实时推理 | RMSE 稍高、延迟 < 5ms |
| 移动端部署 | 延迟 < 1ms，接受精度下降 |

> [!note] `best_trial` 与 `best_trials`
> 单目标用 `study.best_trial`；多目标用 `study.best_trials`（复数），返回前沿上所有解。

## 6. 调参的进阶坑

### 6.1 过拟合验证集

跑几百次后，验证集上的“最佳”可能只是运气。对策：

- 用交叉验证而不是单次切分；
- 留出独立的测试集，最后只评一次；
- 关注分数随 trial 的整体趋势，而不是单个最小值。

### 6.2 目标函数有噪声

同一组参数换 CV 划分结果会抖动。TPE 会追逐噪声。对策：增大 CV 折数、固定划分、对多次结果取平均。

### 6.3 特殊的数据泄露

- 调参用到的验证集不能和最终测试集重叠；
- 特征工程（如目标编码）必须放进 CV 的每一折内部，不能提前在全量数据上做；
- 时间序列要按时间切分，不能随机打乱。

### 6.4 特征工程才是大头

调参通常只能带来几个百分点的提升，特征工程和数据质量的影响大得多。先保证数据和特征，再谈调参。
