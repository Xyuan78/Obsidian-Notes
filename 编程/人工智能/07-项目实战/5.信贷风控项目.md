# 信贷风控项目

课程最终的综合作业：把前面所有环节组装成一个可运行的“智能信贷风控分析系统”。它不只是一个模型，而是数据、特征、模型、调参、解释、LLM、Web 的完整流水线。

## 1. 业务场景

用户提交贷款申请后，系统要在几秒内给出：

1. 违约概率；
2. 风险等级与审批建议；
3. 判断依据（合规要求）；
4. 业务人员能读懂的自然语言报告。

传统做法是训练 XGBoost、部署 API，业务只看到一个 0.73。这个项目在模型之上加了 **SHAP 解释层**和 **LLM 智能层**，让结果可解释、可对话。

## 2. 数据集

天池“零基础入门金融风控-贷款违约预测”：

| 项目 | 内容 |
|---|---|
| 训练集 | 80 万行 |
| 测试集 | A/B 各 20 万行 |
| 特征 | 47 列（含 15 列匿名特征） |
| 目标 | `isDefault`，二分类 |
| 指标 | AUC |

字段分组：基础字段（id、贷款金额、期限）、数值字段（利率、年收入、负债收入比等）、类别字段（grade、purpose、职业等）、日期字段（放款日期、最早授信日期）、匿名字段（n0–n14）。

> [!warning] 数据量与内存
> 解压后 `train.csv` 约 155MB，读的时候用 `dtype` 指定类型，否则容易吃满内存。没有真实数据时可以运行项目的 `generate_sample_data.py` 生成同 schema 的合成数据，流程能完整跑通，但指标会偏低（课上作业里模型指标 0.6 几，真实数据通常 0.8 以上）。

## 3. 技术栈

| 层 | 技术 | 作用 |
|---|---|---|
| 数据 | pandas / numpy | 加载、切分、预处理 |
| 特征 | sklearn + 自定义 | 构造、编码、筛选 |
| 模型 | XGBoost + PyTorch MLP + Ensemble | 双模型融合 |
| 调参 | Optuna | 超参搜索 |
| 解释 | SHAP | 全局 + 局部解释 |
| LLM | DeepSeek API | 报告、建议、异常分析 |
| 编排 | 自研 Pipeline + YAML | 流程串联 |
| 展示 | Streamlit + Plotly | Web 界面 |
| 工具 | loguru / pydantic / jinja2 | 日志、校验、模板 |

## 4. 分层架构

```text
展示层 app/            Streamlit 页面
编排层 src/pipeline/    TrainingPipeline, ArtifactManager
能力层 src/{models,explain,llm,tuning}/
特征层 src/features/    FeatureBuilder, FeatureSelector
数据层 src/data/        DataLoader, DataSplitter, Preprocessor
工具层 src/utils/       ConfigLoader, Logger, Evaluator
```

依赖方向严格单向：上层可以调下层，下层不能反向依赖上层。

### 4.1 配置驱动

所有路径、超参、字段定义都写在 YAML：

```yaml
# configs/model_config.yaml
xgboost:
  max_depth: 6
  learning_rate: 0.05
  n_estimators: 500
  scale_pos_weight: auto
```

```python
configs = ConfigLoader("./configs")
model = XGBModel(config=configs.model.xgboost)
```

好处：改超参不改代码、不同环境不同配置、实验参数可版本管理。

实现要点：

- **单例**：全程序只有一个 `ConfigLoader`；
- **AttrDict**：`config.model.xgboost.max_depth`，不用层层方括号；
- **环境变量插值**：`api_key: ${DEEPSEEK_API_KEY}`；
- **热重载**：`reload()` 不重启程序。

### 4.2 接口抽象

`BaseModel` 定义四个抽象方法：

```python
class BaseModel(ABC):
    @abstractmethod
    def fit(self, X_train, y_train, X_val=None, y_val=None): ...
    @abstractmethod
    def predict_proba(self, X) -> np.ndarray: ...
    @abstractmethod
    def save(self, file_path: str): ...
    @abstractmethod
    def load(self, file_path: str) -> "BaseModel": ...
```

新增 LightGBM、CatBoost 只要继承并实现这四个方法，就能接进流水线和 Web 界面，不用改上层代码。

### 4.3 训练数据流

```text
原始 CSV
  → DataLoader
  → Preprocessor.fit_transform
  → FeatureBuilder.transform
  → FeatureSelector.fit_transform
  → DataSplitter.split
  → XGBModel.fit / MLPModel.fit
  → EnsembleModel
  → Evaluator
  → ArtifactManager 落盘
```

预测时把 `fit_transform` 换成 `transform`，沿用训练阶段学到的均值、方差、编码表。这是 sklearn 的标准模式，也是避免数据泄漏的关键。

## 5. 模型层

- **XGBoost**：表格数据主力，处理缺失值、类别不平衡、特征重要性；
- **MLP**：PyTorch 实现，输入 47 维，隐藏层要比鸢尾花的 4 个神经元大得多，层数也要增加；用 Dropout + BatchNorm 抑制过拟合；
- **Ensemble**：两个模型的概率加权融合，权重可以用验证集搜索。

课上明确的作业要求：

- 违约数据输入 47 个特征，隐藏层神经元要调大，隐藏层不够就继续加；
- 必须使用 Dropout 缓解过拟合；
- 按 `Linear → BatchNorm → ReLU → Dropout` 的顺序搭；
- XGBoost 必须用 Optuna 调一次参。

## 6. 调参与解释

- Optuna：TPE + 剪枝 + SQLite 持久化，搜索深度、学习率、采样比例、正则；
- SHAP：全局蜂群图看整体风险特征，瀑布图解释单个申请人；
- 报告：把前几大特征、数值、参照值、改善建议交给 LLM 生成自然语言。

## 7. LLM 层

三个 Agent 共用“三段式”：

```text
build_context → render_prompt → call_llm → parse_response
```

| Agent | 输入 | 输出 |
|---|---|---|
| 报告 Agent | 违约概率、SHAP Top 特征 | 客户可读的风险说明 |
| 建议 Agent | 特征数值、阈值 | 可行动的改善建议 |
| 异常 Agent | 预测与特征组合 | 异常原因分析 |

Prompt 写在 `configs/prompts/*.j2`，用 Jinja2 渲染，不硬编码。

> [!warning] 合规
> 给客户看的文本不能出现 `V14`、`PCA`、`SHAP` 这类术语；必须给出具体原因和建议。金融场景的模型解释是法律要求，不是加分项。

## 8. Web 与部署

Streamlit 页面大致包括：首页、单笔预测、批量预测、模型解释、调参记录、数据概览、关于。模型、预处理器、特征列表、metadata 一起打包保存，加载时按同一版本恢复。
