# SSM 整合、事务、加密与验证码

> [!info] 讲义补充
> 本节依据讲义第 3324–5138、5753–5813 行整理。录播只完成早期环境搭建，SSM 业务链路与加密验证码属于后续补充。

## SSM 的职责边界

| 框架 | 职责 |
|---|---|
| Spring | IoC/DI、组件装配、事务、AOP |
| SpringMVC | Web 请求映射、参数绑定、响应处理 |
| MyBatis | SQL 映射、参数绑定、结果映射 |

一次请求：

```text
DispatcherServlet
  → Controller
  → Service
  → Mapper
  → MyBatis
  → DataSource
  → MySQL
```

## 核心装配

### 数据源

```xml
<bean id="dataSource"
      class="com.alibaba.druid.pool.DruidDataSource"
      destroy-method="close">
    <property name="url" value="${mysql.url}"/>
    <property name="username" value="${mysql.username}"/>
    <property name="password" value="${mysql.password}"/>
    <property name="driverClassName" value="${mysql.driver}"/>
</bean>
```

### SqlSessionFactory

```xml
<bean id="sqlSessionFactory"
      class="org.mybatis.spring.SqlSessionFactoryBean">
    <property name="configLocation" value="classpath:mybatis-config.xml"/>
    <property name="dataSource" ref="dataSource"/>
    <property name="typeAliasesPackage" value="com.elm.model.entity"/>
</bean>
```

### Mapper 扫描

```xml
<bean class="org.mybatis.spring.mapper.MapperScannerConfigurer">
    <property name="basePackage" value="com.elm.mapper"/>
    <property name="sqlSessionFactoryBeanName" value="sqlSessionFactory"/>
</bean>
```

这样 Controller 才能通过 `@Autowired` 获得 Mapper 代理对象。

### 事务管理器

```xml
<bean id="txManager"
      class="org.springframework.jdbc.datasource.DataSourceTransactionManager">
    <property name="dataSource" ref="dataSource"/>
</bean>

<tx:annotation-driven transaction-manager="txManager"/>
```

## @Transactional

Service 示例：

```java
@Service
@Transactional
public class UserServiceImpl implements UserService {
    @Autowired
    private UserMapper userMapper;

    @Override
    public void register(User user) {
        userMapper.insert(user);
        userMapper.insertProfile(user.getId());
    }
}
```

### 默认回滚规则

- 发生 `RuntimeException` 或 `Error`：默认回滚。
- 发生受检异常（如 `IOException`）：默认**不回滚**。
- 需要受检异常也回滚时：

```java
@Transactional(rollbackFor = Exception.class)
```

### 传播行为

常见 `propagation`：

| 值 | 含义 |
|---|---|
| `REQUIRED` | 有事务则加入，无事务则新建（默认） |
| `REQUIRES_NEW` | 挂起当前事务，新建独立事务 |
| `NESTED` | 当前事务中的嵌套事务 |
| `SUPPORTS` | 有事务则加入，无事务也可执行 |

课堂示例只使用默认 `REQUIRED`。复杂业务要明确：哪些步骤必须同成同败，哪些日志/通知需要独立事务。

### 事务失效的常见原因

- 同类内部方法自调用，绕过 Spring 代理。
- 方法不是 `public`。
- 异常被 `catch` 后没有重新抛出。
- 抛出受检异常但未配置 `rollbackFor`。
- 使用的不是 Spring 管理的 Bean。
- 数据库表引擎不支持事务（如部分 MyISAM 表）。

> [!warning] 事务不是 try/catch
> 如果异常在 Service 内被吞掉，Spring 认为方法正常返回，事务可能提交。需要记录日志时，应 `log.error(...)` 后重新抛出，或明确设置回滚。

## MD5 加盐与索引

### 为什么不直接存明文

数据库泄露时，明文密码会立即暴露。直接 MD5 也不够安全，因为相同密码得到相同摘要，容易被彩虹表命中。

课堂方案：

```text
salt = 随机字符串
hash = MD5(salt + password + salt)
```

再把 `salt`、`saltIndex` 和 `hash` 一起保存。

```java
String salt = RandomStringUtils.randomAlphabetic(10);
int index = (int) (Math.random() * 10) % 10;
String hash = MD5Util.md5To32String(rawPassword, salt, index);

user.setUserSalt(salt);
user.setUserSaltIndex(index);
user.setUserPwd(hash);
```

“索引”用于从不同的十六进制字符表中生成摘要，增加课堂演示的定制性。

登录时：

```java
String candidate = MD5Util.md5To32String(
        inputPassword,
        storedUser.getUserSalt(),
        storedUser.getUserSaltIndex()
);
boolean ok = candidate.equalsIgnoreCase(storedUser.getUserPwd());
```

> [!danger] 课程方案的安全边界
> MD5 加盐能避免明文存储和简单彩虹表，但 MD5 已不适合作为现代密码哈希算法。生产系统应使用 BCrypt、scrypt 或 Argon2，并按需增加成本因子。不要在笔记中把课堂 MD5 实现误当成当前最佳实践。

### 密码比较与日志

- 使用原密码重新计算摘要后比较。
- 不要把明文、盐、摘要写进生产日志。
- 登录失败提示要模糊，避免账号枚举。

## 验证码

### 原理

1. 服务端生成随机字符串和图片。
2. 随机串存入 Session。
3. 图片以流写给浏览器。
4. 登录时比较用户输入和 Session 值。
5. 验证后立即删除 Session 中的验证码。

```java
String code = randomCode(4);
request.getSession().setAttribute("imageCode", code);
writeImage(response, code);
```

验证：

```java
String expected = (String) request.getSession().getAttribute("imageCode");
if (!input.equalsIgnoreCase(expected)) {
    return "验证码错误";
}
request.getSession().removeAttribute("imageCode");
```

### 安全要求

- 设置过期时间。
- 验证码一次性使用。
- 刷新验证码时生成新值。
- 限制尝试次数。
- 不要把验证码明文写回响应或日志。
- 验证码不能替代密码强度和限流。

## 第三方验证码

课堂提到 EasyCaptcha、Kaptcha、Hutool `CaptchaUtil` 等。

以 `CaptchaUtil` 为例：

```java
CaptchaUtil.createLineCaptcha(120, 40);
boolean ok = CaptchaUtil.ver(inputCode, request);
CaptchaUtil.clear(request);
```

使用第三方库时仍要确认：

- Session 如何处理。
- 是否一次性校验。
- 过期策略、字体、干扰线和无障碍方案。
- 登录接口是否有限流。

## 课堂代码风险

- `MD5Util` 忽略字符集，应明确 `StandardCharsets.UTF_8`。
- `salt + password + salt` 的拼接方式应固定并文档化。
- 自定义字符表不会增加密码学强度，不能替代更强的哈希算法。
- 验证码比较必须先判空，不能直接 `equalsIgnoreCase(null)`。
- 账户锁定后的解锁流程需要管理员或超时机制。
