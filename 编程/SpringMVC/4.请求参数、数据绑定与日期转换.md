# 请求参数、数据绑定与日期转换

> [!info] 课堂来源
> 录制 7，约 18:44–46:32；录制 8，约 00:00–11:30。讲义对应第 1672–1806、2469–2629 行。

## 数据来源

HTTP 请求中的数据可能来自：

- URL 查询串：`?password=123456&id=100`
- 表单字段：`application/x-www-form-urlencoded` 或 `multipart/form-data`
- 路径段：`/users/1`
- 请求头：`token: 1234`
- 请求体：JSON/XML 等
- Cookie 和 Session

SpringMVC 根据方法参数与注解选择对应的解析方式。

## 方式一：同名参数自动绑定

```java
@RequestMapping("/stringParams")
@ResponseBody
public String stringParams(String name, String pwd) {
    return name + ":" + pwd;
}
```

请求：

```text
/stringParams.do?name=zhangsan&pwd=123456
```

规则：

- 默认按参数名匹配请求中的 key。
- 基本类型和包装类型可自动转换。
- 缺少引用类型通常是 `null`；缺少基本类型可能触发绑定错误。
- 同名自动绑定简单，但字段名变化会让接口契约变得脆弱。

## 方式二：@RequestParam

```java
@RequestParam(
    value = "password",
    required = true,
    defaultValue = "000000"
) String pwd
```

| 属性 | 含义 |
|---|---|
| `value` / `name` | 请求参数名 |
| `required` | 是否必须存在 |
| `defaultValue` | 缺失或空值时使用的默认值 |

课堂示例：

```java
@RequestMapping(value = "/list3", produces = "application/json;charset=UTF-8")
@ResponseBody
public Admin2 demo3(
        @RequestParam(value = "password", required = true, defaultValue = "000000") String pwd,
        @RequestParam(value = "id", required = true, defaultValue = "100") Integer id) {
    Admin2 admin = new Admin2();
    admin.setAdminPassword(pwd);
    admin.setAdminId(id);
    return admin;
}
```

> [!warning] required 与 defaultValue 的组合
> 一旦提供 `defaultValue`，参数缺失时会使用默认值，`required=true` 的实际约束会被弱化。若参数必须由客户端提供，不要写默认值；若允许默认值，就应把业务语义写清楚。

## 方式三：HttpServletRequest

```java
@RequestMapping("/list4")
@ResponseBody
public Admin2 demo4(HttpServletRequest request,
                    HttpServletResponse response) {
    String password = request.getParameter("password");
    String tempId = request.getParameter("id");

    password = password == null ? "aaaaaa" : password;
    password = password.toUpperCase();

    Integer id = Integer.parseInt(tempId);
    id += 10;

    Admin2 admin = new Admin2();
    admin.setAdminPassword(password);
    admin.setAdminId(id);
    return admin;
}
```

优点：最接近 Servlet，来源清晰，便于处理响应头/流。

缺点：样板代码多，类型转换、默认值、空值和异常处理都要自己完成。

> [!bug] 当前代码风险
> `Integer.parseInt(tempId)` 在 `id` 缺失或不是数字时会抛 `NumberFormatException`。应先判空、校验格式，再转换，或改用带默认值的 `@RequestParam Integer id`。源码注释提到正则校验，但示例代码并未真正执行。

## 方式四：@ModelAttribute

```java
@RequestMapping("/list5")
@ResponseBody
public Admin2 demo5(@ModelAttribute Admin2 admin) {
    admin.setAdminId(admin.getAdminId() + 100);
    return admin;
}
```

规则：

- 请求参数名必须与对象属性名一致，且大小写一致。
- 依赖实体类的 getter/setter。
- 适合 `application/x-www-form-urlencoded` 表单和普通查询参数。
- 不负责解析 JSON 请求体。

例如：

```text
/admin2/list5.do?adminId=10&adminName=张三&adminPassword=123456
```

## 方式五：@RequestBody

```java
@RequestMapping(value = "/list6", produces = "application/json;charset=UTF-8")
@ResponseBody
public Admin2 demo6(@RequestBody Admin2 admin) {
    admin.setAdminId(admin.getAdminId() + 100);
    return admin;
}
```

请求：

```http
POST /api/admin2/list6.do
Content-Type: application/json

{
  "adminId": 10,
  "adminName": "张三",
  "adminPassword": "123456",
  "adminCreateDate": "2028-01-01 12:59:59"
}
```

`@RequestBody` 使用消息转换器读取整个请求体。没有 JSON 依赖、`Content-Type` 不匹配或 JSON 字段类型错误，都会导致 400/415。

## 日期绑定：两个注解不能混用

当前 `Admin2`：

```java
@JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss", timezone = "GMT+8")
@DateTimeFormat(pattern = "yyyy-MM-dd")
private Date adminCreateDate;
```

| 注解 | 处理方向 | 主要场景 |
|---|---|---|
| `@JsonFormat` | JSON 序列化/反序列化 | `@RequestBody`、`@ResponseBody` |
| `@DateTimeFormat` | Web 参数到 Java 日期类型绑定 | 查询参数、表单字段、`@ModelAttribute` |

### 为什么 JSON 日期需要 @JsonFormat

若直接返回 `Date`，Jackson 默认常输出时间戳：

```json
{"adminCreateDate":1792369192423}
```

加上：

```java
@JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss", timezone = "GMT+8")
```

后才更可能得到：

```json
{"adminCreateDate":"2026-10-19 08:19:52"}
```

时区必须明确。课堂代码使用 `GMT+8`，否则服务器按其他时区序列化时会产生 8 小时偏差。

### 为什么表单日期需要 @DateTimeFormat

```java
@DateTimeFormat(pattern = "yyyy-MM-dd")
private Date adminCreateDate;
```

表单发送 `2026-10-18` 时，Spring 需要把字符串转换成 `Date`。若格式不匹配，方法可能根本不会进入，表现为 400。

> [!important] 判断规则
> JSON 用 Jackson 规则，优先检查 `@JsonFormat`；表单/查询参数走 Spring 数据绑定，优先检查 `@DateTimeFormat`。同一个字段可以同时使用两个注解，但 pattern 应覆盖各自输入。

## 课堂 Postman 演示

1. `params`：在 Query Params 中填写 `id`、`password`。
2. `form-data`：选择 POST，字段名与实体属性一致，日期按 `@DateTimeFormat`。
3. `body → raw → JSON`：选择 POST/PUT，设置 `Content-Type: application/json`，日期按 `@JsonFormat`。
4. 先看第一行日志是否出现，再判断是映射失败还是绑定/业务失败。

## 易错点清单

- `@ModelAttribute` 不等于 JSON 反序列化。
- `@RequestBody` 每个方法最多绑定一个请求体对象。
- 表单上传文件时必须设置 `enctype="multipart/form-data"`。
- `required=true` 与 `defaultValue` 同时出现时要重新审视接口语义。
- 日期 pattern 中的大小写有含义：`MM` 是月，`mm` 是分钟。
- JavaScript 中 `Date` 的时区、后端 `Date` 的时区和 JSON pattern 必须一起检查。
