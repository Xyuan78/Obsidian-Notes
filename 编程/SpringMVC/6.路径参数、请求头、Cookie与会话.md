# 路径参数、请求头、Cookie 与会话

> [!info] 讲义补充
> 本节主要来自讲义第 1807–2029 行，本次录播未完整演示。逐字稿中只讲到路径参数与请求头的重要性，代码细节以讲义为准。

## @PathVariable

路径参数把变量放进 URL 路径，而不是查询串：

```java
@RequestMapping("/path/{userId}/select")
@ResponseBody
public User getUser(@PathVariable("userId") int id) {
    return userService.findById(id);
}
```

请求：

```text
/api/user/path/1/select.do
```

对应关系：

```text
路径模板：/path/{userId}/select
实际路径：/path/1/select
方法参数：@PathVariable("userId") int id
```

### 多个路径参数

```java
@RequestMapping("/{module}/{userId}/{op}")
@ResponseBody
public String getInfo(@PathVariable("module") String module,
                      @PathVariable("userId") int id,
                      @PathVariable("op") String op) {
    return module + ":" + id + ":" + op;
}
```

参数名与模板名绑定，方法参数顺序不必与 URL 顺序相同。

### 路径参数不是查询参数

| 形式 | URL | 取值方式 |
|---|---|---|
| 查询参数 | `/list.do?id=1` | `@RequestParam("id")` |
| 表单字段 | 请求体或查询串 | `@ModelAttribute` / `@RequestParam` |
| 路径参数 | `/users/1/select.do` | `@PathVariable("id")` |

## 动态生成表单地址

讲义演示了纯 JavaScript 修改表单 `action`：

```html
<form id="form001" action="" method="post">
    id: <input id="stuId" name="stuId">
    <button type="button" onclick="submitForm()">查询</button>
</form>

<script>
function submitForm() {
    const id = document.getElementById("stuId").value;
    const form = document.getElementById("form001");
    form.action = "/api/user/path/" + encodeURIComponent(id) + "/select.do";
    form.submit();
}
</script>
```

> [!warning] 编码
> 路径段可能包含 `/`、空格、中文等特殊字符。拼接前应使用 `encodeURIComponent`，后端仍需做类型校验，不能只依赖前端。

## 使用路径参数返回受保护页面

讲义建议把 JSP 放在 `WEB-INF`，外部不能直接访问：

```java
@Controller
@RequestMapping("/page")
public class PageController {
    @RequestMapping("/{pageName}")
    public String page(@PathVariable String pageName) {
        return "WEB-INF/" + pageName;
    }
}
```

请求 `/page/a1.do` 才由 Controller 转发到 `/WEB-INF/a1.jsp`。

> [!danger] 不要直接相信 pageName
> 课堂示例用于说明 `WEB-INF` 的保护作用，但直接把任意路径拼进视图名可能造成越权读取或路径穿越。生产代码应使用白名单映射，例如 `Map<String, String>`，而不是把用户输入直接拼到文件路径。

## @RequestHeader

```java
@RequestMapping("/myHeader")
@ResponseBody
public String getHeaders(@RequestHeader("Host") String host) {
    return host;
}
```

方法参数名和请求头名不一致时，使用注解 value：

```java
@RequestHeader(value = "X-Token", required = false) String token
```

常见请求头：

| 请求头 | 用途 |
|---|---|
| `Host` | 主机与端口 |
| `Accept` | 可接受的响应媒体类型 |
| `Content-Type` | 请求体媒体类型 |
| `Authorization` | 认证信息 |
| `Cookie` | Cookie 内容 |
| `User-Agent` | 客户端标识 |
| `Referer` | 来源页面 |

### 请求头映射条件

```java
@RequestMapping(
    value = "/secure",
    headers = "X-Token=1234"
)
```

这要求请求头满足条件，否则不会匹配该方法。它与读取请求头的方法参数是两件事：

- `headers` 用于**决定方法是否匹配**。
- `@RequestHeader` 用于**把值绑定到方法参数**。

## @CookieValue

```java
@RequestMapping("/getCookie")
@ResponseBody
public String getCookie(
        @CookieValue(value = "JSESSIONID",
                     required = false,
                     defaultValue = "none") String sessionId) {
    return sessionId;
}
```

注意：

- Cookie 名区分大小写。
- Cookie 是浏览器持有的一段键值数据，不等于 Session 本身。
- 前后端分离时 Cookie 跨域、SameSite、Secure、CSRF 等问题更复杂，项目通常改用 Token。

## Request、Session、Application 作用域

```java
@RequestMapping("/scope")
@ResponseBody
public String scope(HttpServletRequest request) {
    request.setAttribute("requestKey", "value");

    HttpSession session = request.getSession();
    session.setAttribute("loginUser", user);

    ServletContext application = request.getServletContext();
    application.setAttribute("systemName", "SSM Demo");

    return "ok";
}
```

| 作用域 | 生命周期 | 典型用途 |
|---|---|---|
| request | 一次请求 | 本次页面渲染数据 |
| session | 一次浏览器会话 | 登录用户、验证码 |
| application | 整个 Web 应用 | 全局配置、共享统计 |

课堂还提到 `@SessionAttributes`，它把 Model 中的属性暂存到 Session。该注解通常写在 Controller 类上，并需要显式清理，实战中不如直接管理 `HttpSession` 直观。

## 登录会话示例

```java
request.getSession().setAttribute("admin", loginAdmin);
```

后续页面可以读取：

```java
Object admin = request.getSession().getAttribute("admin");
if (admin == null) {
    return "redirect:/login.do";
}
```

> [!warning] Session 不是万能鉴权
> Session 适合单体同域应用。前后端分离、移动端或多服务场景要结合 Token、统一认证和权限模型。验证码、登录状态和权限校验不能只靠前端。

## 易错点

- `@PathVariable("id")` 的 `id` 必须与 `{id}` 一致。
- 路径变量与查询参数不要混用。
- 请求头名和 Cookie 名通常区分大小写。
- Session 数据在浏览器关闭或会话过期后失效；“浏览器关闭”还受服务端 Session 超时影响。
- 不应把密码、完整 Token、验证码等敏感值写入日志。
