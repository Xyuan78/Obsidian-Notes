# 返回值、视图解析与统一响应

> [!info] 课堂来源
> 录制 4，约 00:27–44:35；录制 5，约 00:01–05:48。对应讲义第 1558–1806、5018–5072 行。

## 返回字符串为什么可能 404

`@Controller` 方法不加 `@ResponseBody` 时，字符串通常被解释为**逻辑视图名**：

```java
@RequestMapping("/helloworld")
public String demo() {
    return "hello";
}
```

若视图解析器配置：

```xml
<bean class="org.springframework.web.servlet.view.InternalResourceViewResolver">
    <property name="prefix" value="/WEB-INF/jsp/"/>
    <property name="suffix" value=".jsp"/>
</bean>
```

最终查找：

```text
/WEB-INF/jsp/hello.jsp
```

文件不存在，就可能返回 404。课堂当前 `springmvc-config.xml` 已移除视图解析器，因此示例通过 `@ResponseBody` 直接返回响应体。

> [!note] 核心判断
> 字符串本身没有“天然类型”。它到底是页面名还是普通文本，取决于有没有跳过视图解析。

## @ResponseBody

```java
@RequestMapping("/helloworld")
@ResponseBody
public String demo() {
    return "hello";
}
```

`@ResponseBody` 的作用：

1. 告诉 SpringMVC 不把返回值当视图名。
2. 交给 `HttpMessageConverter` 写入响应体。
3. 字符串按文本写出，对象通常会由 Jackson 写成 JSON。

## @RestController

```java
@RestController
@RequestMapping("/admin")
public class AdminController { ... }
```

等价于：

```java
@Controller
@ResponseBody
public class AdminController { ... }
```

适合 REST 接口；如果项目需要返回 JSP 页面，应使用 `@Controller` 和视图解析器。

## 返回 JSON

### 单个对象

```java
@RequestMapping(value = "/obj", produces = "application/json;charset=UTF-8")
@ResponseBody
public Admin getAdmin() {
    return adminService.getAdmin();
}
```

### 集合

```java
@RequestMapping(value = "/list", produces = "application/json;charset=UTF-8")
@ResponseBody
public List<Admin> list() {
    return adminService.getList();
}
```

Jackson 会把集合写成 JSON 数组。前提：

- classpath 中存在 Jackson 依赖。
- 配置了合适的消息转换器。
- 实体字段有可访问的 getter，或 Jackson 可见的字段。

## 返回 XML

实体类：

```java
@XmlRootElement
public class User implements Serializable { ... }
```

控制器：

```java
@RequestMapping(value = "/xml", produces = "application/xml;charset=UTF-8")
@ResponseBody
public User getXml() {
    return user;
}
```

要点：

- `produces` 决定目标响应类型。
- 需要 JAXB/Jackson XML 等消息转换能力。
- JDK 8 与后续 JDK 对 JAXB 模块的处理不同，不能只复制注解而忽略依赖。

## 视图名、转发与重定向

不加 `@ResponseBody` 时：

```java
return "admin/list";              // 视图名
return "forward:/WEB-INF/a.jsp"; // 请求转发
return "redirect:/login.do";     // 重定向
```

## 统一响应结构 MyMessage

课堂当前代码：

```java
@Data
@AllArgsConstructor
@NoArgsConstructor
@Accessors(chain = true)
public class MyMessage<T> implements Serializable {
    private Integer httpCode = 200;
    private String msg = null;
    private Boolean success;
    private T tag;
}
```
字段含义：

| 字段 | 作用 |
|---|---|
| `httpCode` | 业务响应中携带的 HTTP 状态建议值 |
| `msg` | 面向调用方的说明 |
| `success` | 操作是否成功 |
| `tag` | 泛型数据载荷，可以是字符串、对象、集合 |

### 为什么使用泛型

如果使用 `Object tag`，取出数据需要强制类型转换：

```java
List<Admin> list = (List<Admin>) result.getTag();
```

使用 `T` 后，编译期能保留元素类型：

```java
MyMessage<List<Admin>> result =
        new MyMessage<List<Admin>>().setSuccess(true).setTag(adminList);

List<Admin> list = result.getTag();
```

### Service 层封装

```java
@Override
public MyMessage<List<Admin>> getListAdv() {
    MyMessage<List<Admin>> result = new MyMessage<>();
    result.setHttpCode(200);
    result.setMsg("查询成功");
    result.setSuccess(true);
    result.setTag(adminMapper.selectAllAdmin());
    return result;
}
```

### Controller 层直接返回

```java
@RequestMapping(value = "/listAdv", produces = "application/json;charset=UTF-8")
@ResponseBody
public MyMessage<List<Admin>> listAdv() {
    return adminService.getListAdv();
}
```

统一结构示例：

```json
{
  "httpCode": 200,
  "msg": "查询成功",
  "success": true,
  "tag": [
    {"adminId": 1, "adminName": "admin"}
  ]
}
```

> [!warning] httpCode 不是真实 HTTP 状态码
> `result.setHttpCode(500)` 只会改变 JSON 中的字段。要改变真实 HTTP 状态，应使用 `ResponseEntity`、`@ResponseStatus` 或直接在 `HttpServletResponse` 中设置状态。不要把业务码和传输层状态混为一谈。

## 状态码语义

| 范围 | 含义 | 常见例子 |
|---|---|---|
| 2xx | 成功 | 200、201、204 |
| 3xx | 重定向/缓存协商 | 302、304 |
| 4xx | 客户端问题 | 400、403、404、405、415 |
| 5xx | 服务端问题 | 500、502、503 |

课堂只展示了最基础的 200、400、404、405、500。生产项目应统一约定业务码、消息和异常处理。

## 易错点

- 统一响应不是在 Controller 中重复 `new MyMessage` 就结束了，最好由统一返回工具、切面或异常处理器收口。
- 泛型只在编译期提供类型检查，JSON 输出仍由运行时对象结构决定。
- `@ResponseBody` 与视图解析互斥于同一次返回值处理。
- `produces` 要和实际消息转换器能力匹配。
- 中文乱码要检查响应 `Content-Type` 的 `charset`。
