## 学习主线

1. **先分清模型、视图、控制器**：不要只背“MVC 是模型视图控制器”，要能说明三者各自接收什么、产出什么、由谁调度。
2. **再跑通请求闭环**：浏览器请求 → DispatcherServlet → HandlerMapping → Controller → Service → Mapper → 返回值/视图。
3. **掌握控制器契约**：URL、HTTP 方法、参数条件、请求头、请求体、返回媒体类型共同决定一个方法能否被调用。
4. **掌握数据绑定**：普通参数、`@RequestParam`、`@ModelAttribute`、`@RequestBody` 分别解决不同来源的数据。
5. **掌握返回结果**：返回视图名会进入视图解析链；加 `@ResponseBody` 或使用 `@RestController` 则直接把对象写成响应体。
6. **最后进入 SSM 实战**：Spring 管理 Service/Mapper 与事务，MyBatis 负责 SQL，SpringMVC 负责 Web 请求。

## 必须区分的概念

| 概念 | 结论 |
|---|---|
| 三层架构与 MVC | 三层架构按“表示/业务/数据访问”分工；MVC 描述表示层内部的模型、视图、控制器协作 |
| 前端控制器与小控制器 | `DispatcherServlet` 是统一入口；`@Controller` 类中每个映射方法是具体处理器 |
| 视图名与响应体 | 字符串默认可能被当作视图名；`@ResponseBody` 跳过视图解析，把返回值写成 HTTP 响应体 |
| `@Controller` 与 `@RestController` | 后者等价于 `@Controller + @ResponseBody`，适合 REST/JSON 接口 |
| `@RequestParam` 与 `@RequestBody` | 前者读取查询参数或表单字段；后者由消息转换器读取整个请求体，常见于 JSON |
| `@JsonFormat` 与 `@DateTimeFormat` | 前者控制 JSON 日期格式；后者控制表单/请求参数到 Java `Date` 的绑定 |
| `consumes` 与 `produces` | `consumes` 限制请求体媒体类型；`produces` 声明响应媒体类型 |
| HTTP 状态码与业务码 | `MyMessage.httpCode` 只是响应 JSON 字段，不会自动改变真实 HTTP 状态码 |
| forward 与 redirect | 转发是一次请求、服务器内部完成；重定向是两次请求，浏览器地址会变化 |
| Cookie 与 Token | 单体同域项目常用 Session/Cookie；前后端分离项目更常用 Token |

## SpringMVC 请求执行链

```mermaid
flowchart LR
    A[浏览器请求 *.do] --> B[DispatcherServlet]
    B --> C[HandlerMapping]
    C --> D[HandlerAdapter]
    D --> E[@Controller 方法]
    E --> F[Service]
    F --> G[Mapper / 数据库]
    G --> F --> E
    E -->|返回视图名| H[ViewResolver]
    H --> I[JSP / HTML]
    E -->|@ResponseBody| J[HttpMessageConverter]
    J --> K[JSON / XML / 文本]
```
