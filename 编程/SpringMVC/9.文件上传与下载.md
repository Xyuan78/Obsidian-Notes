# 文件上传与下载

> [!info] 讲义补充
> 本节依据讲义第 2847–3323 行整理，本次录播未演示。代码保持课堂结构，同时补充必要的安全约束。

## 上传的前置条件

### 1. 依赖

```xml
<dependency>
    <groupId>commons-fileupload</groupId>
    <artifactId>commons-fileupload</artifactId>
    <version>1.3.2</version>
</dependency>
```

### 2. MultipartResolver

```xml
<bean id="multipartResolver"
      class="org.springframework.web.multipart.commons.CommonsMultipartResolver">
    <property name="maxUploadSize" value="104857600"/>
    <property name="maxInMemorySize" value="4096"/>
    <property name="defaultEncoding" value="UTF-8"/>
</bean>
```

| 属性 | 含义 |
|---|---|
| `maxUploadSize` | 请求总大小上限，单位字节 |
| `maxInMemorySize` | 内存缓存阈值，超过后写临时文件 |
| `defaultEncoding` | 文件名和表单字段编码 |

### 3. 表单

```html
<form action="/api/upload/file.do"
      method="post"
      enctype="multipart/form-data">
    <input type="file" name="file" accept="image/*">
    <input type="text" name="description">
    <button type="submit">上传</button>
</form>
```

> [!warning] 三个必须
> 请求方法必须是 POST；`enctype` 必须是 `multipart/form-data`；`<input type="file">` 必须有 `name`，并且要与 `@RequestParam` 对应。

## 单文件上传

```java
@RequestMapping("/file")
@ResponseBody
public MyMessage<String> upload(
        @RequestParam("file") MultipartFile file,
        HttpServletRequest request) throws IOException {

    String root = request.getServletContext().getRealPath("/");
    File dir = new File(root, "upload");
    if (!dir.exists() && !dir.mkdirs()) {
        throw new IOException("无法创建上传目录");
    }

    String original = file.getOriginalFilename();
    String ext = original.substring(original.lastIndexOf("."));
    String savedName = UUID.randomUUID().toString().replace("-", "") + ext;
    File target = new File(dir, savedName);

    file.transferTo(target);

    return new MyMessage<String>()
            .setSuccess(true)
            .setMsg("上传成功")
            .setTag(savedName);
}
```

关键步骤：

1. 校验文件是否为空。
2. 限制大小、扩展名和 MIME 类型。
3. 生成新文件名，保留规范化扩展名。
4. 确保目标目录存在。
5. 保存并返回相对文件名，不暴露绝对路径。

## 多文件上传

```java
@RequestMapping("/multi")
@ResponseBody
public List<String> uploadMulti(
        @RequestParam("files") MultipartFile[] files) throws IOException {
    List<String> names = new ArrayList<>();
    for (MultipartFile file : files) {
        // 复用单文件保存逻辑
        names.add(save(file));
    }
    return names;
}
```

HTML：

```html
<input type="file" name="files" multiple>
```

多文件处理要判断部分成功还是全部回滚。若业务要求“全成功才保存”，应先把文件写入临时目录，数据库事务成功后再移动到正式目录，并清理失败留下的文件。

## 上传路径怎么选

### 方式一：项目部署目录

```java
String path = request.getServletContext().getRealPath("/") + "/upload/";
```

优点：简单，File 直接可访问。

缺点：

- Maven/Tomcat 插件运行时文件常进入 `target`，重新构建后可能丢失。
- WAR 重新部署会破坏上传文件。
- 不适合生产环境。

### 方式二：固定绝对路径

```properties
filepath=D:\\upload\\
```

优点：重新部署不易丢失。

缺点：需要运维配置目录权限；应用服务器可能没有写权限。

### 方式三：可配置外部目录

推荐把路径放入环境配置，而不是硬编码：

```properties
app.upload-dir=${APP_UPLOAD_DIR:D:/upload/}
```

并通过静态资源映射或下载接口访问文件。

## 图片预览

```javascript
function preview(input, imgId) {
    const file = input.files[0];
    if (!file) return;

    const reader = new FileReader();
    reader.onload = function (event) {
        document.getElementById(imgId).src = event.target.result;
    };
    reader.readAsDataURL(file);
}
```

这是浏览器本地预览，不依赖服务器；上传是否成功仍要看后端响应。

## 文件下载

```java
@RequestMapping("/download")
public void download(@RequestParam("name") String name,
                     HttpServletRequest request,
                     HttpServletResponse response) throws IOException {
    File file = resolveSafeFile(name);
    if (!file.isFile()) {
        response.sendError(HttpServletResponse.SC_NOT_FOUND);
        return;
    }

    response.setContentType("application/octet-stream");
    response.setHeader(
            "Content-Disposition",
            "attachment; filename*=UTF-8''" +
            URLEncoder.encode(file.getName(), StandardCharsets.UTF_8)
                    .replace("+", "%20"));

    try (InputStream in = Files.newInputStream(file.toPath());
         OutputStream out = response.getOutputStream()) {
        IOUtils.copy(in, out);
        out.flush();
    }
}
```

课堂旧写法使用 GBK → ISO-8859-1：

```java
String newFileName = new String(fileName.getBytes("GBK"), "iso-8859-1");
```

它可解决旧浏览器中文乱码，但不如 RFC 5987 的 `filename*=UTF-8''...` 现代、明确。

## 文件安全清单

> [!danger] 必须校验
> 1. 文件名不能直接参与路径拼接，防止 `../` 路径穿越。
> 2. 不能只看扩展名，还要限制 MIME、文件头或实际解码结果。
> 3. 限制文件大小和数量。
> 4. 文件名使用 UUID/随机值，避免覆盖和特殊字符。
> 5. 上传目录不能允许执行脚本。
> 6. 下载前确认文件属于当前用户，防止越权。

错误示例：

```java
String path = uploadDir + file.getOriginalFilename();
```

若用户提供 `../../WEB-INF/web.xml`，可能覆盖或读取非预期文件。应使用规范化路径并验证仍位于上传根目录：

```java
Path root = Paths.get(uploadDir).toRealPath();
Path target = root.resolve(savedName).normalize();
if (!target.startsWith(root)) {
    throw new SecurityException("非法路径");
}
```

## 图片压缩

依赖：

```xml
<dependency>
    <groupId>net.coobird</groupId>
    <artifactId>thumbnailator</artifactId>
    <version>0.4.8</version>
</dependency>
```

```java
Thumbnails.of(sourceFile)
        .scale(0.5)
        .outputQuality(0.5)
        .toFile(targetFile);
```

- `scale` 控制宽高比例。
- `outputQuality` 控制图片质量。
- 压缩后仍需校验格式和大小。
- 不要用压缩掩盖上传限制缺失。

## 易错点

- `MultipartFile` 为空时仍可能收到 0 字节文件。
- 不同浏览器传来的文件名可能包含完整路径。
- 直接拼接原文件名会带来重名和路径安全问题。
- 下载响应一旦开始写入，就不能再正常返回 JSON 错误。
- 上传目录在 `target` 下时，`mvn clean` 会删掉文件。
