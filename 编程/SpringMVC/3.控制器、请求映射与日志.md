# 控制器、请求映射与日志

> [!info] 课堂来源
> 录制 3，约 00:06–18:38；录制 6，约 04:20–42:58。对应讲义第 1302–1671 行。

## @Controller

`@Controller` 把一个类声明为 Web 控制层 Bean，并交给 Spring 容器管理：

```java
@Controller
@RequestMapping("/admin")
@Slf4j
public class AdminController {
    @RequestMapping("/helloworld")
    @ResponseBody
    public String demo() {
        log.info("AdminController.demo");
        return "hello";
    }
}
```

同类注解的职责：

| 注解 | 语义 |
|---|---|
| `@Controller` | 表示 Web 控制层 Bean |
| `@Service` | 表示业务层 Bean |
| `@Repository` | 表示持久层 Bean |
| `@Component` | 通用组件 |
| `@Mapper` | MyBatis Mapper 标识，常与 Spring 扫描配合 |

只有被组件扫描发现的类，注解才会生效：

```xml
<context:component-scan base-package="com.elm.controller"/>
```

## @RestController

```java
@RestController
@RequestMapping("/api/users")
public class UserRestController {
    @GetMapping("/{id}")
    public User find(@PathVariable Long id) {
        return userService.find(id);
    }
}
```

`@RestController = @Controller + @ResponseBody`：

- 类中所有处理方法默认跳过视图解析。
- 返回对象通常由 Jackson 写成 JSON。
- 无法直接返回 JSP 视图名；若需要页面，应使用 `@Controller` 并配合视图解析器。

## @RequestMapping 的匹配条件

`@RequestMapping` 不是只匹配一个 URL。一个请求能否进入方法，由多类条件共同决定：

| 属性 | 作用 | 示例 |
|---|---|---|
| `value` / `path` | URL 路径，可写数组 | `{"/list", "/list2"}` |
| `method` | HTTP 方法 | `GET`, `POST` |
| `params` | 必须存在/等于/不等于某些参数 | `key=value`, `age=18` |
| `headers` | 必须满足某些请求头 | `token=1234` |
| `consumes` | 请求体媒体类型 | `application/json` |
| `produces` | 响应媒体类型 | `application/json;charset=UTF-8` |

> [!warning] 拼写
> 注解属性名必须写完整：响应媒体类型使用 `produces`，请求媒体类型使用 `consumes`；录入或书写时不要省略末尾的 `s`。

### 写在类上

```java
@Controller
@RequestMapping("/admin")
public class AdminController {
    @RequestMapping("/list")
    public String list() { ... }
}
```

完整路径：`/admin/list`。类级路径用于模块分组，并降低不同控制器之间的 URL 冲突。

### 写在方法上

```java
@RequestMapping(value = {"/list", "/list2"},
                method = {RequestMethod.GET, RequestMethod.POST})
@ResponseBody
public Admin2 list() { ... }
```

一个方法可以处理多个路径和多个 HTTP 方法。

### params 与 headers

```java
@RequestMapping(
    value = "/list",
    params = {"key=value", "age=18"},
    headers = {"token=1234"}
)
```

只有同时满足下面条件才能进入方法：

```text
/api/admin2/list.do?key=value&age=18
请求头：token: 1234
```

否则通常得到 404（没有匹配的处理器），而不是进入方法后报参数错误。

### produces

```java
@RequestMapping(
    value = "/list",
    produces = "application/json;charset=UTF-8"
)
@ResponseBody
public Admin2 list() {
    return admin;
}
```

`produces` 影响响应媒体类型和内容协商，不会自动把任意对象变成 JSON；仍需 Jackson 等消息转换器。

## 课堂代码核对

当前 `Admin2Controller` 的示例组合了几乎所有匹配条件：

```java
@RequestMapping(
    value = {"/list", "/list2"},
    method = {RequestMethod.GET, RequestMethod.POST},
    produces = "application/json;charset=utf8",
    params = {"key=value", "age=18"},
    headers = {"token=1234", "Content-Type=application/xml;charset=utf8"}
)
@ResponseBody
public Admin2 demo() {
    ...
}
```

> [!bug] 教学演示中的冲突
> 该映射要求请求头 `Content-Type` 为 XML，却声明响应为 JSON。它用于演示 `headers`/`produces` 的匹配能力，不代表推荐的业务设计。真实接口应让请求媒体类型、响应媒体类型和方法语义一致。

## 日志

课堂要求在每个处理函数第一行写日志：

```java
@Slf4j
@Controller
public class AdminController {
    @RequestMapping("/list")
    @ResponseBody
    public List<Admin> list() {
        log.info("AdminController.list");
        return adminService.getList();
    }
}
```

日志级别从低到高：

```text
TRACE < DEBUG < INFO < WARN < ERROR
```

- 根日志级别设为 `DEBUG` 时，DEBUG 及以上都会输出。
- 根日志级别设为 `WARN` 时，只输出 WARN 和 ERROR。
- 第一行日志出现，说明 URL 和参数匹配至少已经成功进入方法。
- 第一行日志不出现，应优先检查 URL、HTTP 方法、`params`、`headers` 和请求体格式。

> [!tip] 日志内容
> 写“类名 + 方法名”，比只写 `hello` 更容易在多个 Controller 中定位。不要在日志中输出密码、Token、验证码等敏感数据。

## 状态码定位

| 状态码 | 常见原因 |
|---|---|
| 400 Bad Request | 参数类型不匹配、日期格式不支持、请求体无法反序列化 |
| 404 Not Found | 路径不存在，或映射条件未被满足 |
| 405 Method Not Allowed | 路径匹配但 HTTP 方法不允许 |
| 415 Unsupported Media Type | `Content-Type` 与 `consumes` 不匹配 |
| 500 Internal Server Error | Controller/Service/数据库内部异常 |

## 易错点

- `@RequestMapping` 写在类上会成为所有方法的前缀。
- 多个 Controller 可以都写 `/list`，但完整路径必须全局唯一。
- 请求满足路径但方法不匹配时，Spring 可能返回 405；参数/请求头条件不满足时，常见是 404。
- `@ResponseBody` 只影响返回值的处理，不会自动修复参数绑定错误。
- 日志级别不要全局长期设为 DEBUG，生产环境会产生大量输出。
