# 响应式基础

## 响应式设计的核心

页面应根据可用空间自动调整，而不是为每一种设备写一套独立页面。

基础策略：

- 使用流式宽度。
- 设置合理的最小和最大尺寸。
- 使用 Flexbox 与 Grid 自动重排。
- 使用媒体查询处理明显断点。
- 保证文字、按钮和触控区域可读可点。

## viewport

HTML 中必须包含：

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0" />
```

没有这条配置时，移动端浏览器可能按桌面宽度缩放页面。

## 移动优先

先写移动端基础样式，再逐步增强大屏布局：

```css
.card-grid {
  display: grid;
  grid-template-columns: 1fr;
  gap: 16px;
}

@media (min-width: 640px) {
  .card-grid {
    grid-template-columns: repeat(2, minmax(0, 1fr));
  }
}

@media (min-width: 1024px) {
  .card-grid {
    grid-template-columns: repeat(3, minmax(0, 1fr));
  }
}
```

断点由内容决定，不应只照抄某台设备的像素值。

## 相对尺寸

```css
.page {
  width: min(100% - 32px, 1100px);
  margin-inline: auto;
}

.title {
  font-size: clamp(1.5rem, 4vw, 2.5rem);
}

.image {
  display: block;
  width: 100%;
  height: auto;
}
```

- `min()` 取较小值，适合限制最大宽度。
- `max()` 取较大值。
- `clamp(最小值, 理想值, 最大值)` 适合流式字号和间距。
- 图片常设置 `max-width: 100%` 或 `width: 100%; height: auto`。

## 自动换行

```css
.tags {
  display: flex;
  flex-wrap: wrap;
  gap: 8px;
}
```

Flexbox 和 Grid 可以在不写媒体查询的情况下完成许多自适应效果。

## 容器查询简介

媒体查询关注视口，容器查询关注父容器尺寸：

```css
.card-container {
  container-type: inline-size;
}

@container (min-width: 480px) {
  .card {
    display: grid;
    grid-template-columns: 120px 1fr;
  }
}
```

组件在侧栏中较窄、在主内容区较宽时，容器查询尤其有用。

## 可访问性与触控

- 正文通常不应小于 `16px`。
- 行高建议保持在舒适范围。
- 可点击区域不要过小。
- 不要只依赖 hover 状态，触屏没有稳定的悬停行为。
- 支持缩放，不要禁止用户放大页面。
- 使用 `prefers-reduced-motion` 降低动画。

```css
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    scroll-behavior: auto !important;
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
  }
}
```

## 常见错误

- 使用固定宽度导致横向滚动。
- 文字太小，无法在移动端阅读。
- 用 `user-scalable=no` 阻止缩放。
- 只隐藏内容处理窄屏，而不重新考虑信息层级。
- 用过多离散断点，维护成本高。
