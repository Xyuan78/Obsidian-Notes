## 一、这套手册是什么

这是一份**施工手册**。它的作用是：你照着第 00 章做到第 12 章，最后会得到 61 个文件、一个能训练模型、能上网页、能生成 AI 分析报告的系统。

它**不是**：

- 不是教材。不讲算法推导，讲的是"这行代码在干什么、为什么这里需要它"。
- 不是参考书。不用来查 API，用来跟着做。
- 不是项目代码包。代码都在手册里，你要自己建文件、自己粘进去。

配套的两份原始文档仍在 `E:/PythonCode/11.4/` 下：

| 文档 | 你什么时候看它 |
|---|---|
| `开发指导书.md` | 想知道"为什么这么设计"、准备答辩时 |
| `信贷风控_从零手写完整文档.md` | 本手册的代码来源。卡住时可以对照原文 |

本手册的代码**已经修正了原文档 34 个根因问题（源自 71 处现象）**，其中 23 处是照抄必报错的（完整清单见 `附录/附录B_错误对照总表.md`）。所以你对照原文时会发现"不一样"，这是故意的，不是抄错了。

## 二、你最后会做出什么

一个叫「智能信贷风控分析系统」的 Web 应用。场景是：一个人来申请贷款，系统在几秒内回答——

1. 他违约的概率是多少（0.73，即 73%）
2. 这个概率算高还是低（高风险 / 中风险 / 低风险）
3. **为什么**是这个结果（哪个因素把他推高了、哪个拉低了）
4. 用**人话**写一份风险报告（AI 生成，业务人员能看懂）

再加一个模型训练台：换数据、调参数、重新训练、看指标变化。

技术上它串起了这条链：

```
原始CSV → 清洗 → 造特征 → 挑特征 → 切分 → XGBoost ┐
                                              ├→ 融合 → 评估 → SHAP解释 → AI报告 → 网页
                                       MLP ───┘
```

每一段对应一章。这就是为什么章节必须按顺序做——**后一章要用前一章的产物**。

## 三、怎么用这套手册（最重要的一节）

### 3.1 三遍法

每一章都按同样的方式过三遍，**不要试图一遍就懂**。

| 遍次 | 你做什么 | 明确禁令 | 时间占比 |
|---|---|---|---|
| **第一遍：照抄跑通** | 只做「分步操作」段。代码原样粘贴，跑验证命令 | **禁止理解**。看到不懂的概念直接跳过 | 60% |
| **第二遍：回读原理** | 读「本章知识点」表和每步的「逐块讲解」 | 禁止改代码 | 30% |
| **第三遍：自测** | 做「本章自测」3~5 题，答不上就回查编号 | — | 10% |

为什么这么安排：小白 90% 的时间浪费在"想在纸上搞懂再动手"。但代码跑起来之后，理解成本会下降一个数量级——你看得见输出，才看得懂原理。

代码里凡是"现在不用懂"的行，都标了 `# ⚠️ 先照抄，第 X 章会讲`。看到这个标记，放心跳过。

### 3.2 每章固定的九段结构

翻到任何一章，都是这九段，位置固定：

| 段 | 内容 |
|---|---|
| 1 | 这一章在流水线上的位置（一张图，箭头指向你当前所在格） |
| 2 | 本章你要做什么（一句话 + 产物预览） |
| 3 | 开工前检查（3~5 条 checkbox） |
| 4 | 本章知识点（表格 + 1~3 个展开讲） |
| 5 | 分步操作（每步：目标→代码→讲解→验证→报错） |
| 6 | 本章错误对照（原文档写错的地方，❌/✅/💥/🧠/自查） |
| 7 | 常见坑 |
| 8 | 本章自测（答案折叠） |
| 9 | 本章产物清单 + 下一步 |

### 3.3 全文符号约定

| 符号 | 含义 |
|---|---|
| ❌ 原文写法 | 原始文档里这么写，但会报错 |
| ✅ 修正写法 | 手册正文用这个，照抄即可 |
| 💥 不修的后果 | 会看到什么报错 |
| 🧠 为什么 | 一句话原理 |
| ⚠️ | 注意，容易踩坑 |
| ⏸ | 可以在这里停下，下次从这里继续 |
| `必懂` / `知道即可` / `先跳过` | 知识点的要求等级，出现在知识点表最后一列 |

知识点编号规则：`KP-<类别>-<序号>`，类别共 8 种：

`ML` 机器学习基础 · `EV` 评估指标 · `AL` 算法原理 · `EN` 工程与设计 · `LLM` 大模型工程 · `WEB` 网页 · `BIZ` 风控业务 · `PY` Python 语言

全部知识点在 `附录/附录A_知识点速查册.md` 里，共 93 条（66 条必懂 + 27 条知道即可）。章内表格只放"这一章不学就写不下去"的那些。

### 5.1 硬件与软件

| 项目 | 最低要求 | 说明 |

这份手册会出现大量报错。**报错是正常的，不是你的问题。** 每个步骤末尾都给了「常见报错」表，按报错原文去查，90% 能自己对上。查不到就把报错原文贴给 AI 助手。

## 八、卡住了怎么办

按这个顺序，不要跳步：

1. **看当前步骤的「常见报错」表**——80% 的问题在这里。
2. **看本章「常见坑」**——剩下 15% 在这里。
3. **看 `附录/附录D_Windows命令速查.md`**——命令写错（`cp`/`copy`、路径斜杠）。
4. **看 `附录/附录B_错误对照总表.md`**——确认你是不是抄到了原文的错误版本。
5. 还不行，把**完整报错原文**（不是"报错了"三个字）贴出来。

一个排查铁律：**报错先看最后一行**。Python 的报错堆栈很长，但真正的原因永远在最后一行，上面全是调用路径。

```
Traceback (most recent call last):
  File "train_pipeline.py", line 12, in <module>
    from src.models import XGBModel
ModuleNotFoundError: No module named 'torch'     ← 只看这一行
```

这行的意思是"找不到 torch"，跟前面那些文件路径没关系。
