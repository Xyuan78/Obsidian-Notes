## C.1 术语主表（拼音序）

### A

**AUC**（Area Under Curve）
把随机一个好客户和一个坏客户配成对，模型把坏客户排得更靠前的概率。
`0.5` = 瞎猜（抛硬币），`0.75` = 能用，`0.85` = 很好，`0.95+` = 要么模型极强，要么数据泄漏了。
`🚫` 常见误读：以为 AUC 是"准确率"。AUC 只看**排序**，不看阈值。一个 AUC 0.85 的模型，在 0.5 阈值下准确率可能只有 60%。

**Adam / AdamW**（优化器）
一种"按梯度更新参数"的规则，带自适应步长 + 动量，是深度学习的默认选择。`AdamW` 是修正了权重衰减实现的版本。
`🚫` 常见误读：以为优化器越新越好。表格数据用 XGBoost 根本不用优化器；用 MLP 时 Adam 就够。

---

### B

**BatchNorm**（批归一化）
在网络层之间把数据重新拉回"均值 0、方差 1"，让后面的层好训练。
`🚫` 常见误读：以为它和"标准化"是一回事。标准化在**输入**做一次；BatchNorm 在**每一层中间**做，且有可学习参数。

**背景数据集**（background dataset）
算 SHAP 基准期望值用的那批样本。本项目的 `max_background_size=1000` 就是从训练集里抽 1000 条。
`🚫` 常见误读：以为样本越多越准。超过一两千条，精度提升极小，但耗时会线性增长。

**贝叶斯优化**（Bayesian Optimization）
根据"已经试过的参数组合效果如何"，推测下一组最值得试的参数。比网格搜索省几十倍时间。
`🚫` 常见误读：以为它保证能找到全局最优。它是启发式，找到的是"在预算内最好的那个"。

**标准化**（Standardization / Z-score）
每个值减去均值、除以标准差，变成"偏离平均多少个标准差"。
公式：`(x - mean) / std`
`🚫` 常见误读：把它和"归一化"混着叫。归一化（MinMax）是把值压到 `[0,1]`，两者不同。本项目的 `_apply_scaler` 支持多种，别拿 `mean_` 判断是哪种。

**变量**（Variable）
数据表的一列。同义词：字段（field）、特征（feature）、维度（dimension）。
`🚫` 常见误读：以为"特征"和"变量"永远等价。原始列叫变量；经过构造产出的新列才更适合叫特征。

---

### C

**超参数**（Hyperparameter）
**训练开始前**人为设定的参数，比如树深 `max_depth=6`、学习率 `learning_rate=0.05`。
它和"模型参数"（树的分裂点、神经网络的权重）是两回事——后者是训练出来的。
`🚫` 常见误读：以为超参数越调越好。调参的上限由特征和数据决定，特征烂，调参救不回来。

**抽象基类**（Abstract Base Class / ABC）
一个"只定规矩不干活"的类：规定子类**必须**实现哪些方法，自己不实现。
本项目的 `BaseModel` 就是它，强制 `XGBModel` / `MLPModel` / `EnsembleModel` 都有 `fit` / `predict_proba` / `save` / `load`。
`🚫` 常见误读：以为继承了就能用。`@abstractmethod` 装饰的方法没实现，实例化时直接报 `TypeError`。

**测试集**（Test Set）
只用来**最后考一次试**的数据，训练和调参全程不许碰。
`🚫` 常见误读（**本手册最重要的误读**）：用测试集挑模型、挑阈值、挑特征。这等于考前偷看答案，指标虚高，上线暴跌。这叫数据泄漏。

**重试与退避**（Retry with Backoff）
调用外部接口失败后，等一会儿再试，且每次等待时间递增（1s → 2s → 4s）。
用 `tenacity` 库的 `@retry` 装饰器三行搞定。
`🚫` 常见误读：以为重试次数越多越好。对 4xx 错误（如 401 未授权）重试一万次也没用，只会浪费配额。

**词元**（Token）
大模型计费和限流的单位。中文约 1 字 = 1~1.5 token，英文约 1 词 = 1.3 token。
`🚫` 常见误读：以为 token 是"字数"。它是分词器切出来的片段，不等于字符数。

---

### D

**单例模式**（Singleton）
一个类在程序里**只创建一次实例**，全局共用。
`ConfigLoader._instance` 就是它——配置读一次就够，重复读盘又慢又可能读到不同版本。
`🚫` 常见误读：以为单例没坏处。它的副作用是**测试污染**：第一个测试改了配置，第二个测试读到的就是改后的。测试里要 `ConfigLoader._instance = None` 重置。

**Dropout**
训练时随机"关掉"一部分神经元（比如 30%），逼网络别依赖某几个节点。预测时全部打开。
`🚫` 常见误读：以为 `model.eval()` 只是换个名字。不调 `eval()`，Dropout 在预测时还在随机丢，结果每次都不一样。

**对抗样本**（Adversarial Example）
故意构造的、人眼看不出差别但能让模型判错的输入。风控里对应"欺诈者试探模型"。
`🚫` 常见误读：以为这是本项目的重点。本项目不涉及对抗训练，知道概念即可。

---

### E

**二分类**（Binary Classification）
输出只有两个类别：违约 / 不违约，欺诈 / 正常，点击 / 不点击。
本项目的 `isDefault` 就是二分类标签。

---

### F

**反向传播**（Backpropagation）
从损失函数往回算"每个参数该往哪个方向调、调多少"。PyTorch 里就是 `loss.backward()`。
`🚫` 常见误读：以为要自己写求导公式。框架自动做了，你只要保证 `requires_grad=True`。

**方差筛选**（Variance Threshold）
把"几乎所有人都是同一个值"的列删掉——它对预测零贡献。
`🚫` 常见误读：以为阈值越高越好。设太高（如 0.1）会把有价值的稀疏特征（如"是否曾经逾期"99% 是 0）删掉。

**分层抽样**（Stratified Sampling）
切分数据时保证每份的**正负样本比例**与原始一致。
不做分层，随机切可能切出"测试集里几乎没有坏客户"，AUC 就失去意义。
`🚫` 常见误读：以为分层只对大样本有用。样本越小越必须分层。

**复制 vs 软链接**（copy vs symlink）
软链接 = 一个"快捷方式"，指向真实文件；复制 = 真的一模一样拷一份。
`latest` 目录用软链接省空间，但 **Windows 建软链接要管理员权限**，常失败。本项目改用复制。
`🚫` 常见误读：以为软链接失败了程序会报错。常常是"静默失败"，然后 `latest` 目录不存在，`load_latest` 报 `FileNotFoundError`。

---

### G

**概率校准**（Probability Calibration）
模型输出的 `0.73` 是不是真的"73% 会违约"？校准就是修这个。
`🚫` 常见误读：以为 AUC 高就代表概率准。AUC 只看排序，一个 AUC 0.9 的模型可能把所有人预测成 0.9。

**过拟合**（Overfitting）
模型把训练集的"巧合"当规律背下来了：训练集分数极高，新数据一塌糊涂。
判断方法：训练 AUC 0.99、验证 AUC 0.72 → 严重过拟合。
`🚫` 常见误读：以为过拟合就是"训练太久"。原因可能是特征太多、模型太复杂、样本太少、泄漏。

---

### H

**合成数据**（Synthetic Data）
按真实数据的分布规律"造"出来的假数据，用于没有真实数据时开发和调试。
本项目的 `generate_sample_data.py` 按风险逻辑（负债收入比、FICO、利率、逾期次数加权）生成标签，违约率控制在约 20%。
`🚫` 常见误读：以为合成数据能替代真实数据。它的字段**类型和取值格式**必须和真实数据一致，否则换数据时全错位（见 W-07）。

**混淆矩阵**（Confusion Matrix）
四格表：真阳（TP）、假阳（FP）、真阴（TN）、假阴（FN）。
风控里 **假阴（该抓没抓到）代价远高于假阳（误伤好人）**，这是业务决定的。
`🚫` 常见误读：以为准确率高就好。99% 正常的样本里，全预测"正常"就能有 99% 准确率，但一个坏客户都没抓到。

---

### J

**基准期望值**（Base Value / Expected Value）
SHAP 里的"起点"：模型在背景数据上的平均预测。
单笔预测 = 基准值 + 所有特征的 SHAP 值之和（这就是可加性）。
`🚫` 常见误读：以为基准值是 0。它是 `0.2` 左右（样本违约率附近），不是 0。

**剪枝**（Pruning，Optuna 里）
调参时，某个 trial 跑到一半发现明显没希望，就提前终止，省时间。
`🚫` 常见误读：装了 `MedianPruner` 就以为生效了。**必须**在 objective 里手动 `trial.report(score, step)` + 检查 `trial.should_prune()`，否则剪枝器永远收不到信号。

**交叉验证**（Cross Validation, CV）
把训练集切成 K 份，轮流留一份做验证，跑 K 次取平均，评估更稳。
`🚫` 常见误读：以为 CV 能替代测试集。CV 用的是**训练集内部**，测试集仍然只能考一次。

**解释器**（Explainer，SHAP 里）
算 SHAP 值的引擎。三种：
- `TreeExplainer` —— 树模型快，精确
- `DeepExplainer` —— 神经网络，需要 `nn.Module`
- `KernelExplainer` —— 通用但极慢
`🚫` 常见误读：以为随便给哪个都行。给 DeepExplainer 传一个包装类（不是 `nn.Module`）会报 `_modules` 属性缺失。

**精确率**（Precision）
"我判为坏的那些里，真正坏的比例"。`Precision = TP / (TP + FP)`
`🚫` 常见误读：和召回率搞混。精确率关心"抓得准不准"，召回率关心"抓得全不全"。

---

### K

**KS**（Kolmogorov-Smirnov）
好坏两类样本的**累积分布曲线的最大垂直距离**。风控行业最看重的指标。
经验值：`< 0.2` 不可用，`0.2~0.3` 勉强，`0.3~0.5` 良好，`> 0.5` 优秀（也可能是泄漏）。
`🚫` 常见误读：以为 KS 和 AUC 是一回事。它们相关（通常 KS ≈ 2×AUC - 1）但不相等，KS 更关注"最佳切分点的区分度"。

**可复现性**（Reproducibility）
同一份代码、同一份数据、同一个随机种子，跑出来的结果完全一样。
`🚫` 常见误读：以为设了 `random_state=42` 就一定可复现。还要固定 `numpy` 的种子、PyTorch 的种子，以及**列顺序**（列顺序变了结果也会变）。

**可加性**（Additivity，SHAP 的性质）
`预测值 = 基准值 + 特征1贡献 + 特征2贡献 + ... + 特征n贡献`
这是瀑布图能画出来、报告能"拆账"的根本原理。
`🚫` 常见误读：以为这是近似。对树模型它是**精确成立**的（这是 SHAP 相对其他解释方法的最大优势）。

---

### L

**类别不平衡**（Class Imbalance）
正样本（违约）远少于负样本（正常），模型会"偷懒"全预测为多数类。
本项目违约率约 20%，属于轻度不平衡，用 `scale_pos_weight` 补偿即可。
`🚫` 常见误读：以为必须做重采样（SMOTE）。轻度不平衡用 `scale_pos_weight` 更简单，且不改变数据分布。

**留出法**（Hold-out）
最简单的切分方式：一次切成训练 / 验证 / 测试三份。
本项目的 `DataSplitter` 就是它。
`🚫` 常见误读：以为留出法的比例随便定。样本少的时候，测试集太小会导致指标方差极大。

**流式输出**（Streaming）
大模型边生成边返回，前端一个字一个字显示（打字机效果）。
实现靠 Python 的 `yield` 生成器 + `st.write_stream`。
`🚫` 常见误读：以为流式输出能降低费用。它只改善**感知速度**，token 总量不变。

---

### M

**冒烟测试**（Smoke Test）
最基础的"能不能跑起来"测试。名字来自硬件时代：通电不冒烟就算过。
本项目的 `test_basic.py` 就是冒烟测试，11 个用例，5 秒跑完。
`🚫` 常见误读：以为冒烟测试够了。它只能证明"没崩"，不能证明"算得对"。

**幂等**（Idempotency）
同样的操作执行一次和执行多次，结果一样。
`🚫` 常见误读：以为流水线天然幂等。带随机性的训练**不幂等**，要靠固定种子 + 固定 run_id 才能做到可复现。

**MLP**（Multi-Layer Perceptron，多层感知机）
最基础的神经网络：输入层 → 若干隐藏层（线性变换 + 激活函数）→ 输出层。
`🚫` 常见误读：以为 MLP 很弱所以不用学。它是理解所有深度网络的起点，且表格数据上 MLP + XGBoost 融合往往有效。

**目标函数**（Objective Function，Optuna 里）
输入一组超参数，输出一个分数（本项目是验证集 AUC）。Optuna 靠它判断这组参数好不好。
`🚫` 常见误读：以为可以返回 loss。方向要统一——Optuna 默认**最大化**，返回 loss 要加 `direction="minimize"`。

---

### N

**NaN**（Not a Number）
缺失值。XGBoost 能自动处理 NaN，但 sklearn 的模型和神经网络不能，必须先填充。
`🚫` 常见误读：以为 `df.isnull().sum()` 是 0 就没有缺失。有些数据用 `-1`、`999`、`"未知"` 表示缺失，得靠业务理解识别。

---

### O

**One-Hot 编码**（独热编码）
把 `"36 months"` / `"60 months"` 变成两列 0/1。
`🚫` 常见误读：以为所有类别特征都该 One-Hot。高基数类别（如上万种职业）会导致维度爆炸，该用目标编码或频次编码。

**Optuna**
自动调参框架。核心概念：`study`（一次调参任务）+ `trial`（一次参数尝试）。
`🚫` 常见误读：以为它替代了人工。搜索空间（`search_space`）还是人定的，定错了 Optuna 只会更快地找到错的答案。

---

### P

**Pipeline**（流水线 / 编排）
把"加载 → 切分 → 预处理 → 特征 → 训练 → 评估"按依赖顺序串成一个可重跑的整体。
本项目的 `TrainingPipeline.run()` 就是它。
`🚫` 常见误读：以为 Pipeline 只是"把代码整理好看"。它的真正价值是**顺序可审计**——顺序错了（比如 preprocess 在 split 前）会静默造成数据泄漏。

**Pruning**（剪枝）
两种含义，注意区分：
1. **Optuna 剪枝** —— 提前终止没希望的 trial
2. **决策树剪枝** —— 砍掉树的枝叶防过拟合
`🚫` 常见误读：看到 "pruning" 就以为是同一个东西。

---

### Q

**期望值**（Expected Value）
同"基准期望值"，见上。

**全序**（Total Order）
任意两个元素都能比大小。概率是连续值，所以有全序，才能算 AUC。
`🚫` 这个术语很少用到，本手册不涉及，列在这里只为防止你搜到时困惑。

---

### R

**ROC 曲线**（Receiver Operating Characteristic）
横轴假阳率（FPR）、纵轴真阳率（TPR），把阈值从 0 扫到 1 画出来的曲线。AUC 就是它下面的面积。
`🚫` 常见误读：以为 ROC 曲线"越靠左上越好"就完事了。极度不平衡时 ROC 会过于乐观，该看 PR 曲线。

---

### S

**SHAP**（SHapley Additive exPlanations）
用博弈论的 Shapley 值来"公平分配"每个特征对这次预测的贡献。
回答的问题：**"为什么这一笔被判成高风险？"**
`🚫` 常见误读（**务必看清**）：SHAP 是**相关性归因**，不是**因果**。"收入低推高了风险分"不等于"提高收入就能降低风险"。

**Shapley 值**
SHAP 的数学基础：一个特征在所有可能的"特征组合顺序"下带来的平均边际贡献。
`🚫` 常见误读：以为是启发式拍脑袋。它有唯一性公理保证（效率性、对称性、虚拟性、可加性）。

**Softmax**
把一组实数变成"加起来等于 1 的概率分布"。多分类用。
`🚫` 常见误读：二分类也用它。二分类用 Sigmoid 就够（本项目 `BCEWithLogitsLoss` 内部含 Sigmoid）。

**数据泄漏**（Data Leakage）
测试集（或未来）的信息，提前进入了训练过程。
三种典型形态：
1. **预处理泄漏** —— 在含测试集的全量数据上 `fit` 标准化器 / 筛选器
2. **时间泄漏** —— 用了预测时点之后才知道的信息
3. **标签泄漏** —— 某个特征其实是标签的"事后产物"（如"催收结果"）
本手册 9.0 节把原文档的 `preprocess → feature_selection → split` 改成了 `split → preprocess → feature_selection`，就是为了消灭第 1 种。
`🚫` 常见误读：以为泄漏一定报错。**它从不报错，只会让指标虚高 2 个 AUC 点。** 这是最危险的地方。

**Stacking**（堆叠）
用多个基模型的**预测结果**作为新特征，再训一个"元模型"。
本项目支持三种融合：`weighted_avg`（加权平均）、`voting`（投票）、`stacking`（堆叠）。
`🚫` 常见误读：以为 Stacking 一定比加权平均好。小数据上 Stacking 极易过拟合，加权平均更稳。

**随机种子**（random seed）
让随机过程可复现的初始值。`random_state=42` / `np.random.seed(42)` / `torch.manual_seed(42)`。
`🚫` 常见误读：以为设一个地方就够了。XGBoost、numpy、PyTorch、sklearn 的切分，各要各的。

---

### T

**梯度提升树**（Gradient Boosting Decision Tree, GBDT）
一棵一棵树"接力"：每棵新树专门去修正前面所有树的残差。XGBoost / LightGBM / CatBoost 都是它的实现。
表格数据上，它至今仍是最强基线。
`🚫` 常见误读：以为树越多越好。靠 `early_stopping_rounds` 决定什么时候停。

**特征工程**（Feature Engineering）
从原始字段造出更有信息量的新字段。比如 `月还款 / 月收入 = 负债收入比`。
`🚫` 常见误读：以为这是"调参之外的可选项"。**在表格数据上，特征工程带来的提升通常大于调参。**

**特征筛选**（Feature Selection）
从上百个特征里挑出真正有用的子集。本项目三道筛：方差 → 相关性 → 模型重要性 Top-K。
`🚫` 常见误读：以为特征越多越好。冗余特征会稀释重要性、拖慢训练、加剧过拟合。但也别删过头（见 W-02）。

**TPE**（Tree-structured Parzen Estimator）
Optuna 默认的贝叶斯优化采样器。用历史 trial 建两个概率模型（好的 / 坏的），挑"更可能落在好的那边"的点。
`🚫` 常见误读：以为它需要大量历史数据才能工作。`n_startup_trials=10` 之后就开始生效。

---

### W

**违约概率**（Probability of Default, PD）
模型输出的 0~1 之间的数，代表"这个客户会违约的可能性"。
`🚫` 常见误读：以为 0.5 是分界线。风控里最优阈值往往是 0.2~0.4（宁枉勿纵），要用 Youden 指数找。

**网格搜索**（Grid Search）
把所有参数组合穷举一遍。3 个参数各 5 个候选 = 125 次训练。
`🚫` 常见误读：以为它比贝叶斯优化"更可靠"。它只是更"笨但完整"，在参数多时完全不可行。

**WeightedBCELoss**
本项目自定义的加权二元交叉熵：给正样本乘一个权重系数，缓解类别不平衡。
`🚫` 常见误读：以为它和 `scale_pos_weight` 完全等价。前者作用于 loss，后者作用于 XGBoost 内部的梯度统计，效果相近但不等价。

---

### X

**相关系数**（Correlation Coefficient）
两个变量线性相关的程度，`-1` 到 `1`。
本项目用它做第二道筛选：两列相关性 > 0.95 就删掉一个。
`🚫` 常见误读：以为相关系数高就一定是冗余。它只测**线性**关系，两个强非线性相关的特征相关系数可能接近 0。

**学习率**（learning_rate）
每一步更新参数时"走多远"。太大震荡不收敛，太小训练慢。
XGBoost 里常用 `0.05`，配 `early_stopping` 时可以用 `0.01` 换更好效果。
`🚫` 常见误读：以为越小越好。太小会导致 `early_stopping` 提前触发（还没学到东西就停了）。

---

### Y

**验证集**（Validation Set）
用来**调参和选模型**的数据。可以反复看，但看完要"花掉"。
`🚫` 常见误读：验证集和测试集混用。验证集可以看一百次，测试集只能看一次。

**阈值**（Threshold）
概率大于多少就判为"违约"。默认 0.5，风控里通常用 Youden 指数（`TPR - FPR` 最大处）来选。
`🚫` 常见误读：以为阈值是模型的一部分。阈值是**业务决策**，同一模型换个阈值就是另一套成本结构。

**硬编码**（Hardcoding）
把本该可配置的值直接写死在代码里，比如 `api_key = "sk-xxx"`。
`🚫` 常见误读：以为只有密钥不能硬编码。路径、阈值、特征名列表硬编码同样会造成维护灾难。

---

### Z

**正则化**（Regularization）
惩罚模型复杂度，防过拟合。XGBoost 里是 `reg_alpha`（L1，让权重稀疏）和 `reg_lambda`（L2，让权重变小）。
`🚫` 常见误读：以为正则化越强越好。太强会导致欠拟合，模型学不到东西。

**置信度**（Confidence）
本项目 `CaseAgent` 里，指"这个相似案例和当前客户有多像"。低于阈值就过滤掉，避免拿不相关的案例误导。
`🚫` 常见误读：以为是大模型的"信心分数"。大模型不能可靠地给出自己的置信度，这里的置信度是**案例相似度**算出来的。

**自动求导**（Autograd）
PyTorch 自动计算梯度的机制。`loss.backward()` 之后，所有 `requires_grad=True` 的参数的 `.grad` 就填好了。
`🚫` 常见误读：以为每次 `backward()` 会自动清零。**不会**，梯度会累加，所以每个 batch 要 `optimizer.zero_grad()`。

## C.2 最容易混的 8 组（重点看这里）

| 组 | 区别一句话 |
|---|---|
| **验证集 vs 测试集** | 验证集可以反复看（调参用），测试集只能看一次（最终交付用） |
| **标准化 vs 归一化** | 标准化 = 减均值除标准差；归一化 = 压到 `[0,1]` |
| **精确率 vs 召回率** | 精确率 = 抓得准不准；召回率 = 抓得全不全 |
| **AUC vs KS** | AUC 看整体排序；KS 看最佳切分点的区分度 |
| **超参数 vs 模型参数** | 超参数是人定的；模型参数是训练出来的 |
| **SHAP vs 相关系数** | SHAP 是"对这一笔预测的贡献"；相关系数是"两列的线性关系" |
| **数据泄漏 vs 过拟合** | 泄漏是"偷看了答案"；过拟合是"背下了题库" |
| **软链接 vs 复制** | 软链接是快捷方式（省空间、要权限）；复制是实体副本（通用、占空间） |

## 附录 C 自测

不看上面，用自己的话说清楚：

1. AUC 0.92 但 KS 只有 0.15，正常吗？可能是什么问题？
2. "我把测试集也拿去 fit 标准化器了，但代码没报错，是不是没问题？"
3. `trial.should_prune()` 装了但从来不触发，最可能漏了什么？
4. 加权平均和 Stacking，样本只有 8000 条时你选哪个？为什么？
5. SHAP 说"负债收入比推高了风险 0.15"，能不能得出结论"降低负债收入比就能降低风险 0.15"？
6. `optimizer.zero_grad()` 忘了写会怎样？

<details>
<summary>答案</summary>

1. **不正常**。正常关系是 `KS ≈ 2×AUC - 1`，AUC 0.92 应对应 KS 约 0.84。KS 极低说明"存在某个切分点区分度很差"，或者 AUC 被极少数极端样本"撑"起来了。要看 ROC 曲线形状和 KS 曲线。
2. **有问题，而且很严重**。数据泄漏从不报错。它只让指标虚高（本项目实测约 2 个 AUC 点），然后上线暴跌。判断方法：看流水线里 `split` 是否在 `preprocess` 之前。
3. 漏了在 objective 里 **`trial.report(score, step)` 和手动抛 `optuna.TrialPruned()`**。剪枝器看不到中间分数就没法判断。
4. **加权平均**。Stacking 的元模型也要学参数，8000 条数据切完只剩 5600 条训练，元模型极易过拟合。加权平均只有 2~3 个参数，稳得多。
5. **不能**。SHAP 是相关性归因，不是因果。它只说"模型看到这个特征值低，于是把风险分推高了"，不说"改变这个值就能改变风险"。要证明因果得做 A/B 实验或因果推断。
6. 梯度会**累加**而不是替换，等效于把 learning rate 越调越大，训练会发散。每个 batch 都要 `optimizer.zero_grad()`。

</details>
