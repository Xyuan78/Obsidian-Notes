def test_splitter():

    df = pd.DataFrame({

def test_shap():
    from src.explain.shap_analyzer import SHAPAnalyzer
    from src.models.xgb_model import XGBModel
    from src.utils.config_loader import ConfigLoader

    cfg = ConfigLoader(str(ROOT / "configs")).get("model").xgboost
    cfg.params.n_estimators = 20

    rng = np.random.default_rng(7)
    X = pd.DataFrame(rng.normal(size=(200, 5)), columns=list("abcde"))
    y = pd.Series(rng.binomial(1, 0.3, 200))

    model = XGBModel(cfg).fit(X[:150], y[:150])
    analyzer = SHAPAnalyzer(max_background_size=50).fit(model.model, X.head(50))
    exp = analyzer.explain_single(X.iloc[0])

    assert len(exp.shap_values) == 5
    assert len(exp.get_top_features(3)) == 3
    # 可加性：基准 + 各贡献 ≈ 预测
    assert exp.prediction == pytest.approx(exp.base_value + exp.shap_values.sum(), abs=1e-5)

## 6. 本章错误对照

### 错误 E-23　测试之间互相污染（单例的副作用）

**现象**　单独跑 `pytest tests/test_basic.py::test_xgb_train` 通过，跑全量时失败。

**原因**　`ConfigLoader` 是单例。前一个测试改了 `cfg.params.n_estimators = 30`，这个修改**留在了全局实例上**，后面的测试拿到的是被改过的配置。

**✅ 解法**

```python
@pytest.fixture(autouse=True)
def reset_configs():
    yield
    from src.utils.config_loader import ConfigLoader
    ConfigLoader._instance = None      # 每个测试后清空单例
    ConfigLoader._configs = {}
```

**🧠 为什么**　单例的"全局共享"在应用里是优点，在测试里是缺点。测试要求隔离，所以要在测试层主动破坏单例。

## 7. 常见坑

| 现象 | 原因 | 解决 |
|---|---|---|
| `pytest` 找不到 `src` | 没在根目录跑 | 根目录执行，或加 `conftest.py` 设 `sys.path` |
| 测试运行很慢 | 每个测试都训完整模型 | 测试里把 `n_estimators` 调小 |
| 随机失败 | 没固定 `random_state` | 所有随机处都传种子 |
| Windows 上 `pytest` 命令不存在 | 没装进当前环境 | `python -m pytest` 代替 |

## 8. 本章自测

**1. 冒烟测试和单元测试的区别？**

<details>
<summary>点开看答案</summary>

单元测试针对单个函数/方法，追求覆盖分支和边界；冒烟测试只验证"最基础的路径能不能跑通"，不求覆盖率。本项目做的是冒烟测试——10 个测试覆盖 10 个模块的主干。

</details>

**2. 为什么测试里要把 `n_estimators` 调小？**

<details>
<summary>点开看答案</summary>

测试验证的是"逻辑对不对"，不是"模型准不准"。1000 棵树和 30 棵树在逻辑上没有区别，但前者慢 30 倍。测试要在几秒内跑完，才能在你每次改代码后都跑。

</details>

**3. 六步验收为什么要新建一个环境？**

<details>
<summary>点开看答案</summary>

你现在的环境里可能有一些"顺手装上但没写进 requirements"的包。在全新环境里装一遍，才能发现漏写的依赖——这是"在我机器上能跑"和"能交付"的分界线。

</details>
