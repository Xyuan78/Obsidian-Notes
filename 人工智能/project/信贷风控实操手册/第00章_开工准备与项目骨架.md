## 4. 本章知识点

| 编号       | 概念               | 一句话解释                                   | 为什么这里需要它                                                          | 本项目用在哪                   | 要求   |
| -------- | ---------------- | --------------------------------------- | ----------------------------------------------------------------- | ------------------------ | ---- |
| KP-EN-01 | 虚拟环境             | 给每个项目单独一间"房间"，装的库互不干扰                   | 你电脑上可能还有别的项目需要不同版本的库，不隔离会打架                                       | conda 的 `credit_risk` 环境 | 必懂   |

| KP-EN-02 | 依赖清单             | 一张"要装哪些库"的购物单                           | 换电脑时不用回忆装过什么，一条命令重现环境                                             | `requirements.txt`       | 必懂   |
| KP-EN-03 | 环境变量与 `.env`     | 密钥不写在代码里，写在单独文件，运行时读进来                  | 代码要传给别人/传到 GitHub，写死的 Key 会泄露                                     | `.env` + `python-dotenv` | 必懂   |
| KP-EN-04 | `.gitignore`     | 一份"这些文件别提交"的名单                          | 数据、模型、密钥体积大且敏感，不该进版本库                                             | 项目根目录                    | 知道即可 |
| KP-EN-05 | 绝对路径 vs 相对路径     | `./data` 是"当前目录下的 data"                 | 所有配置里用相对路径，项目挪位置不用改代码                                             | 5 个 YAML 里全是相对路径         | 知道即可 |

### 展开讲 1：虚拟环境到底在隔离什么

假设你电脑上装了 pandas 1.5，而本项目需要 pandas 2.1。直接 `pip install pandas==2.1` 会把全局的 pandas 升级，你原来那个项目就崩了。

conda 的做法是：在某个目录下复制一份独立的 Python，所有包装进这个目录。你 `conda activate credit_risk` 之后，`python` 命令指向的就是这份独立副本，跟外面的世界无关。

验证方法：

```bash
conda activate credit_risk
where python
```

输出里应该出现 `...\envs\credit_risk\python.exe`，而不是 `C:\ProgramData\Anaconda3\python.exe`。看到 `envs\credit_risk` 就对了。

### 展开讲 2：`__init__.py` 为什么必须"先建空、后回填"

`src/models/__init__.py` 里最终会写：

```python
from src.models.xgb_model import XGBModel
```

这行的意思是"从这个包里，把 XGBModel 这个名字提上来"。但如果你在第 0 章就写进去，而此时 `xgb_model.py` 还不存在，那么**任何人 import `src.models` 都会立刻报错**。

所以流程是：

1. 第 0 章：建 `__init__.py`，内容留空（或只写一句注释）
2. 第 5 章：写完 4 个模型文件
3. 第 5 章末尾："回填仪式"——把 import 语句填进去
4. 跑一条 import 命令验证

中间那段时间 `__init__.py` 是空的，**这是正确的，不是漏了**。

## 6. 本章错误对照

### 错误 E-00　在 cmd 里用 `mkdir -p` 和 `cp`

**出现在**：原文档第 0 章建目录命令、第 0.3 节复制 `.env`

**❌ 原文写法**

```bash
mkdir -p configs/prompts
cp .env.example .env
```

**✅ 修正写法**

```bat
mkdir configs\prompts
copy .env.example .env
```

**💥 不修的后果**　在 Anaconda Prompt（cmd）里执行会得到：

```
'mkdir' 不是内部或外部命令，也不是可运行的程序
```

或者 `-p` 被当成目录名，建出一个叫 `-p` 的怪文件夹。

**🧠 为什么**　`cp` / `mkdir -p` / `touch` / `rm -rf` 都是 Linux 命令。Windows 的 cmd 有自己的 `copy` / `mkdir` / `type nul >` / `del`。两个体系不通用。

**✅ 自查**　看到 `-p`、`cp`、`touch`、`ls`、`rm` 出现在命令里，就说明这段是从 Linux 教程抄来的。换成下表对应的 Windows 写法：

| Linux | Windows cmd |
|---|---|
| `mkdir -p a/b` | `mkdir a\b` |
| `cp a b` | `copy a b` |
| `cp -r a b` | `xcopy a b /E /I` |
| `touch a` | `type nul > a` |
| `ls` | `dir` |
| `rm a` | `del a` |
| `cat a` | `type a` |
| `pwd` | `cd` |

### 错误 N-01　`.env.txt` 陷阱

**出现在**：步骤 0.3

**❌ 原文写法**　用记事本另存为 `.env`，实际得到 `env.txt`

**✅ 修正写法**　资源管理器 → 查看 → 勾选「文件扩展名」，确认文件名完整是 `.env`（前面有个点，后面没有 `.txt`）

**💥 不修的后果**　`python-dotenv` 找不到文件，所有 Key 都是 `None`，到第 8 章才会暴露，排查起来很浪费时间。

**🧠 为什么**　Windows 默认隐藏已知扩展名，你在记事本里输入 `.env`，实际存成 `.env.txt`。

## 8. 本章自测

**1. `__init__.py` 为什么现在是空的？**

<details><summary>点开看答案</summary>

因为它最终要写 `from src.xxx import Yyy`，而现在 `xxx.py` 还没写。提前写会让任何 import `src` 的代码都报 `ModuleNotFoundError`。等那一章的类文件写完了，再回来填（"回填仪式"）。

</details>

**2. `pip install torch` 和 `pip install torch --index-url .../cpu` 有什么区别？**

<details><summary>点开看答案</summary>

前者从 PyPI 装，Windows 上默认得到 CPU 版（体积小但版本号不带后缀）；后者明确指定 PyTorch 官方源，能选 CPU 或 CUDA 版。有 NVIDIA 显卡想要 GPU 加速时，必须用后者并指定 `cu126` 之类的源。

</details>

**3. `.env` 和 `.env.example` 为什么要两个文件？**

<details><summary>点开看答案</summary>

`.env` 装着真 Key，被 `.gitignore` 排除，永远不进版本库；`.env.example` 只有占位符，进版本库，告诉别人"你需要配这几个变量"。这样代码共享时不会泄露密钥。

</details>

**4. 我怎么确认当前用的是虚拟环境，不是全局 Python？**

<details><summary>点开看答案</summary>

`where python`，输出路径里应该含 `envs\credit_risk`。

</details>
