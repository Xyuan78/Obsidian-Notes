### 注意：
```md
手动编写的注意事项
(1)实体类
在类上使用@TableName("t_user")//确定要使用的表
在主键上使用@TableId("id")//确定主键列
在不符合驼峰命名映射的字段上使用@TableField("first_email")// 如果列名与字段不一致，用TableField进行确认
@Accessors(chain=true)的作用，开启链式编程 例如：
https://blog.csdn.net/weixin_42470128/article/details/116603820
//开起chain=true后可以使用链式的set
User user=new User().setAge(27).setName("kevin");//返回对象
System.out.println(user);



（2）Mapper接口
在接口上使用@Mapper注解该接口
该Mapper接口继承自BaseMapper<T>，操作哪一张表，就使用对应的实体类替换泛型T

（3）service接口
所有的service接口继承自extends IService<T> 操作哪一张表，就使用对应的实体类替换泛型T

（4）service接口的实现类
对应的service接口的实现类，除了实现自己对应的业务接口外，还要继承自ServiceImpl这个类
对应的泛型ServiceImpl<T,R> T表示要调用的持久层的Mapper接口，R表示要处理的对应的实体类。例如：
public class AdminServiceImpl extends ServiceImpl<AdminMapper, Admin> implements AdminService {
}

（5）控制器还是原有的写法

（6）在应用程序的启动类上，写对于Mapper的扫描
@MapperScan("com.qa.mybatisplus.mapper")
```
### 1. 建实体类
```java
@Data                // 通过注解的方式给出 getter 与 setter
@NoArgsConstructor   // 不带参数的构造
@AllArgsConstructor  // 带所有参数的构造

@TableName(t_student) //
public class Student {
    private Integer stuId;
    private String stuNo;
    private String stuName;
    private int stuAge;
    private String stuAddress;
}
```

和MyBaties不同的是多了一个@TableName  ： 这个实体对应哪一张表

```java
@Data  
@AllArgsConstructor  
@NoArgsConstructor  
@Accessors(chain = true) //商家类  
@TableName("t_bussiness")//这个实体类对应哪一张表  
public class Business implements Serializable {  
    // @TableId 指定表的主键  
    // value = "主键列的列名",type = 主键列的类型，设置是自动增长列  
    @TableId(value = "business_id",type = IdType.AUTO)  
    private Integer businessId;  
    //其他列如果遵循驼峰命名映射，后面就不用改了  
    // 如果不符合, 使用@TableField，指定对应的列  
    @TableField(value = "business_password")  
    private String businessPassword;  
    private String businessName;  
    private String businessAddress;  
    private String businessExplain;  
    private Double startPrice;  
    private Double deliveryPrice;  
  
    //自动填充  
  
    // 忽略这个属性  
    @TableField(exist = false)  
    private List<Object> foods;//数据库中没有这一列  
}
```

```java
}
```

### 3. 在service下创建接口和实体类


##### 1. Foodservice接口
```java
package com.qxy.demo1.service;  
  
  
import com.baomidou.mybatisplus.extension.service.IService;  
import com.qxy.demo1.model.entity.Food;  
  
public interface FoodService extends IService<Food> {  
}
```

为什么继承IService？因为IService中已经定义了Food的增删改查方法，继承后可以直接使用这些方法
##### 2. FoodserviceImpl实现类
```java
package com.qxy.demo1.service.impl;  
  
import com.baomidou.mybatisplus.extension.service.impl.ServiceImpl;  
import com.qxy.demo1.mapper.FoodMapper;  
import com.qxy.demo1.model.entity.Food;  
import lombok.extern.slf4j.Slf4j;  
import org.springframework.stereotype.Service;  
import org.springframework.transaction.annotation.Transactional;  
  
  
@Service  
@Transactional  
@Slf4j  
public class FoodServiceImpl extends ServiceImpl<FoodMapper, Food> {  
}
```

增删改查方法实现完成？是的，继承了ServiceImpl类，这些方法就自动拥有这些方法的实现，无需再写
