# 全局配置与日志

`MyBatisConfig.xml` 是 MyBatis 的**全局唯一配置文件**：数据源、事务、别名、SQL 日志开关等跨 Mapper 的设置全部集中在这里。它和 Mapper 映射文件分工明确——一个管"怎么连数据库、怎么干活"，另一个管"写什么 SQL"。

Mapper映射文件

本篇同时整理**打印 SQL 的 log4j 方案**，这是调试 MyBatis 最常用的手段。
## MyBatisConfig.xml详解
### 1. 详细内容
```xml
<?xml version="1.0" encoding="UTF-8" ?>
<!DOCTYPE configuration PUBLIC "-//mybatis.org//DTD Config 3.0//EN"
        "http://mybatis.org/dtd/mybatis-3-config.dtd">
<configuration>
    <!--
        顺序
        properties(属性,加载属性文件，加载数据库的配置)
        settings（全局参数设置）
        typeAliases（类型别名）
        typeHandlers（类型处理器）
        objectFactory（对象工厂）
        plugins（插件）
        environments（环境信息集合，对数据库环境的配置）
                  environment（单个环境信息）jdbc
                     transactionManager（事物）
                     dataSource（数据源
        mappers（映射器）
    -->
    <properties resource="db.properties" />
    <settings>
        <!-- 设置命名法转化，即下划线分开的单词，改成骆驼命名法   -->
        <setting name="mapUnderscoreToCamelCase" value="true" />
    </settings>
    <typeAliases>
        <!-- 批量设置别名 -->
        <!-- package:指定包名称来为该包下的po类声明别名，默认的别名就是类名（类名首字母大小写都可以） -->
        <package name="com.elm.model.entity"/>
        <!-- 自己制定特殊的别名
            <typeAlias type="完全限定名的类" alias="别名"/>
        -->
    </typeAliases>
    <environments default="development">
        <environment id="development">
            <transactionManager type="JDBC" />
            <dataSource type="POOLED">
                <!--对应数据库修改-->
                <property name="driver" value="${mysql.driver}" />
                <property name="url" value="${mysql.url}" />
                <property name="username" value="${mysql.username}" />
                <property name="password" value="${mysql.password}" />
            </dataSource>
        </environment>
    </environments>
    <mappers>
        <!--     包处理映射文件   -->
        <package name="com.elm.mapper"/>
    </mappers>
</configuration>
```
这个文件必须放在类路径根目录（`resources` 下），因为程序用 `Resources.getResourceAsStream("mybatis-config.xml")` 按根查找。搭建步骤见 [[1 .MyBatis 环境搭建]]
### 2. 子标签书写顺序
源文在 `<configuration>` 的开头用一段注释专门列出了顺序，这是**必须遵守的硬约束**：

| 顺序 | 子标签 | 作用 |
|---|---|---|
| 1 | `properties` | 属性，引入外部配置 |
| 2 | `settings` | 全局参数设置 |
| 3 | `typeAliases` | 类型别名 |
| 4 | `typeHandlers` | 类型处理器 |
| 5 | `objectFactory` | 对象工厂 |
| 6 | `plugins` | 插件 |
| 7 | `environments` | 环境信息集合 |
| 8 | `mappers` | 映射器 |
其中 `environments` 内部还嵌两层：`environment`（单个环境信息）→ `transactionManager`（事物）+ `dataSource`（数据源）。
#### 1. properties：引入外部配置
```xml
<properties resource="db.properties" />
```
`resource` 指向类路径下的 `db.properties`，把数据库连接参数从 XML 中抽出去。抽出去之后，`dataSource` 里的四个 `property` 就能用 `${}` 占位符取值：
```xml
<property name="driver" value="${db.mysql.driver}" />
```
`db.properties` 的具体内容（驱动类名、连接串、账号密码）见 [[1 .MyBatis 环境搭建]]]。这样换数据库只需改 properties，不用动 XML。
#### 2. setting : 全局参数配置
```xml
<settings>
    <!-- 设置命名法转化，即下划线分开的单词，改成骆驼命名法   -->
    <setting name="mapUnderscoreToCamelCase" value="true" />
</settings>
```
`mapUnderscoreToCamelCase` 打开后，数据库的下划线列名与 Java 的驼峰字段自动对应：

| 数据库列名                | Java 字段            |
| -------------------- | ------------------ |
| `stu_id`             | `stuId`            |
| `teacher_login_name` | `teacherLoginName` |
#### 3. typeAliases：类型别名
```xml
<typeAliases>
    <!-- 批量设置别名 -->
    <!-- package:指定包名称来为该包下的po类声明别名，默认的别名就是类名（类名首字母大小写都可以） -->
    <package name="com.neuedu.entity"/>
    <!-- 自己制定特殊的别名
        <typeAlias type="完全限定名的类" alias="别名"/>
    -->
</typeAliases>
```
两种做法，源文都给出了：

- **`package` 批量注册（源文采用的方式）**：指定包名后，该包下的 po 类自动获得别名，**默认别名就是类名，且首字母大小写都可以**。配置成本最低，适合实体类集中放在一个包里的项目。
- **`typeAlias` 单个自定义（源文以注释形式给出，未启用）**：`<typeAlias type="完全限定名的类" alias="别名"/>`，适合要起特殊别名的个别类。
#### 4. environments：环境与数据源

```xml
<environments default="development">
    <environment id="development">
        <transactionManager type="JDBC" />
        <dataSource type="POOLED">
            <!--对应数据库修改-->
            <property name="driver" value="${db.mysql.driver}" />
            <property name="url" value="${db.mysql.url}" />
            <property name="username" value="${db.mysql.username}" />
            <property name="password" value="${db.mysql.password}" />
        </dataSource>
    </environment>
</envi
```
三层含义：

1. `environments` 的 **`default="development"`** 指定默认使用的环境；`environment` 的 **`id="development"`** 是该环境的标识。一个配置文件里可以配多套环境（开发/测试/生产），靠 `default` 切换。
2. **`transactionManager type="JDBC"`** —— 事务管理器。用 JDBC 的事务方式管理连接，也就是 `session.commit()` / 回滚那条链路的底层实现。底层原理见 [[8.JDBC技术]]。
3. **`dataSource type="POOLED"`** —— 数据源使用**连接池**，连接被复用而不是每次新建。四个 `property`（`driver` / `url` / `username` / `password`）的值全部来自上面 `properties` 引入的 `db.properties`，源文注释写着"对应数据库修改"，指的是这里随数据库而变。

#### 5. mappers：注册映射器
只能处理一个文件，替换为包文件

```xml
<mappers>
    <!--
    路径+xml文件
    com/neuedu/entity/TeacherInfoMapper.xml
    -->
    <mapper resource="com/neuedu/entity/TeacherInfoMapper.xml" />
</mappers>
```

源文注释点明了 `resource` 的写法是 **"路径 + xml 文件名"**，例如 `com/neuedu/entity/TeacherInfoMapper.xml`。
```xml
<mappers>
        <!--     包处理映射文件   -->
        <package name="com.elm.mapper"/>
    
```


## log4i 的使用
MyBatis 本身不打印 SQL，需要借助日志组件。源文使用 **log4j 1.2.17**，配置后即可在控制台看到实际执行的 SQL 与参数。
### 1. 配置

##### 第一步：在 `pom.xml` 中引入依赖

```xml
<!-- 引入依赖 -->
<!-- 日志处理 -->
<dependency>
    <groupId>log4j</groupId>
    <artifactId>log4j</artifactId>
    <version>1.2.17</version>
</dependency>
```

##### 第二步：新建/修改日志配置文件 `log4j.properties`

```properties
# 修改日志配置文件
log4j.rootLogger=DEBUG,console
log4j.appender.console = org.apache.log4j.ConsoleAppender
log4j.appender.console.Target = System.out
log4j.appender.console.Threshold=DEBUG
log4j.appender.console.layout = org.apache.log4j.PatternLayout
log4j.appender.console.layout.ConversionPattern=[%c]-%m%n

log4j.logger.com.ibatis=DEBUG
log4j.logger.com.ibatis.common.jdbc.SimpleDataSource=DEBUG
log4j.logger.com.ibatis.common.jdbc.ScriptRunner=DEBUG
log4j.logger.com.ibatis.sqlmap.engine.impl.SqlMapClientDelegate=DEBUG
log4j.logger.Java.sql.Connection=DEBUG
log4j.logger.java.sql.Statement=DEBUG
log4j.logger.java.sql.PreparedStatement=INFO
log4j.logger.java.sql=INFO
log4j.logger.org.mybatis=INFO
```

配置分两部分：

- **前半段定义日志输出目标**：`rootLogger=DEBUG,console` 表示全局级别 DEBUG 并输出到名为 `console` 的 appender；`ConsoleAppender` + `Target=System.out` 把日志打到标准输出；`PatternLayout` 的 `[%c]-%m%n` 决定每行格式为 `[日志来源类名]-日志内容`。
- **后半段为具体包指定级别**：把 `com.ibatis`、`java.sql`、`org.mybatis` 等与 SQL 执行相关的日志器打开到 DEBUG/INFO，SQL 才会被打印出来。
##### 第三步：运行原程序，观察输出

```text
#结果可以看到打印的执行的sql语句，方便对程序的调试
[org.apache.ibatis.transaction.jdbc.JdbcTransaction]-Setting autocommit to false on JDBC Connection [com.mysql.jdbc.JDBC4Connection@49fc609f]
[com.neuedu.mapper.StuMapper.selectStuById]-==>  Preparing: select * from t_stu_info where stu_id=? 
[com.neuedu.mapper.StuMapper.selectStuById]-==> Parameters: 1(Integer)
[com.neuedu.mapper.StuMapper.selectStuById]-<==      Total: 1
Stu{stuId=1, stuNo='stu001', name='zhangsanTX'}
```

| 输出                            | 含义                                                |
| ----------------------------- | ------------------------------------------------- |
| `Setting autocommit to false` | 打开连接时关闭自动提交，对应前面 `transactionManager type="JDBC"` |
| `==>  Preparing: ...`         | 真正执行的 SQL，`?` 是占位符                                |
| `==> Parameters: 1(Integer)`  | 填入 `?` 的参数与类型                                     |
| `<==      Total: 1`           | 本次查询返回的结果条数                                       |
| `Stu{...}`                    | 映射后的实体对象，程序自己 `println` 的结果                       |
|                               |                                                   |
日志中 `StuMapper.selectStuById` 这一前缀来自 `[%c]`，即日志器的类名，可以直接定位到是哪个 Mapper 的哪条语句。

**乱码的处理的一种方式：`-Dfile.encoding=UTF-8`**

在 JVM 启动参数中加上该选项，指定文件编码为 UTF-8，解决控制台输出乱码。
