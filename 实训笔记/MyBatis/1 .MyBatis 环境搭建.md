## 4. 新建实体类
实体类需要符合**驼峰命名映射**：
```java
@Data                // 通过注解的方式给出 getter 与 setter
@NoArgsConstructor   // 不带参数的构造
@AllArgsConstructor  // 带所有参数的构造
public class Admin implements Serializable {  
    //驼峰命名映射，admin_id  =》 adminId    //把下划线删除，下划线后的第一个字母大写

    private String adminName;  
    private String adminPassword;  
  
}
```
数据库列名是下划线风格（`stu_id`），Java 字段是驼峰风格（`stuId`）。让二者对上，靠的是全局配置里的 `mapUnderscoreToCamelCase`（见下一步）。

#### 2. 创建日志，方便打印SQL语句
```properties
log4j.rootLogger=DEBUG,console
log4j.appender.console = org.apache.log4j.ConsoleAppender
log4j.appender.console.Target = System.out
log4j.appender.console.Threshold=DEBUG
log4j.appender.console.layout = org.apache.log4j.PatternLayout
log4j.appender.console.layout.ConversionPattern=[%c]-%m%n

log4j.logger.com.ibatis=DEBUG
log4j.logger.com.ibatis.common.jdbc.SimpleDataSource=DEBUG
log4j.logger.com.ibatis.common.jdbc.ScriptRunner=DEBUG
log4j.logger.com.ibatis.sqlmap.engine.impl.SqlMapClientDelegate=DEBUG
log4j.logger.Java.sql.Connection=DEBUG
log4j.logger.java.sql.Statement=DEBUG
log4j.logger.java.sql.PreparedStatement=INFO
log4j.logger.java.sql=INFO
log4j.logger.org.mybatis=INFO
```
配置分两部分：

- **前半段定义日志输出目标**：`rootLogger=DEBUG,console` 表示全局级别 DEBUG 并输出到名为 `console` 的 appender；`ConsoleAppender` + `Target=System.out` 把日志打到标准输出；`PatternLayout` 的 `[%c]-%m%n` 决定每行格式为 `[日志来源类名]-日志内容`。
- **后半段为具体包指定级别**：把 `com.ibatis`、`java.sql`、`org.mybatis` 等与 SQL 执行相关的日志器打开到 DEBUG/INFO，SQL 才会被打印出来。

## 6. 新建MyBatisConfig.xml（整体配置文件）
详见[[2 .全局配置与日志]]

```xml
<?xml version="1.0" encoding="UTF-8" ?>
<!DOCTYPE configuration PUBLIC "-//mybatis.org//DTD Config 3.0//EN"
        "http://mybatis.org/dtd/mybatis-3-config.dtd">
<configuration>
    <!--
        顺序
        properties(属性,加载属性文件，加载数据库的配置)
        settings（全局参数设置）
        typeAliases（类型别名）
        typeHandlers（类型处理器）
        objectFactory（对象工厂）
        plugins（插件）
        environments（环境信息集合，对数据库环境的配置）
                  environment（单个环境信息）jdbc
                     transactionManager（事物）
                     dataSource（数据源
        mappers（映射器）
    -->
    <properties resource="db.properties" />
    <settings>
        <!-- 设置命名法转化，即下划线分开的单词，改成骆驼命名法   -->
        <setting name="mapUnderscoreToCamelCase" value="true" />
    </settings>
    <typeAliases>
        <!-- 批量设置别名 -->
        <!-- package:指定包名称来为该包下的po类声明别名，默认的别名就是类名（类名首字母大小写都可以） -->
        <package name="com.elm.model.entity"/>
        <!-- 自己制定特殊的别名
            <typeAlias type="完全限定名的类" alias="别名"/>
        -->
    </typeAliases>
    <environments default="development">
        <environment id="development">
            <transactionManager type="JDBC" />
            <dataSource type="POOLED">
                <!--对应数据库修改-->
                <property name="driver" value="${mysql.driver}" />
                <property name="url" value="${mysql.url}" />
                <property name="username" value="${mysql.username}" />
                <property name="password" value="${mysql.password}" />
            </dataSource>
        </environment>
    </environments>
    <mappers>
        <!--     包处理映射文件   -->
        <package name="com.elm.mapper"/>
    </mappers>
</configuration>
```

# 3. 执行流程与增删改查
## 1. 三段式骨架
这三行就是 MyBatis 的启动流程：

```java
// 1. 查找根目录下的配置文件
InputStream is = Resources.getResourceAsStream("mybatis-config.xml");
// 2. 构建工厂
SqlSessionFactory factory = new SqlSessionFactoryBuilder().build(is);
// 3. 打开 session
SqlSession session = factory.openSession();
```
- `SqlSessionFactory` 是重量级对象，整个应用通常只建一次；
- `SqlSession` 代表一次数据库会话，**用完必须关闭**。


## 2. Mapper XML 与sql语句标签
### 1. 增加
在AdminMapper.xml中加入
```xml

<!-- insert标签处理添加功能，写一个死的sql语句    -->  
    <insert id="insert01">  
        insert into t_admin values(null,'zhaosi','12345')  
    </insert>
    <insert id="insert02" parameterType="Admin" useGeneratedKeys="true"  
        keyProperty="adminId" keyColumn="admin_id">  
    insert into t_admin values(null,#{adminName},#{adminPassword})  
</insert>
```

- parameterType="Admin、admin（别名）" 参数类型，包.类  
- #{} 占位符，  
- #{类的属性名}  
- useGeneratedKeys="true" 返回自动增长列的值，（1）注册后不用登陆直接进行其他处理，（2）购买商品，订单付款后（订单Id =》修改购物车项），  
- keyProperty="adminId" 自动增长列的值存在对象的哪一个属性中（可以不写，属性名必须叫id）  
- keyColumn="admin_id"  自动增长列是表中的哪一个列（可以不写，列名必须是叫id）  

### 2. 删除

delete from 表名 where 条件，单值的常用类型（数值型，字符串）  
通过Id删除信息  
数字类型（Integer），单值  #{id} 获得数据  
字符串类型（String），单值  #{value} 获得数据
```xml
<delete id="delete01" parameterType="Admin">  
    delete from t_admin where admin_id=#{adminId}  
</delete>

<delete id="delete02" parameterType="integer">  
    delete from t_admin where admin_id=#{id}  
</delete>  


<delete id="delete03" parameterType="string">  
    delete from t_admin where admin_name=#{value}  
</delete>
```
删除id 大于某个数字  
- 大于号 通过转义字符书写  &gt;
- 小于号                               &lt;

## 3. 使用JUnit

用 `main` 方法测试的缺点是：一个类只能有一个入口，想测多个方法就要反复改代码。JUnit 用注解描述"测试前做什么、测试后做什么、哪些方法是测试用例"，于是同一个类里可以并排放多个独立测试。

### 1. 下载依赖，修改pom.xml

```xml
<dependency>
    <groupId>junit</groupId>
    <artifactId>junit</artifactId>
    <version>4.13.2</version>
</dependency>
```


### 2. 编写测试代码

```java
SqlSession session = null;  
@Before  
public void myBefore() throws IOException {  
    //（1）加载配置文件  
    InputStream resourceAsStream = Resources.getResourceAsStream("MyBatisConfig.xml");  
    //(2)构建session工厂  
    SqlSessionFactory factory = new SqlSessionFactoryBuilder().build(resourceAsStream);  
    //（3）构建session  
    session = factory.openSession();  
}  
@After  
public void myAfter(){  
    //关闭session  
    session.close();  
}  
@Test  
public void test(){  
    System.out.println("test");  
}
```

| 注解        | 作用                   | 源文对应说明                    |
| --------- | -------------------- | ------------------------- |
| `@Before` | 每个测试方法执行**前**都先执行一次  | "测试代码执行前先执行这个函数"          |
| `@After`  | 每个测试方法执行**完毕**后都执行一次 | "当测试代码执行完毕后，执行after注解的函数" |
| `@Test`   | 标记一个测试用例             | 被标记的方法会被 JUnit 自动执行       |
